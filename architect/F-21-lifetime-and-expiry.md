# F-21 Lifetime and automatic expiry: architecture

- **Version:** 0.2 (QA-21-r1 folded in: X-3, X-4, X-5, X-9)
- **Status:** accepted (31 Oct 2026). Critical lane: automatic deletion is data loss, and expired content must stop being served (SH-10). OQ-87 resolved (accepted, 31 Oct 2026)
- **Date:** 31 Oct 2026
- **History:** [history/F-21-lifetime-and-expiry.md](history/F-21-lifetime-and-expiry.md)
- **Feature:** [`features/F-21-lifetime-and-expiry.md`](../features/F-21-lifetime-and-expiry.md)
- **Requirements:** UP-7 (lifetime, 48 h draft rule), AC-4, SH-10, SH-2, NFR Privacy (no data outlives its workout); TD Publish and view flow (Publish 7), Security and privacy (Lifetime), invariant I-4. Decision log 30 Oct 2026 (draft deadline, overdue draft = not found)
- **Builds on:** [F-12](F-12-owner-api.md) O-5, O-7, O-10 and its F-21 hand-off; [F-15](F-15-publish-pipeline-and-static-page.md) P-6, P-8 and its F-21 hand-off; [F-20](F-20-publish-share-delete-controls.md) C-10 and its F-21 hand-off; [ADR-019](ADR-019-sqlite-store-schema-and-migrations.md) rev. 3 (item 9, deleted rows scrubbed from the files), [ADR-022](ADR-022-private-workout-files-staging-and-recovery.md), [ADR-025](ADR-025-owner-api-access-and-not-found-response.md), [ADR-028](ADR-028-public-files-rebuilt-whole-page-as-commit-point.md) item 5; new: [ADR-031](ADR-031-cross-process-lock-on-the-public-area.md) (settles QA-15-r2-1)
- **Owner:** backend only. **No frontend change:** the draft line (F-20 C-10), the expiry date on the page (F-13, F-15 P-11) and the generic page on `404` (F-19 E-4) are already built
- **No migration, no new setting, no new `Record` field**

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| X-1 | **One deadline rule, pure, in `lifecycle`.** Deadline = `expires_at` for an unlisted workout; `min(created_at + 48 h, expires_at)` for a draft. 48 h is the exact duration 172,800 s (hours, not calendar days, UP-7), a constant next to the lifetime constants. A workout is **live** while `now < deadline` and **due** from the deadline on (the same boundary as today's `ExpiresAt.After(now)`). Publishing turns a draft unlisted, so its deadline becomes `expires_at` at once (F-21 AC 3) | One home for "is this workout still alive". Everything below asks this rule, never `expires_at` directly |
| X-2 | **Every place that asks "live?" uses X-1:** the ADR-025 lookup (an overdue draft is the not-found response, decision log 30 Oct; so is publish of it, AC 4, 5), the post-build re-read (P-6), and the store's due query and live-public query. The store's queries are the SQL form of X-1. A boundary check pins the SQL to the pure rule (deadline − 1 s live, deadline due, for drafts and unlisted rows) | Without this the owner API could still serve a draft the sweep has not reached. Two homes of one rule must be pinned to each other |
| X-3 | **Due is final.** Every owner write runs the lookup under the O-7 lock, and the expiry pass deletes under the same lock, so no request can revive a due row (lengthen its lifetime, publish it). Every owner update also re-checks `Live(now)` on the row it read **inside the update** and answers not found when it is due (QA-21-r1-2): a request that passed the lookup before the deadline and commits after it is refused, not reported as saved or published and then deleted. A clock stepped backwards can delay a delete; it cannot resurrect content already removed. Accepted | Lets the pass delete without re-checking each row against the owner's changes |
| X-4 | **The expiry pass** is one `lifecycle` operation. In order: (1) list the due rows; (2) delete each through `Delete` (F-12 O-10: row, then `public/{public_id}`, then `private/{id}`), each under the O-7 lock, with one INFO line `workout deleted`, `id`, `by=expiry` (drafts too); (3) the P-8 public sweep under the O-7 lock, which releases the bytes it frees. **Step 3 runs even when step 1 fails** (QA-21-r1-4; the sweep has its own query); (4) when step 2 deleted a row, or an earlier checkpoint was incomplete, the WAL checkpoint of ADR-019 item 9. A failure on one row is logged (ERROR with `id` and stage, never the `public_id`, P-14) and the pass goes on; the next pass retries. The pass logs nothing when it removed nothing | The public sweep in step 3 removes a due workout's public folder even when its row delete failed, because the live-public query (X-2) no longer lists it: what is served converges independently of the row |
| X-5 | **When it runs.** `serve` runs the pass once at startup, after `Recover` and before the storage total is measured and the listener opens (AC 6), then **every 30 s** on a timer that lives in `cmd` (I/O at the edge; the pass takes `Deps.Now`). Not a setting. The pass never stops the timer on error. **A failing startup pass is logged and `serve` starts anyway**; the timer retries. Until then AC 6 rests on the lookup (a due row is not found, X-2) and on `Recover`'s sweep, which already removed its public folder | SH-10 counts from the deadline. A 60 s period plus the run time would already miss 60 s. 30 s leaves room for the waits in X-6. One indexed query and one listing of `public/` per pass cost nothing at this volume |
| X-6 | **SH-10 bound.** Deadline → files gone ≤ 30 s (period) + one owner build waiting on O-7 (≈ T + one compression, T = `WORKOUT_EXPLORER_PARSE_TIMEOUT`) + one other process's write phase waiting on the public lock (ADR-031). At the default T = 10 s this is about 45 s. With T above about 25 s, a save of a slow file that overlaps a deadline can exceed 60 s. Accepted and recorded; the operator setting is the lever. While Go is down, Caddy keeps serving `public/` (ADR-028 context 1): see OQ-87 | Makes the bound checkable instead of assumed |
| X-7 | **Sweep vs a concurrent build in another process (QA-15-r2-1): a cross-process lock**, [ADR-031](ADR-031-cross-process-lock-on-the-public-area.md). `publish` takes one exclusive `flock` on `{data}/public.lock` for every operation that changes `public/` (write phase, folder removal, sweep), in every process (`serve`, F-30 `regenerate`, F-27 `delete`). In `serve`, O-7 is always taken before it. Rejected: a grace period for new unlinked files. It does not cover a first-publish or remove-first folder that has no `index.html` yet (the sweep removes it whole and the other build then fails), and it makes what the sweep removes depend on file times | Exact by construction, stdlib only, released when the holder dies |
| X-8 | **Private orphans at runtime.** If `Delete` removed the row but not `private/{id}`, the folder stays until the next start (`Recover`, ADR-022 item 5); the ERROR line tells the operator. The pass does not sweep `private/` | A folder without a row is also the normal state of an upload in flight (folder first, row last, ADR-022), so a runtime sweep would delete uploads. Private files are never served, so SH-10 is not at stake |
| X-9 | **AC 8, the complete check.** The F-12 AC 5 list of places that hold workout data becomes the complete check: after an expiry, the row, `private/{id}`, `tmp/` and `public/{public_id}` are empty or absent, and the check also enumerates the database's tables and the data directory's entries and fails on any it does not classify. F-27 (`reports`) and later pins must add theirs. It also **scans the bytes of `workouts.db`, `-wal` and `-shm`** for the deleted workout's title, description and `public_id`, and fails on any hit (QA-21-r1-1, user decision 31 Oct 2026; the store side is ADR-019 item 9). **Accepted limit:** copies below SQLite (file system journal, SSD remapping, backups) are not covered | "Every table and folder" must not depend on someone remembering to extend a list. A row count says nothing about free pages and WAL frames |
| X-10 | **Already built, verify only:** the lifetime change rewrites the page in place (`expires_at` is on the P-7 allow-list, F-15 P-11), the generic page after expiry (no `index.html`, P-13), and expired rows answered as not found (ADR-025) | AC 1 (generic page), AC 7 |

## Verification (critical lane: QA at effort high)

| What | Check |
| --- | --- |
| X-1, X-2 | Injected clock at deadline − 1 s and at the deadline, for an unlisted row, a draft under 48 h, a draft whose lifetime ends before 48 h, and a draft published at 47 h with 7 days (AC 2, 3). Owner `GET`, `PATCH`, `publish`, `DELETE` and both downloads answer the byte-identical not-found response for an overdue draft the pass has not deleted (AC 4, 5) |
| X-4, X-5 | End to end through `newApp`: a due row and its three places gone after one pass; the generic-page condition (no `index.html`) holds; a failing public or private removal does not stop the pass or the next row; the storage total drops by the freed bytes. Restart over a deadline: gone before the listener opens (AC 6) |
| X-7 | The QA-15-r2-1 probe (`TestQAR2SweepDuringOtherBuild`, a second `Area` on the same data directory) passes: no broken page. Because `flock` is per open file, two `Area`s in one test process exclude each other. A real-binary run: `serve` with the pass running while another process rebuilds in a loop leaves no page linking a missing file |
| X-9 | Adding an unclassified table or data-directory entry fails the check. After an expiry and after an owner delete, with the server still running, the byte scan finds none of the three values |
| Mutants | Each must fail a test: the draft rule dropped from the lookup or from the due query; `<=` swapped for `<` at either boundary; 48 h as calendar days; the pass without the public sweep; the sweep or a write phase without the public lock; the startup pass after the listener; one failed row stopping the pass; `secure_delete` off; no checkpoint after the pass or after an owner delete; no `Live` re-check inside the update; the sweep skipped when the due query fails |

## Hand-offs

| To | What |
| --- | --- |
| F-30 | (1) Builds and deletes go through `publish`, so they take the ADR-031 lock with no extra code. (2) The lock does not make the record current: `regenerate` builds from a row it read seconds earlier, and an owner's hides-more save in `serve` can land in between. Before its write phase, inside the lock, `regenerate` must confirm the row still equals the record it built from, and rebuild if not; otherwise a stale, less hidden page can overwrite a newer one (SH-10, privacy). (3) Choose workouts with X-1 and skip due ones; expiry deletes are `serve`'s. The post-build re-read (P-6) already uses X-1. (4) Its rewrite of `draft.bin` in `private/` races `serve`'s deletes the same way: it must never recreate a folder whose row is gone (write only into an existing `private/{id}`, or take the same lock). (5) `serve`'s storage total does not see `regenerate`'s writes; the drift lasts until the next start. Accept or re-measure, F-30 decides. (6) F-21 adds no `Record` field, so P-7's allow-list is unchanged by F-21. The CONTINUE.md reminder stays F-30's: recompute ADR-030's hidden ranges and put `HiddenRanges` on `publish.HidesMore`'s allow-list (never public), or every regenerate becomes remove-first |
| F-27 | `workout-explorer delete` goes through `Delete`, so it takes the ADR-031 lock, and checkpoints after it (ADR-019 item 9). Add `reports` to the X-9 check, including its text columns in the byte scan |
| F-31 | `Restart=always` for `serve` (shortens OQ-87's window). The data directory is a local file system (`flock`, ADR-031). Never let Caddy serve `{data}/public.lock` (it is outside `public/`) |
| Requirements (TD) | Publish 7: "every 30 s and once at startup" (or "often enough for SH-10, F-21 X-5"). Files on disk: add `public.lock`. Code structure: `publish` holds the public lock (ADR-031). ADR-028 item 5 now points here for the schedule |
