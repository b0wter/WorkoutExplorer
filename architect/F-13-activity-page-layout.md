## Decisions

| # | Decision | Why |
| --- | --- | --- |
| D-1 | **Template.** `src/web/index.html` becomes the page template: Go `html/template`, logic-free, executed with `missingkey=error`, printing only strings. `build/web/index.html` is the deployable template; it is never served raw. The frontend owns it; F-15 executes it | ADR-026 items 1, 2. Contextual escaping is what makes AC 5 hold |
| D-2 | **Page view model** (the template's only input). Display-ready strings in these groups: page (document title, view path, data file URL), header (title or UP-4's default "Ride, 9 Oct 2026", sport name and icon key, local start date and time, description, expiry date), summary items in AP-2 order, route presence, chart count, laps (columns and cell strings). Later features add groups (F-23 Open Graph, F-24 download). Keys are always present; a group that is absent is `null` and is only tested, never printed. Route presence is two test strings (`Route.Map`, `Route.NoLocation`), the chart count is one class string (`ChartsClass`, e.g. `charts-6 cells-8`: charts and readout cells), because the template has no comparison functions | The samples (D-3) are the contract, not this list. One home per fact |
| D-3 | **Sample view models** in `src/server/testdata/page/`, written by the pure builder `lib/page` from the synthetic golden data files plus fixed settings. `make ci` fails when they are stale. Together they cover: a ride with a route, `ride-12h` (24 laps, the HTML budget case), a run without power, a workout without heart rate, an indoor file, an unknown time zone, a multisport file, and a title and description containing HTML and `<script>`. F-15's Go builder must reproduce them exactly | One contract for both languages (review decision 30). Synthetic only (ADR-004) |
| D-4 | **Summary values.** Every value is the data file's `summary` as written (device totals, else the server's value; F-08 R-10). The page never chooses between the two and never computes. An absent key means no cell at all: no 0, no dash. Shown: the AP-2 metrics in AP-2's order. `timer_time` and `descent` are not shown. Pace for running, walking and hiking (per km), swimming (per 100 m) and rowing (per 500 m); speed for every other sport, `multisport` and unknown included. A pace from a speed ≤ 0 is hidden. Cadence is spm for the pace sports, rpm for the others, and the neutral "/min" for `multisport`. Maximums (OQ-61, decided): for speed or pace, heart rate, power, cadence and temperature, wherever the summary has them, as a second value in the same cell as the average ("max 172"); a maximum without its average is the cell's value, labelled "Max …". The server markup is always metric (question 7); F-14 changes units in place | OQ-22. F-08 hand-off: the browser never derives speed from distance |
| D-5 | **Laps markup** (columns provisional, OQ-28): lap totals as written in the data file. "Time" is the lap's `elapsed_time`. A column appears when at least one lap has its value; a cell without one shows "–". There is no laps module when the file has no laps *(29 Oct 2026: nor advancing distance, F-18 L-8)*. AP-8's computed values for laps without device values go into the data file's lap totals on the server (ADR-026 item 3; hand-off) | No renderer computes. One computation for page and client |
| D-6 | **One formatting home:** a pure `lib/format` module (it absorbs `lib/charts/format.ts`) for numbers, durations, pace, dates and sport names. It uses fixed English strings and never `Intl` or `toLocale*`, because their output differs between engines and from Go. F-14 extends it; Go mirrors only the metric part, held equal by the samples | DS-3; byte-equal output in two languages |
| D-7 | **Local time** (AC 2) and **expiry** (OQ-62, decided 24 Oct 2026). Start = `start_time` + `offset_seconds` when the zone is known, formatted from the shifted instant with UTC getters only (TypeScript) or a fixed zone (Go), never the viewer's zone. An unknown zone shows UTC with a "UTC" label (question 13). 24-hour clock; dates as "9 Oct 2026". The markup written at publish shows the expiry as an estimate, a date only in the workout's zone (UTC when unknown): "Expires around 30 Oct 2026", in a `<time datetime>` element carrying the UTC `expires_at`. When the bundle runs, it replaces the text with "Expires in …", computed from that UTC time, so it is the same in every zone. The bundle shows no date; any date the browser shows uses the browser's time zone | The server markup cannot know the viewer's zone, and both sides must print the same text. Replaces the earlier "date only, same zone as the start" rule |
| D-8 | **Adoption, not hydration.** The client never re-renders server markup. Svelte `mount()`s only into empty slots: the map, the charts, and the range panel (F-17). Behaviour on server markup (copy link now; units F-14, laps rows F-18, report form F-28) is attached by framework-free enhancers through hook attributes, and those work on any markup that carries the hooks | ADR-026 item 4 |
| D-9 | **Edit page (F-19).** Svelte static components (header, summary and notice, hint, laps, footer without the Report link, question 21) render the template's markup from the view model, which `lib/page` builds in the browser. They sit under one root component that F-19 mounts in its lazy owner chunk. The map and charts island and the enhancers are the same as on the viewing page. The viewing entry never imports these components (0 counted bytes). The template is the reference markup | Feature scope. ADR-011 item 2 (owner UI is lazy) |
| D-10 | **No layout shift.** Markup and CSS reserve every box the client fills before the bundle runs: the map box when presence is `route`; the chart area by F-05's `chartAreaHeight(n, chartHeight)`, chosen by a class from the chart count; and the readout's first-render height at each breakpoint. No `style` attributes (CSP). No viewport units (`vh`, `dvh`, `svh`, `lvh`) in any height: phone browser bars change some of them, and fixed pixels per media query are enough. System fonts only. *Exception (24 Oct 2026, D-18): the sticky desktop map in the two-column query may be `100vh` with a `100lvh` override; it moves nothing in the right column.* Layouts per D-17. With JavaScript off, reserved boxes stay empty. Changes the user causes (pinning, D-19) may move content; nothing else may. *Exception (29 Oct 2026, F-17 QA-17-r1-2): a split the viewer stored (AP-17) is applied synchronously at the start of the page glue, before any `await`; if that runs after the first paint, the one shift it causes is accepted as the viewer's own choice. (User, 29 Oct 2026: accepted for now also on a cached reload, as module scripts run after the first paint; a later fix may be a small inline `<head>` script setting `--map-w` before the first paint, allowed by its CSP hash in F-22.)* | AC 7. Box sizes are a function of the view model, the viewport width and height, and user actions only |
| D-17 | **Two layouts, one markup, CSS only.** Breakpoint `min-width: 1024px`. **Two columns** at and above it when the page has a map box (`Route.Map`): left column the map; right column header, summary, privacy notice, charts, range slot, laps, footer (the footer is the last item inside the layout wrapper, so the left column is only the map; on the phone the pinned map may stay pinned over it). **One column** below it, and at every width when there is no map box (indoor hint, or no visible route): today's order (header, summary, notice, map or hint, charts, range slot, laps, footer) and today's maximum width. The template keeps one DOM order (today's); CSS places the boxes (grid placement), so the server markup, the edit page's components and the reading order are the same in both layouts. The template marks the map case with a class from the existing `Route.Map` test (`{{if .Route.Map}}`), not `:has()`; the view model and the samples do not change. In two columns the right column is never narrower than 608 px (the content width at which the 4-column readout of D-10 was reserved), and the page's maximum width grows so both columns have room; the column ratio is 1:1 (`minmax(320px, 1fr) minmax(608px, 1fr)`; user's request, 24 Oct 2026) | User decision 24 Oct 2026. 1024 keeps phones in any orientation and tablets in portrait in one column. 608 px keeps the readout's reserved row count true inside the narrower column |
| D-18 | **Desktop map is sticky; no toggle there.** In two columns the map box sticks to the top of the viewport (small top offset) while the right column scrolls, for as long as the right column lasts. Its height is the large viewport: `100vh` with a `100lvh` override (never resizes, never leaves a gap when Safari's bar collapses, iPad report 24 Oct 2026; with the bar showing, the bottom strip is out of view, so attribution moves to the top, left of the zoom control, and fitBounds uses 60 px bottom padding in two columns), no top offset, no stepped px heights (user decision 24 Oct 2026; the only viewport unit in the CSS, allowed because a sticky box in its own column moves nothing else). The map is flush with the column and page edges (`.page.has-map` has no padding or max width); the header is the first item of the right column, so the map starts at the window's top edge, is exactly one window tall and spans every grid row (its containing block is the whole right column); the right column and footer keep their padding. Pure CSS | The map ↔ chart link is the point of the page; on desktop the charts (up to ~1,000 px) would otherwise scroll the map away. Costs no byte of script and no choice for the viewer. Would choose differently if the operator finds a sticky map distracting while reading laps: then stop it at the end of the charts |
| D-19 | **Phone: the pin toggle.** One column only, map case only. An icon-only pin button in MapLibre's top-right control stack under fullscreen, styled as its control group (8 Nov 2026; colour selector moved top left), **bundle-only**: the glue in `src/page` creates it in `onmapready`, so it never exists without JavaScript, before the map, or when the map failed (F-06 failure text). It is a child of that control stack inside `#map-slot`, so inserting it moves nothing. It toggles one class on the layout wrapper and `aria-pressed`; off at load; held in memory only (no storage, no URL). Everything else is CSS under a `max-width: 1023.98px` query: when pinned, the map box is `position: sticky; top: 0`, above the charts, with a smaller fixed height per orientation (24 Oct 2026: `--pin-h: 35vh`, overridden to `35lvh` inside `@supports (height: 1lvh)` so browsers without lvh keep a working value, never dvh/svh so the browser bar does not resize it; 125 px on short landscape screens, where 35 % would leave no chart; both at most 40 %, AP-18). The toggle has aria-label and title "Pin map" and shows its state through aria-pressed and a pressed style, and the readout's sticky `top` (F-05 D-17) becomes that height so it sticks under the map instead of behind it. Pinned height constraint: below the pinned map and the readout, at least one whole chart (plot and title row) is visible on the reference phone (iPhone 13 mini) with the browser bars shown, in portrait and in landscape. The map box's containing block must reach past the charts (a one-column grid row does not: sticky would never engage); it may run to the end of the laps. Pinning shrinks the map box in the flow, so content below moves once, caused by the tap (outside CLS by definition). Across the breakpoint the class stays but is inert at ≥ 1024 px, and the button is hidden there. Wording proposed by the engineer (OQ-63 rule). The edit page gets the same toggle through the same glue | User decision 24 Oct 2026. Useless without JavaScript, so not in the template: the HTML budget and the Go side are untouched. One class keeps the script to a click handler; CSS owns every size |
| D-20 | **Map size follows its box.** On the page, CSS owns the map's height in every layout and state; `RouteMap`'s container fills `#map-slot` instead of carrying a fixed px height (today `start.ts` passes `clientHeight`, which F-06's `height` prop reads once). How `RouteMap` expresses "fill the parent" is the engineer's choice; `bench/map.html` may keep a fixed height. On phones (< 1024 px) the attribution stays expanded for 5 s after its text first appears (first `idle` that finds text), or until the first pointer or wheel input on the map, whichever comes first, then collapses to its (i) button; a tap on (i) is the viewer's choice and ends the auto-collapse (user decision, QA-13-r2-4). The existing rect cache rules cover it (stale on `resize` and on `scroll`). The cursor link is unchanged while pinned: the same store and marker; touch on the pinned map follows F-06 D-10 (one finger on the route scrubs, elsewhere scrolls the page) | A 320 → ~200 px shrink at a fixed zoom would cut the route and lose the cursor marker, which defeats pinning. Lazy code only: 0 static bytes. Would choose differently if the refit feels jumpy on the phone; then refit only on pin and unpin |
| D-11 | **Head.** `lang="en"`, viewport, `referrer no-referrer` (ADR-014), `robots noindex, nofollow, noarchive` (TD), document title, `<link rel="preload" as="fetch" crossorigin>` for the data file, the module script and the one stylesheet. No inline `<style>` or `<script>` (ADR-026 item 5). F-23's tags render only when their group is present | TD Load order step 2: the HTML preloads bundle and data file |

| D-13 | **Load failure** (AC 9, OQ-10). Header, summary, notice and laps stay. In production a version mismatch means an old bundle met a newer data file (a tab open across a deploy, mainly the edit page); a reload fetches the current page and bundle | Keeps F-07 D-3's text and logic (`load-error.ts` moves) |
| D-14 | **Copy link (SH-6).** The markup has a link to the view path, so nothing shifts when it is enhanced, and without JavaScript the browser's "copy link address" works. ## B-1 Backend step: protoserve serves sample pages (senior-backend-engineer, after the frontend part)

- protoserve stops serving the raw template (`/` and `/index.html` return 404). It executes `<web>/index.html` once at start-up for each sample (`html/template`, `missingkey=error`, the JSON decoded into a map) and serves the result at `/w/<name>`, with brotli like every other file. The start-up listing prints raw, gzip -9 and brotli sizes for each page.
- A Go test, run by `go test` and so in CI, executes the source `src/web/index.html` with every committed sample. It checks that execution succeeds and that the page shows the AC 1, 3, 4, 5, 8 and 10 content. `ci` runs tests before the Vite build, so the source template is the one tested; Vite only adds tags.
- `make prototype-data` writes the synthetic data files that the samples point at. Standard library only; the protoserve dependency rule is unchanged.
