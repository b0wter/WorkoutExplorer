## Decisions

| # | Decision | Why |
| --- | --- | --- |
| AB-1 | **One page, `/about`, frontend-owned template `src/web/about.html`**, a fifth Vite entry like `generic.html` (F-15 P-12). CSS only: it imports the plain pages' theme (`src/theme/plain.css`), so light and dark follow `prefers-color-scheme` with JavaScript off; no theme drop-down (decision log 3 Nov 2026). No `<script>`, no inline style, no theme head script. Metas as on the generic page (`color-scheme`, `referrer no-referrer`, `robots noindex, nofollow, noarchive`). Licence texts sit in `<details>`, which opens without JavaScript. No chunk shared with the activity entry (ADR-024); no JavaScript, so no ADR-011 share. A static check like `generic.test.ts` asserts: no script, the metas, every loaded resource (`src`, `<link href>`) same-origin (external `<a>` links are allowed), the footer link, and the PT-17 sentence word for word | AC 6, AC 7. Reuses the theme and check the plain pages already have |
| AB-2 | **The privacy text lives verbatim in that template**: one home, no Markdown step, no second copy. The **user owns its wording** (OQ-106). FE-1 drafts it from the facts table below; a wording change later is a small-lane change. An engineer never changes what a sentence states without the user | The privacy policy is a product and legal statement, not code |
| AB-3 | **Per-deployment values are filled by `serve` at start; everything else is in the release build.** Slots: operator name, operator contact, the binary's version, and one block that is present only when both Pushover settings are set (INF-4). Two new settings, rows below. **No base URL on the page:** every internal link is relative, so `WORKOUT_EXPLORER_BASE_URL` is not read for it | The release is public and self-hosters deploy the same bytes (F-31 DP-16, DP-18), so no operator fact may be baked into the build. The env file is the one home of per-deployment values (DP-6), and only Go reads settings (TD Configuration). Go already knows whether Pushover is on, so the page never claims a notification that is off |
| AB-4 | **Go serves `/about`.** `serve` reads `<web>/about.html` once at start (as `index.html`, F-15 P-10), fills AB-3, keeps the bytes in memory and answers `GET`/`HEAD /about`; Go adds no access log. Missing, unparsable, or still without the generated list → exit 1 before listening. The fill must not interpret anything in the generated list (licence texts may hold any characters, `{{` included). Caddy: `handle /about` proxies to Go and sets `Cache-Control: no-cache`; the H-2 set applies unchanged. Caddy never serves `build/web/about.html` itself (`/about.html` stays `404`). **Cost:** `/about` answers `502` while Go is down (a few seconds per deploy). Rejected: Caddy `templates` (no validation of the values; it would need the Pushover token to know on/off; it executes actions inside licence texts); writing the page into `public/` (ADR-028 item 5 sweeps every entry that is not a live workout folder); substitution in `deploy.sh` (a second path for Dockerfile users) | One reader of settings, one validation path, one page for both deploy paths. **Would choose differently if** the About page must stay up while Go is down: then Caddy `templates` with custom delimiters and the Pushover block dropped |
| AB-5 | **The attribution list is generated in every `make build`**, so in `make ci`, the tag build that becomes the release, and the Dockerfile's Go stage (after the web build is copied in). It reads the build's own outputs (table below); nothing generated is committed, so nothing can go stale. Generator: a dev-only Go program in `src/server/tools/attributions`, standard library only, never in the binary (as `corpusgen`). Output deterministic (sorted), names and texts HTML-escaped; links come only from the committed sources file and only as `https:`. Our own entry: AGPL-3.0, the repository URL (committed constant; a fork edits it) and the version slot | AC 4. The bundler and the linker decide what ships, so the list follows them by construction; dev tools (Vite, TypeScript, Vitest, `corpusgen`) never appear because they never ship. AGPL section 13 asks for a source offer to network users |
| AB-6 | **The build fails** (so CI and the Docker build fail) when: Vite's licence file is missing; an npm entry has no licence identifier or no text; a Go module has no licence file; a sources entry has no licence name or link; an external origin in the `deploy/Caddyfile` CSP is not claimed by a sources entry; the template has no place for the list. **Escape hatch:** a committed licence text for one package at one exact version, for a package that ships none; a version bump fails again until someone looks | AC 4 ("cannot be determined"). The CSP rule guards the one hand-written part that can go stale: a new tile or font host cannot ship without its attribution |
| AB-7 | **Footer link `/about` on every page** (F-11 U-11 fixed the path): upload, generic, viewing, edit, published, the deleted screen (all present today), and the About page itself, which also links to `/` | AC 1 |

**Sources of the list (AB-5)**

| What | Read from | Shown |

**New settings (TD Configuration rows)**

| Setting | Meaning | Default | Format | Read by |
| --- | --- | --- | --- | --- |
| `WORKOUT_EXPLORER_OPERATOR_NAME` | The operator named on the About page (controller, INF-1) | none: the page shows `[OPERATOR NAME]` | Free text, trimmed, 1–100 Unicode code points, no control characters; invalid → exit 2 | `serve` |

## Privacy text: structure and facts

The user writes or approves the wording (OQ-106). The page must state every fact below; QA checks each against the page. Section order is a suggestion.

| # | Section | Fact the page must state | Source |
| --- | --- | --- | --- |
| PT-1 | Who runs this site | Operator name and contact (AB-3 slots). The site runs on a rented server in an EU data centre; the hosting provider processes the data on the operator's behalf. No backups | INF-1, decision 25, NFR Privacy, F-31 DP-13 |
| PT-2 | What is stored | Four kinds, per workout: the **FIT file** as uploaded minus PT-3; the **workout data** built from it (data file, page, preview image); the **settings** (title, description, start and end hiding, lifetime, published or draft, times; the edit link only as a hash); **reports** (reason, optional message up to 1,000 characters, time; no contact details, no IP address) | INF-1, INF-2, TD Data model |
| PT-3 | Removed from every FIT file on upload | The UP-9 list, word for word as in AC 3: device and sensor serial numbers and ANT+ IDs, wherever the file records them; the user profile (name, gender, age, height, weight, heart-rate settings); saved locations; segment leaderboard entries, the segment leaders' activity IDs and segment account keys; raw ANT radio messages | UP-9, ADR-023 item 4 |
| PT-4 | What is not stored | No accounts, email addresses or cookies, no analytics or tracking. IP addresses are never written to disk: rate limiting keeps a hashed client address in memory for up to an hour. Server logs hold no IP address, link or location; a file that fails to parse is logged with its device model | NFR Privacy, ADR-021 item 11, F-22 H-9, TD Logging, F-31 DP-9, DP-11 |
| PT-5 | How it is used | Only to show the workout to people with its link, to let the edit-link holder change, download or delete it, and to let the operator act on reports. Nothing else: no advertising, profiling or sale | INF-1, INF-3, AC-5 |
| PT-6 | Who sees a workout | Draft: only the edit-link holder. Published: anyone with the viewing link (unlisted, `noindex` on every response, so search engines do not list it). Hidden start and end sections are removed from the public data, not just hidden | SH-1, SH-2, SH-4, F-22 H-8 |
| PT-7 | Link previews | When someone pastes a viewing link into a messenger, its service fetches the title, headline numbers and the route image. Previews already made cannot be recalled | SH-5, SH-10 |
| PT-8 | Map tiles | The F-06 hand-off paragraph: OpenFreeMap (possibly through Cloudflare) sees the viewer's IP address, browser type and the map area, not which workout; its own statements on cookies and log retention, re-checked at launch | ADR-014, OQ-17, F-06 hand-off |
| PT-9 | Report notifications (only when on) | Pushover learns that a report with a given number and reason arrived; never the link, title, public ID or message. Rendered only when both Pushover settings are set (AB-3) | INF-4, ADR-039, F-27 hand-off |
| PT-10 | Operator's access | The operator can read reports and delete any workout after a report, without its edit link. The operator cannot tell who uploaded a workout | INF-3, F-27 R-7, AC-1 |
| PT-11 | Operator's web server | The TLS proxy in front of the app is the operator's; what it logs is the operator's statement (OQ-106 b) | F-31 DP-15 and hand-off |
| PT-12 | How long | Lifetime 7 days by default, at most 30 days from upload, chosen by the edit-link holder; never-published drafts deleted 48 hours after upload; delete at any time with the edit link removes everything at once; content stops being served within 60 s; reports go with their workout, at the latest 30 days after filing; no backups | UP-7, AC-4, SH-10, INF-2, decision log 3 Nov 2026 |
| PT-13 | Copies outside our control | Copies viewers already saved and previews already made stay with them | SH-10 |
| PT-14 | In your browser | The units choice, the x axis, the map/content split (separately for wide and short landscape screens) and the theme choice are kept in the browser's storage, no cookie, never sent to the server, until the viewer clears them. The theme is not in INF-1 yet (OQ-105) | DS-1, AP-5, AP-17, DS-4 (3 Nov 2026), NFR Privacy |
| PT-15 | Your rights | Download the stored file and delete the workout with the edit link (export and erasure); without the edit link the operator cannot verify ownership, but anyone can report a workout. Complaint to a data-protection supervisory authority. Legal basis: OQ-106 a | NFR Privacy, INF-2, INF-3 |
| PT-16 | Source and licences | The app is AGPL-3.0 with a link to its source and the running version (AB-5), followed by the generated attribution list | Decision log 2 Nov 2026, INF-1 |
| PT-17 | Upgrades | Exactly: "Workouts are not archived: after an app update, a damaged file may show less than before or be removed." | Decision log 21 Oct 2026, AC 2 |
