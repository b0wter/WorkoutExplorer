## Decisions

| # | Decision | Why |
| --- | --- | --- |
| AB-1 | **One page, `/about`, frontend-owned template `src/web/about.html`**, a fifth Vite entry like `generic.html` (F-15 P-12). CSS only: it imports the plain pages' theme (`src/theme/plain.css`), so light and dark follow `prefers-color-scheme` with JavaScript off; no theme drop-down (decision log 3 Nov 2026). No `<script>`, no inline style, no theme head script. Metas as on the generic page (`color-scheme`, `referrer no-referrer`, `robots noindex, nofollow, noarchive`). Licence texts sit in `<details>`, which opens without JavaScript. No chunk shared with the activity entry (ADR-024); no JavaScript, so no ADR-011 share. A static check like `generic.test.ts` asserts: no script, the metas, every loaded resource (`src`, `<link href>`) same-origin (external `<a>` links are allowed), the footer link, and the PT-17 sentence word for word | AC 6, AC 7. Reuses the theme and check the plain pages already have |
| AB-2 | **Two homes for the privacy text, split by who it is true for.** The template holds only what is true for **every deployment of this code** (PT rows marked *app*), verbatim, no Markdown step. Everything about one deployment (PT rows marked *operator*) is in the operator file (AB-8). The **user owns the wording** of both; FE-1 drafts the template text from the table below, B-1 writes the example operator file as headings with bracketed prompts. An engineer never changes what a sentence states without the user. Test for the template: a self-hoster on another host, with backups and another proxy, must find no false sentence in it | The release is public and self-hosters serve the same bytes (F-31 DP-16, DP-18). A deployment fact in the template would be false for someone |
| AB-3 | **Filled by `serve` at start:** the operator block (AB-8), the binary's version, and one block present only when both Pushover settings are set (INF-4). Everything else is in the release build. **No base URL on the page:** every internal link is relative. The two settings `WORKOUT_EXPLORER_OPERATOR_NAME` and `_CONTACT` are **dropped**: name and contact are written in the operator file, one mechanism | Go already knows whether Pushover is on, so the page never claims a notification that is off. Two env values beside a file would be two homes for operator facts |
| AB-4 | **Go serves `/about`.** `serve` reads `<web>/about.html` and the operator file once at start (as `index.html`, F-15 P-10), fills AB-3, keeps the bytes in memory and answers `GET`/`HEAD /about`; Go adds no access log. Template missing, unparsable, or without the generated list → exit 1 before listening. The fill must not interpret anything in the generated list or in the operator block (`{{`, markers and the like stay text). Caddy: `handle /about` proxies to Go and sets `Cache-Control: no-cache`; the H-2 set applies unchanged. `/about.html` stays `404`. A change to the operator file takes effect at the next restart of `app`. **Cost:** `/about` answers `502` while Go is down. Rejected: Caddy `templates` (no validation; would need the Pushover token; executes actions inside licence texts); writing the page into `public/` (ADR-028 item 5 sweeps it); substitution in `deploy.sh` (a second path for Dockerfile users) | One reader of settings, one validation path, one page for both deploy paths. **Would choose differently if** the About page must stay up while Go is down |
| AB-5 | **The attribution list is generated in every `make build`**, so in `make ci`, the tag build that becomes the release, and the Dockerfile's Go stage (after the web build is copied in). It reads the build's own outputs (table below); nothing generated is committed. Generator: a dev-only Go program in `src/server/tools/attributions`, standard library only, never in the binary (as `corpusgen`). Output deterministic (sorted), names and texts HTML-escaped; links come only from the committed sources file and only as `https:`. Our own entry: AGPL-3.0, the repository URL (committed constant; a fork edits it) and the version slot | AC 4. The bundler and the linker decide what ships, so the list follows them by construction. AGPL section 13 asks for a source offer to network users |
| AB-6 | **The build fails** (so CI and the Docker build fail) when: Vite's licence file is missing; an npm entry has no licence identifier or no text; a Go module has no licence file; a sources entry has no licence name or link; an external origin in the `deploy/Caddyfile` CSP is not claimed by a sources entry; the template has no place for the list. **Escape hatch:** a committed licence text for one package at one exact version, for a package that ships none; a version bump fails again until someone looks | AC 4 ("cannot be determined"). The CSP rule guards the one hand-written part that can go stale |
| AB-7 | **Footer link `/about` on every page** (F-11 U-11 fixed the path): upload, generic, viewing, edit, published, the deleted screen, and the About page itself, which also links to `/` | AC 1 |
| AB-8 | **Operator file: plain text with a three-rule line format, every character HTML-escaped.** Path from one setting, `WORKOUT_EXPLORER_OPERATOR_FILE` (row below). Format, UTF-8: a line `## Text` is a heading (`<h2>`, the template's section level); consecutive lines `- Text` form one list; other non-empty lines join (with a space) into a paragraph; a blank line ends a block. Nothing else is markup: no inline formatting, no links, no HTML (`<b>` shows as `<b>`); an e-mail or web address shows as text. **Limits:** at most 16 KiB, valid UTF-8, no control characters except tab and line ends (CRLF accepted), at least one non-blank line; breach → exit 2 naming the setting. **Unset, or the file does not exist** → the block is a visible placeholder (decision 25) that names what is missing ("[OPERATOR DETAILS: who runs this site, contact, hosting, web server logs, backups, legal basis, complaints]") and `serve` logs one warning at start; any other read error (permissions) → exit 2. The template has one marker for the block, where "Who runs this site" goes. **Repository:** only `deploy/operator.example.txt`, one heading per *operator* PT row with bracketed prompts, no real facts. The operator's own file never enters the repository or the release | Operator-authored, but published to every visitor, so it cannot inject markup or script (the CSP backs this, but escaping makes it true by construction). A real Markdown parser is a dependency for three rules. Missing → placeholder keeps local runs, CI and test deploys working; F-32 checks it is gone. **Would add** `https:`/`mailto:` links (scheme allow-list) only if the user asks for clickable contact |

## Privacy text: structure and facts

The page must state every fact below; QA checks each *app* fact against the template and each *operator* row against `deploy/operator.example.txt` (a prompt per row). The user's own file is checked at F-32. Section order is a suggestion.

| # | Home | Section | Fact | Source |
| --- | --- | --- | --- | --- |
| PT-1 | operator | Who runs this site | Operator name and contact; hosting provider (named or as a category) and where the data centre is; that the provider processes data on the operator's behalf | INF-1, decision 25, NFR Privacy, F-31 DP-13 |
| PT-2 | app | What is stored | Four kinds, per workout: the **FIT file** as uploaded minus PT-3; the **workout data** built from it (data file, page, preview image); the **settings** (title, description, start and end hiding, lifetime, published or draft, times; the edit link only as a hash); **reports** (reason, optional message up to 1,000 characters, time; no contact details, no IP address) | INF-1, INF-2, TD Data model |
| PT-3 | app | Removed from every FIT file on upload | The UP-9 list, word for word as in AC 3 | UP-9, ADR-023 item 4 |
| PT-4 | app | What is not stored | No accounts, email addresses or cookies, no analytics or tracking. The app writes no IP address to disk: rate limiting keeps a hashed client address in memory for up to an hour. The app's own logs (including its bundled web server) hold no IP address, link or location; a file that fails to parse is logged with its device model | NFR Privacy, ADR-021 item 11, F-22 H-9, TD Logging, F-31 DP-9, DP-11 |
| PT-5 | app | How it is used | Only to show the workout to people with its link, to let the edit-link holder change, download or delete it, and to let the operator act on reports. No advertising, profiling or sale | INF-1, INF-3, AC-5 |
| PT-6 | app | Who sees a workout | Draft: only the edit-link holder. Published: anyone with the viewing link (unlisted, `noindex`). Hidden start and end sections are removed from the public data | SH-1, SH-2, SH-4, F-22 H-8 |
| PT-7 | app | Link previews | Messenger services fetch title, headline numbers and route image; previews already made cannot be recalled | SH-5, SH-10 |
| PT-8 | app | Map tiles | The F-06 hand-off paragraph: OpenFreeMap (possibly through Cloudflare) sees IP address, browser type and map area, not which workout; its statements re-checked at launch | ADR-014, OQ-17, F-06 hand-off |
| PT-9 | app, conditional | Report notifications | Pushover learns report number and reason only. Rendered only when both Pushover settings are set (AB-3) | INF-4, ADR-039, F-27 hand-off |
| PT-10 | app | Operator's access | The operator can read reports and delete any workout after a report, without its edit link, and cannot tell who uploaded a workout | INF-3, F-27 R-7, AC-1 |
| PT-11 | operator | Web server logs | What the TLS proxy in front of the app logs (addresses, how long kept), or that it keeps none. The template makes no claim about it | F-31 DP-15, decision log 4 Nov 2026 |
| PT-12 | app | How long | Lifetime 7 days by default, at most 30 days from upload, chosen by the edit-link holder; never-published drafts deleted 48 hours after upload; delete with the edit link removes everything at once; content stops being served within 60 s; reports go with their workout, at the latest 30 days after filing. The app makes no backup copies | UP-7, AC-4, SH-10, INF-2, decision log 3 Nov 2026 |
| PT-12a | operator | Backups | Whether the server or provider keeps backups or snapshots (the operator's: none, DP-13) | F-31 DP-13 |
| PT-13 | app | Copies outside our control | Copies viewers already saved and previews already made stay with them | SH-10 |
| PT-14 | app | In your browser | Units, x axis, map/content split (wide and short landscape separately) and theme kept in browser storage, no cookie, never sent, until cleared | DS-1, AP-5, AP-17, DS-4, INF-1 (OQ-105) |
| PT-15 | app | Your rights | Download and delete with the edit link (export and erasure); without it the operator cannot verify ownership, but anyone can report a workout | NFR Privacy, INF-2, INF-3 |
| PT-15a | operator | Legal basis and complaints | Legal basis (the user's own file: Art. 6(1)(b) for workouts and settings, Art. 6(1)(f) for reports, rate limiting, logs and map tiles, OQ-106 a); the right to complain to a supervisory authority (named or general) | NFR Privacy, OQ-106 a, d |
| PT-16 | app | Source and licences | AGPL-3.0 with a link to its source and the running version (AB-5), then the generated list | Decision log 2 Nov 2026, INF-1 |
| PT-17 | app | Upgrades | Exactly: "Workouts are not archived: after an app update, a damaged file may show less than before or be removed." | Decision log 21 Oct 2026, AC 2 |
