- **Version:** 0.1
- **Status:** accepted (22 Nov 2026). Critical lane (stored owner data, hidden parts, trim): QA at effort high for AL-2 to AL-7. Product decisions OQ-301 to OQ-305 taken (feature file); no open questions
- **Feature:** [`features/F-65-owner-added-laps.md`](../features/F-65-owner-added-laps.md)
- **Requirements:** AP-8, PIN-1; AP-7, AP-12, AP-13, AP-19, AP-23, UP-4, UP-6, UP-7, AC-4, AC-5, SH-4, SH-10, DS-6, INF-1; NFR Performance, NFR Reliability; invariants I-3, I-4, I-5

**Vocabulary.** The feature file's "lap marker" or "marker" is the **added lap boundary** here and in code and API. "Lap marker" keeps its TD meaning: the map's marker at a lap's first sample.

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| AL-1 | **Storage: one nullable column `added_lap_boundaries`** on `workouts`, schema v11 (ADR-019, one-way door), `TEXT` with a `json_valid` check like `pins`. A JSON array of Unix seconds of resolved samples, in ascending order with no duplicates. An empty set is stored as `NULL`. No coordinates, indices, IDs or timestamps. Existing rows stay `NULL`, so no data migration is needed. Deleted with the row (AC-4, `secure_delete`), never logged (I-5) | Same as PN-1: one set per Save, one read-modify-write under O-7. Instants survive `regenerate` (ADR-057 item 2) |
| AL-2 | **Owner API.** The F-12 settings object gets the field `added_lap_boundaries`: an array of RFC 3339 UTC whole-second strings (same form as the trim), ascending in `GET`. A `PATCH` replaces the whole set, `[]` clears it, `null` gets `400`. Each instant resolves to the nearest sample of the normalised workout, ties to the earlier (PN-3), then the pool snap (AL-4) applies. `400 invalid_settings`, all or nothing, row unchanged, for: more than 100 entries; an instant outside the recording; two entries on the same resolved sample; a resolved sample on a boundary (AL-3); a new entry not strictly inside the resulting trim window. **There is no position check**: entries in a hidden start or end, on a dropout or on a workout without a visible route are accepted. One sentence per case, under the existing error code (the F-54 list is unchanged). The O-12 body cap grows by the field (about 3 KB) | AC 5, 6: the server is the judge and the edit page mirrors every rule |
| AL-3 | **Merge rule: one pure function in `workout`**, beside `Trim`. **Laps that can be split:** device laps over their F-03 §5.4 sample ranges, plus **implicit laps**: every run of samples that no device lap covers, widened to the touching device laps' boundary samples. A workout without device laps is therefore one implicit lap over the whole recording. **Boundaries:** the first and last sample of every device and implicit lap, the trim window's first and last sample, and the other added boundaries. An added boundary on any other sample splits the lap that holds it. Where device laps overlap, the later-starting lap is split. **Each part** copies the lap (sport, stroke), takes the split sample as its shared start and end sample (§5.4), and gets cleared totals that `completeTotals` refills: range values, plus the transition rule by start, the same path a trim-cut lap takes (`src/server/internal/workout/trim.go:108`, `laps.go:35`). **Triggers:** every part that ends at an added boundary gets `added`. The last part keeps the original lap's trigger; for an implicit lap that is `""`, an empty cell. An implicit lap without a split is not a lap. Unsplit device laps stay byte-equal. Every part has at least two samples by construction, so L-1 never empties one. **A stored instant that is no longer valid** (a parser change, then `regenerate`) is skipped by the build, never an error. It stays in the row until the owner's next Save, because the edit page mirrors the skip and does not send it | One rule covers "no device laps", truncated tails and laps ending in a gap (Reliability constraint). A lap belongs to its first sample's leg by MS-3 unchanged (F-64 "Open for F-65"). One definition serves the `PATCH` check, the trim removal and the build |
| AL-4 | **Pool snap.** A resolved sample inside a pool-swim session that has lengths moves to the nearest last sample of that session's lengths, rest lengths included, using the data file's length ranges. Nearest is by time, ties to the earlier. AL-2 and AL-3 then check the snapped sample, and the snapped instant is stored. A session without lengths (truncated, OQ-185) does not snap. Both parts keep the device lap's stroke through AL-3's copy | AC 11. Snapping by indices both sides have keeps the browser mirror exact. A snap onto a device lap end gives the boundary refusal, which is correct |
| AL-5 | **`PATCH` order, under O-7** (extends PN-5). First settings (radii, trim), then pins, then added boundaries against the **resulting** trim. Stored entries that are not strictly inside the new window are deleted in the same write, sent or not, and are never restored. A radius change never touches them. The parse is shared with PN-5's and runs only when the field is sent, or when the trim changes on a row with entries (TR-10's deadline covers it). Reached through the existing `Trimmer` port, as `CheckPins` is (`src/server/internal/lifecycle/lifecycle.go:368`) | "Deleted on Save, as pins" (OQ-237); hidden parts allowed |
| AL-6 | **Public build and data file.** The order is parse → AL-3 → trim (TR-2) → `publicTransform` (`src/server/internal/publish/publish.go:159`). The merged laps **are** the data file's `laps`. So the server-rendered table (also without JavaScript), the opening view (AP-8), map lap markers, row taps, the F-51 chart and the F-64 leg blocks all take them with no change. **Format version 7** (ADR-060): the trigger set gains `added`, nothing else changes. `draft.bin` never holds `added`, because it is the full recording with device laps only. Splits, lengths, summary, range links, preview and GPX have no boundary input | One renderer per side keeps working. A separate file like pins would need a second laps renderer in Go and in the entry |
| AL-7 | **Rebuild and regenerate.** `added_lap_boundaries` goes **on** F-15 P-7's allow-list, so the rebuild is in place (ADR-060 item 3). An unchanged set causes no rebuild, because the edit page sends the set only when it differs, as for pins (PN-8). A `PATCH` that also changes the trim or raises a radius stays remove-first through those fields. `regenerate` gets no new step: it reads the column and never writes it (RG-4). The v7 bump rebuilds every workout on deploy, as every bump does | Lap rows are computed from public streams and from device lap values that are already public, so an old copy shows nothing the new one hides. No generic-page second for viewers |
| AL-8 | **Edit page display** (owner chunk `src/edit/`). The chunk mirrors AL-3 and AL-4 in TypeScript over `draft.bin`: it splits `meta.laps`, computes part values with `lib/range` (F-17 R-2, the rules Go's `rangeValues` copies), and gives the merged array to every existing consumer of `data.meta.laps` (laps view through `lib/page`, map lap markers, taps, chart, F-64 blocks). It re-renders on each change, never on a cursor flush. Boundaries use the **live** trim window. A value may differ from the published one in the last shown digit, because `draft.bin` is quantised; accepted. After Save, the response's set replaces the local one. **×** appears only on rows that end at an added boundary. It addresses the boundary by its instant, never by the lap number (F-64), and its accessible name includes the lap. Device rows have no ×. A boundary in the live-trimmed part has its row dimmed with F-56's "Removed on Save" and is left out of the sent set. Without device laps, the first boundary brings the view switch and the laps view (AP-8 rule), and removing the last one takes them away | Changes show at once (AC 8). One merged array instead of a second rendering path |
| AL-9 | **"+" control** (owner chunk, no extra lazy chunk: the owner chunk is already lazy, ADR-011). It sits where "Add pin" sits (PN-12): a map control at the bottom left in the two-column layout, not in fullscreen; in the tools row in one column; below the no-location hint without a visible route, where it offers only "Add lap" (OQ-305). It is disabled without a cursor or range. **It is a disclosure, not an ARIA `menu`**: a button with `aria-expanded` and a translated accessible name, followed in the DOM by its item buttons, so Tab reaches them. A disabled item is `aria-disabled` and its one-line reason is linked by `aria-describedby`, so keyboard and screen-reader users reach the reason. The list opens as an overlay that never changes layout (PN-12's rule); as a map control it opens to the left inside the map container. It closes on a choice, Esc (focus returns to "+"), a click or tap outside, "+" again, or focus leaving the group. Item states are computed on open and on cursor or selection changes while open; nothing runs per flush while closed. **Add pin** is unchanged from F-56. **Add lap** uses the cursor's instant (TR-4 arithmetic), or both range ends, skipping an end that already sits on a boundary. It is disabled with one reason when every end is on a boundary, when the cursor or a range end lies in the live-trimmed part, or when the set would exceed 100. Hidden parts are allowed. The pool snap is mirrored, so the reason applies to the snapped sample | Tab between items (feature Scope) is the disclosure pattern, whereas `menu` expects arrow keys. `aria-disabled` keeps the reason reachable. Scrub gate (AC 13). (23 Nov 2026) The same two items also open from a mouse right-click on the map (`src/edit/mapmenu.ts`; desktop mouse only; acts on the existing cursor or range like the buttons, disabled without; a `menu` of `menuitem`s with arrow keys, since there it is a real menu) |
| AL-10 | **Texts** (F-54): the trigger word "Added" in the code-word tables of Go `internal/page` and `lib/page` (entry and its language file); "+"'s accessible name, "Add lap", the reasons and ×'s name in the edit text group; About (INF-1): added lap boundaries among the stored data | DS-6 |

## What cannot leak

- **Positions:** AL-3 changes only laps, and runs before trim and hiding. With and without boundaries, every stream of the public data file is byte-equal, and the lap metadata has no coordinate field (F-03 §5.3). A boundary in a hidden part gives a lap whose time and distance values the range panel already shows, and no map marker, because its first sample has no position.
- **Row:** integers only, owner API only, gone with the row.

## Cost

| What | Limit |
| --- | --- |
| Activity entry | The code `added` and its word in `lib/page`: estimate +20 bytes gzip, **ceiling 50** from the ADR-011 reserve; the engineer records the figure in item 4. Viewers load no new chunk or file |
| Owner chunk | Mirror, "+" disclosure, ×, reasons: estimate 2,000 bytes gzip within F-19's chunk ceiling; measured +2,857 → 16,745 at QA r1, ceiling raised to 20,000 (F-19 v0.4, QA-65-r1-1) |
| Data file | About 150 bytes of metadata per added lap before compression; at 100 boundaries a few KB brotli, within the F-03 budget |
| Server | One shared parse per relevant `PATCH` (AL-5); the merge is O(N) per build |

## Verification (QA high for AL-2 to AL-7)

Synthetic files only (ADR-004).

| What | Check |
| --- | --- |
| AL-3, AL-4 | Generated workouts: no device laps, two-sample laps, a lap ending in a gap, a truncated tail (implicit lap), overlapping laps, multisport with a boundary in T1 and at a leg start, pool with and without lengths. Unsplit laps are byte-equal; each part's values equal the range values over its range; triggers and order as AL-3; applying the rule to its own resolved instants is idempotent |
| AL-2, AL-5 (direct API) | Every refusal case gets `400` and leaves the row unchanged; 100 entries are accepted and 101 refused. Entries in hidden parts are accepted at radii 0, 50, 300 and 2,000 per end. A trim change deletes exactly the entries that are not strictly inside, sent or not, and undoing it restores none. A radius change keeps all |
| Privacy | Over the corpus and generated tracks, at those radii, with and without a trim, with boundaries in hidden parts, on the first visible sample and on dropouts: the public data file's streams are byte-equal to the same build without boundaries, only `laps` differs, and its keys are exactly §5.3's. No map lap marker is drawn in a hidden part |
| Go and browser agree | Committed samples (single sport with device laps, without device laps, triathlon with a boundary in T1, pool): the TypeScript merge over the `draft.bin`-style fixture gives the same lap ranges, order and triggers as the Go-built v7 file. Values match within quantisation. Both builders' view models match the samples (ADR-026) |
| Regenerate, AC 10 | Stored instants survive `regenerate` byte-identical; v7 golden fixtures. After delete and expiry no row remains; F-21's database byte scan also searches the column's text |
| Edit page (jsdom) | "+" open and close paths and keys (AL-9) in both layouts and without a route; reasons; × only on added rows; the first and the last boundary toggle the laps view |
| Budgets | Entry ceiling; a viewer page makes no new request; 100 boundaries on `ride-12h` pass ADR-016's scrub gate |
| Mutants | Each must fail a check: a boundary in a hidden part refused; the device-boundary or window-end check skipped; trim deletion skipped, or done on a radius change; snap skipped; the last part gets `added`; a part keeps the device totals; any stream changed by the step; cap off by one; `regenerate` writes the column; a rebuild on an unchanged set |
