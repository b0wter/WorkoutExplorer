# ADR-034 history

- **31 Oct 2026, first version** (file `ADR-034-compose-on-host-network-with-mounted-binaries.md`): both services on `network_mode: host`, so ADR-021 item 6's loopback trust held with no Go change, and Caddy saw real IPv6 clients with no Docker IPv6 setup. Caddy bound 80/443 non-root through the host sysctl `net.ipv4.ip_unprivileged_port_start=80`, and its admin API was on a Unix socket, because a TCP port would have been open to every host process.
- **1 Nov 2026, revision:** the user ruled out host networking. Replaced by two bridge networks, a trusted proxy address (ADR-021 rev. 5) and the Docker daemon settings for source addresses (F-31 v0.2 DP-1 to DP-1b).
- **1 Nov 2026, rev. 2:** the user chose "behind the operator's reverse proxy" only. Dropped: `edge` with IPv6 publishing 80 and 443; decision 3 "source addresses kept: the userland proxy is off and ip6tables is on in the Docker daemon, so published ports are DNATed for both address families"; the consequence that the rate limit held only while those daemon settings held; Caddy's state in `/srv/caddy`; "would choose differently if the VPS's Docker cannot DNAT IPv6 with the source kept". Added the two-hop trust chain (Caddy trusts the operator's proxy, Go trusts Caddy).
- **1 Nov 2026, rev. 3:** the user asked for a Dockerfile for self-hosters, nothing published. Item 4 was "No image of ours. Both services run one third-party base image …; the Go binary (CI artefact) and Caddy … are bind-mounted read-only". Context item 2 was "An image per release needs a build and a registry, and puts the Caddy version in a second place next to `deploy/caddy.env`." Reversibility was "Only the Compose file, the Caddyfile and the runbook change."
