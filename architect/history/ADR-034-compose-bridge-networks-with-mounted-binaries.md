# ADR-034 history

- **31 Oct 2026, first version** (file `ADR-034-compose-on-host-network-with-mounted-binaries.md`): both services on `network_mode: host`, so ADR-021 item 6's loopback trust held with no Go change, and Caddy saw real IPv6 clients with no Docker IPv6 setup. Caddy bound 80/443 non-root through the host sysctl `net.ipv4.ip_unprivileged_port_start=80`, and its admin API was on a Unix socket, because a TCP port would have been open to every host process.
- **1 Nov 2026, revision:** the user ruled out host networking. Replaced by two bridge networks, a trusted proxy address (ADR-021 rev. 5) and the Docker daemon settings for source addresses (F-31 v0.2 DP-1 to DP-1b).
- **1 Nov 2026, rev. 2:** the user chose "behind the operator's reverse proxy" only. Dropped: `edge` with IPv6 publishing 80 and 443; decision 3 "source addresses kept: the userland proxy is off and ip6tables is on in the Docker daemon, so published ports are DNATed for both address families"; the consequence that the rate limit held only while those daemon settings held; Caddy's state in `/srv/caddy`; "would choose differently if the VPS's Docker cannot DNAT IPv6 with the source kept". Added the two-hop trust chain (Caddy trusts the operator's proxy, Go trusts Caddy).
- **1 Nov 2026, rev. 3:** the user asked for a Dockerfile for self-hosters, nothing published. Item 4 was "No image of ours. Both services run one third-party base image …; the Go binary (CI artefact) and Caddy … are bind-mounted read-only". Context item 2 was "An image per release needs a build and a registry, and puts the Caddy version in a second place next to `deploy/caddy.env`." Reversibility was "Only the Compose file, the Caddyfile and the runbook change."
- **15 Nov 2026, rev. 5 (F-59, ADR-052):** the user reversed "nothing published". Title was "Docker Compose on two bridge networks, with bind-mounted binaries on one pinned base image". Context item 2 was "An image per release needs a build on the VPS or a way to ship it, puts the Caddy version in a second place next to `deploy/caddy.env`, and replaces `web/` whole, while published pages still name older assets. Self-hosters, who use no release, still need a way to build what runs (user decision: a Dockerfile, nothing published)." Item 4 was "**The operator runs no image of ours; self-hosters build one, nobody publishes one.** On the operator's server both services run one third-party base image (distroless static, Debian), pinned by digest; the Go binary and `web/` (GitHub Release, ADR-035) and Caddy (`deploy/fetch-caddy.sh`, `caddy.env` checksums) are bind-mounted read-only. Self-hosters build one local image from `deploy/Dockerfile` on the same base digest, holding the same files at the same paths, and select it with the override `deploy/compose.build.yaml`; `compose.yaml` stays the one service definition for both. No registry, no CI push; `make ci` builds the image (F-31 DP-16, DP-17)." Item 5 was "Bind mounts of host directories at the same path inside, never single files, never created by Compose. Caddy mounts only `public/` from the data directory; its own state is `tmpfs`. (Note 9 Nov 2026, F-38: also `site/`, read-only, the page shells, ADR-043.)" Item 6 ended "Both run with a read-only root, no capabilities and `no-new-privileges`." Consequences included "A deploy is a file copy and a container restart. There are no image tags to roll back to", "One more pull from a third-party registry, the base image, pinned by digest. A digest bump is a reviewed change, in `compose.yaml` and the Dockerfile together" and "Two ways to get the files into the containers; `make ci` builds both. A self-hoster's upgrade recreates Caddy and replaces `web/` whole: a brief page outage, and older published pages lose their assets until `regenerate` (F-30)." Reversibility: "Moving the operator to the image later is a deploy script change plus a way to keep old assets." Would choose differently: "Keeping two paths working costs more than it saves …, or bundles become content-addressed in a data-directory store that outlives the image: then the operator moves to the self-built image too."
