# ADR-021 Upload request handling: history

History of [architect/ADR-021-upload-request-handling-and-rate-limit.md](../ADR-021-upload-request-handling-and-rate-limit.md), moved out of the live ADR on 22 Oct 2026 (restructuring, no decision changed).

## Header date line as written (revision 4)

- **Date:** 16 Oct 2026 (revision 1, 16 Oct 2026, the user's answers to F-09 OQ-40 to OQ-45: messages fixed by UP-10; refused uploads count, IPv6 per /64, 20,000,000 bytes confirmed; the in-flight cap becomes a server setting from the environment variable `WORKOUT_EXPLORER_MAX_CONCURRENT_UPLOADS`, default 4 (item 4)). Revision 2, 16 Oct 2026, F-09 round 1: memory per upload follows ADR-017 rev. 3 item 4 (item 4, Consequences); a full key table is swept at most once a minute (item 8). Revision 3, 16 Oct 2026, F-09 v1.4 (QA-09-r1-4): the per-key log is a fixed array of whole seconds, so the table at its cap is bounded at 40 MB (L) and counted in the memory model; cap, limit, window and fail-closed behaviour unchanged (item 8, Consequences). Revision 4, 22 Oct 2026, F-09 v1.11 (ADR-017 rev. 7, the user's decision): the write deadline is the read deadline plus 6 × the parser's configured time limit, which is 180 s at the default (item 5); the binary reads a second environment variable (Consequences)

## Superseded text

- **Rev. 6 (1 Nov 2026, F-31 v0.3: behind the operator's proxy, two limit settings):** item 7 opened "**Rate limit: 60 per rolling hour per client address** (`RateLimit`, `RateWindow`). Sliding log: per key the times of the allowed attempts in the last hour, at most 60." Item 8's bound read "the 240-byte array ... **Bound: at most 400 bytes per key at `limit` 60, including the map**, so **L ≤ 40 MB** for 100,000 keys." Consequences read "F-31 sizes `MemoryMax`", "The rate table adds at most L = 40 MB", and "The binary reads two environment variables, `WORKOUT_EXPLORER_MAX_CONCURRENT_UPLOADS` and (rev. 4) `WORKOUT_EXPLORER_PARSE_TIMEOUT` ... The TD's configuration rule names them as the only ones".

- **Item 6, first sentences (before rev. 5, 1 Nov 2026, F-31 v0.2: no host network):** 6. **Client address:** if the direct peer is a loopback address and `X-Forwarded-For` is present, the client is its **last** comma-separated entry (the one Caddy appended); otherwise the peer address. ... A peer that is not loopback can never choose its address through the header. Context said: "`RemoteAddr` is always the loopback address".
- **Item 5, first sentence (before rev. 4):** 5. **Deadlines per request** with `http.ResponseController` (F-01 left the server-wide timeouts unset for this): read deadline 120 s and write deadline 180 s from the start of the handler.
- **Item 8, rev. 3 paragraph, opening:** **(rev. 3) Per-key representation and memory bound.** At the cap, a log of `[]time.Time` (24 bytes per entry, grown by `append` and resliced forward) held about 1.85 KB per key, about 185 MB in total (QA-09-r1-4).
