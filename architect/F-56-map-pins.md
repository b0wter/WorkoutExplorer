## Decisions

| # | Decision | Why |
| --- | --- | --- |
| PN-1 | **Storage: one nullable column `pins` on `workouts`**, schema v10 (ADR-057 item 1; ADR-019, one-way door). Whole set, canonical order, `NULL` = none. No table, no coordinates, no IDs or timestamps. Goes with the row (I-4, AC-4, `secure_delete`); never logged (I-5) | Saved as one set with Save (OQ-274), so one field, one `BEGIN IMMEDIATE` read-modify-write (O-3), and P-7's default with no new code |
| PN-2 | **Owner API** (F-12 settings object, row added there). `pins`: array in `GET` and `PATCH`; a `PATCH` with `pins` replaces the whole set, `[]` clears, `null` gets `400`. Per pin, exactly: `type` (one of `point_of_interest`, `danger`, `difficult_section`, `water_food`, `photo_spot`, `note`), `title` (UP-4 title rule: trimmed, at most 60 code points, no control character; `""` allowed, OQ-277), `note` (description rule: at most 500 code points, line feed the only control character allowed, OQ-238), `start_at` (RFC 3339 UTC whole seconds, as the trim), `end_at` (same, or `null` for a point; a section needs `end_at` > `start_at`). At most 50 pins, dimmed ones included. Unknown keys, wrong types, an instant outside the recording's first and last sample: `400 invalid_settings`, all or nothing. Texts are stored as accepted and escaped on output (O-4). O-12's body cap grows to the largest valid body with JSON escapes (about 350 KB; the engineer computes it) | AC 33, 41. One shape for the edit page and the direct-API test (AC 35). The server is the judge; the edit page mirrors every rule so the sentences never show in normal use (F-12) |
| PN-3 | **Anchor: sample instants** (ADR-057 item 2). The browser sends `start_time` + offset of the chosen `draft.bin` sample (TR-4's arithmetic); the server resolves each instant to the nearest sample, ties to the earlier, and stores that sample's instant | Survives `regenerate` and parser changes the way the trim does; needs no coordinate in the row |
| PN-4 | **Two pure predicates, one place** (ADR-057 item 3), in `publish` beside `publicTransform` (`internal/publish/publish.go:159`). **Kept:** every sample of the pin (a point's one, a section's two ends) lies in the trim window. **Public:** kept, and each such sample has a position in the output of trim then hiding. A section touching a hidden or trimmed part is **never clipped**: a clipped section would keep a title and note that may describe the cut part, and would silently change what the owner marked. Reached from `lifecycle` through the existing `Trimmer` port (`internal/lifecycle/lifecycle.go:368`) | One definition for the `PATCH` check, the trim removal and the build, at each end's own radius by construction (F-55 hand-off: never from `hiding_steps`). "Public" also excludes a dropout sample, which the map cannot draw |
| PN-5 | **`PATCH` order, under O-7.** Settings first (radii, trim as TR-4), then pins against the **resulting** settings. (a) **Not kept** (trimmed away): deleted from the row in the same write, whether sent or not, when its anchor (`start_at`, `end_at`) is stored; a new anchor gets `400` "This pin is in a hidden or trimmed part of the route." Not restored by a later trim change. (b) **Kept but not public** (hiding radius, dropout): stored and accepted only when a stored pin has the same anchor, so the owner can still edit its type and texts or delete it; a new or moved anchor gets the same `400` (AC 35). A workout without a visible route refuses every new anchor the same way (OQ-275). Raising or lowering a radius never deletes a pin. The stored set therefore always satisfies "kept" and may hold non-public pins. Parse once, only when `pins` is sent or a radius or the trim changes on a row with pins; TR-10's three-parse deadline covers it | User decision of 20 Nov 2026. The anchor is the only identity a pin has (no IDs, PN-1); "unchanged anchor" is exactly "not created or moved here". The refusal is for consistency, not privacy: PN-6 publishes only public pins whatever the row holds |
| PN-6 | **Public artefact `pins.{hash}.json`** (ADR-057 item 4; shape below), an artefact of the whole build (P-4), written only when at least one pin is public; P-5's hash rule; no `.br` (small; Caddy compresses JSON on the fly, F-22 H-7). Sorted by `from`, then point before section, then `to`, then stored order. Indices refer to the data file of the same build, so `index.html`, as the commit point, keeps them consistent. Caddy unchanged: the hashed name is immutable (F-22 H-6) | Pins carry no position of their own: what the map shows is the data file's position at that index, already public (F-16 H-1). A pin edit writes one small file and the page, never the streams |
| PN-7 | **The "has pins" signal is the view model**, not the data file: group `Pins` with `URL` (`/w/{public_id}/pins.{hash}.json`, or `""`) and `Count` (public pins as a decimal string, or `""`; a dimmed pin never counts, and nothing else in the view model, the page or the pins file depends on one). Go builder (`internal/page/page.go:19`) and `lib/page` reproduce it; the edit page's view model leaves both `""`; one new sample with pins (F-13 D-3). Under `{{if .Pins.URL}}` the template prints the list slot carrying the URL in a data attribute, which is also ADR-028 item 5's link for the sweep. The slot reserves the list's height from `Count` (rows are one line; the note opens only on selection) and takes space only with JavaScript; how, without inline style, is the engineer's choice | Answers the requirements engineer's flag. A data file flag would need a format bump and rewrite the streams on every pin edit. The reserve keeps F-13 D-10's no-shift rule although the list sits above the charts in one column |
| PN-8 | **Hides more, recall, regenerate, preview.** `pins` stays off P-7's allow-list, with one narrowing (ADR-057 item 5): a `pins` change whose **public projection** (the PN-6 file content, or none) is unchanged triggers no rebuild, so editing or deleting a dimmed pin leaves every public file and the page's timing untouched. Any other pin change is remove-first, so a removed or moved pin's old file goes before anything new is written, and the sweep (P-8) bounds every failure path (SH-10, AC 40). Lowering a radius rebuilds in place as today (HR-5); a dimmed pin it uncovers becomes public by the same build. `regenerate`: no new step; the build reads `pins`, RG-4 never writes it (settings column). A later rule change that hides more drops the pin in the in-place rebuild, as F-16 H-9. **Preview:** pins are no input of the preview or the card (OQ-240, by construction) | No new path; the existing allow-list default fails toward less public content |
| PN-9 | **Viewing page loading** (ADR-011 item 2, F-42 MS-9 pattern). Static: read the slot's URL, one `import()` of the lazy chunk `src/pins/` and one `fetch` of the URL, started after the charts' first paint. No URL: nothing loads (AC 45). On failure: no pins, the slot is released, one console warning. Pin code, icons and CSS live only in the chunk; `lib/pins` (pure: file check, sort, type names) beside it, not in the entry | AC 45; LCP unchanged (nothing on the first-paint path) |
| PN-10 | **Views and linking.** One framework-free selection store (pin index or `null`) shared by map, charts and list; it never ticks on cursor moves. **Point:** selecting sets the cursor to its sample. **Section:** selecting selects its range (AP-7) through the lap-row path, cursor at its start; selecting again clears; a range changed elsewhere deselects it (F-18 rows' rule). **Map:** DOM markers as buttons with an accessible name, built in the chunk and added through one seam of the lazy map module (ADR-013; no pin code in the map chunk); a section as its own line source from `lib/route`'s range geometry, above the route and colouring, below the range highlight and cursor; a tap that starts on a marker selects, ADR-015 otherwise unchanged. **Charts:** markers on the x axis and section shading through MS-7's decoration seam, placed on layout only, never on a cursor flush. **List:** in PN-7's slot; one column under the map, two columns under the charts above the range panel, by CSS only (ADR-026 rev. 1). **Legend:** inside the map container like the colour legend, so it stays in fullscreen; only the workout's types; memory only (OQ-239); a hidden type leaves every view and drops its selection. **Fullscreen:** a marker tap opens one card over the map (AP-15) | 60 fps with 50 pins (AC 45): nothing pin-related runs per cursor frame. One store keeps "selected in all views" true without components talking to each other (ADR-008 style) |
| PN-11 | **Text is text** (AC 41, XSS). Title, note and type names reach the DOM only as text: Svelte text interpolation, `textContent`, `setAttribute`. Never `{@html}`, `innerHTML`, `insertAdjacentHTML` or MapLibre's `setHTML`/HTML popups; icons are fixed SVG from the chunk, never mixed with owner text. The file is read with `JSON.parse` (`response.json()`) and checked by `lib/pins` (types, indices inside the data file, sizes); an invalid file shows no pins. An empty title shows the type's name, chosen in the browser (F-54 translates it). Note line breaks by CSS (`pre-line`). Owner text never enters `index.html` | Go's `html/template` is not in this path, so the browser side carries the whole guarantee; a source scan for the forbidden calls in `src/pins/` and the owner pin editor is checkable |
| PN-12 | **Edit page** (owner chunk; display through the same `src/pins/` code over `draft.bin`, instants mapped to indices by the offsets). "Add pin" places a pin at the selected point (the cursor set by a tap on the map or a chart; ADR-015 on the map) or, with a range selected (AP-7), a section over that range (no "Section" option); no waiting mode (21 Nov 2026). It is disabled with a visible reason line in the tools row (no cursor; "This point is hidden or trimmed."; a pin already there, so selecting a pin never allows a twin) when there is no cursor, or the point (or either range end) is in the shaded part (live sliders and trim, F-55 HR-8, TR-9: the one-line refusal rule, never a pin there); a sample without a position moves to the nearest positioned sample, ties earlier (OQ-234); then the form opens. A section pin being edited: a new range moves its ends (OQ-273), each snapped the same way; Move puts a point pin at the cursor. In the two-column layout (the page's own switch, `TWO_COLUMN_QUERY`) "Add pin" and its reason line are a map control at the map slot's bottom left (not in fullscreen: the pseudo-fullscreen box shows only the map's container); in one column they stay in the tools row. The button never changes the layout (a hint line appearing above the map made the phone's map resize on the old tap mode). Changes show at once; Save (E-6) sends `pins` only when the set differs, as the whole set, dimmed pins included. **Dimmed pins** (saved or live sliders shade them by a radius, PN-5 b): drawn dimmed in every edit view and listed with a short reason ("Hidden by the start radius", "… end radius"; a section touching both names both), editable and deletable, not movable into the shaded part. **Trimmed-away pins** (live trim shades them): also drawn dimmed, with "Removed on Save"; the browser leaves them out of a sent set. After Save, the browser counts the pins it held before (by anchor) that the response lacks and shows one line with that number (AC 36). Distances are from the full recording (OQ-178). No "Add pin" when the same mirror finds no visible route (OQ-275); existing pins then stay listed, dimmed | The browser mirrors the shading lookup it already has (`hiding_steps`, trim window); the server alone decides (F-16 hand-off). An unsaved trim with a radius above 0 can still meet PN-5's `400` for a new pin (HR-8 already says "Save to update"); accepted |
| PN-13 | **Texts.** How to use (AP-22): one line on pins, worded for workouts that have them, in the lazy dialog. About (INF-1): pins (type, title, note, place on the route) among the stored data, in `src/web/about.html`. Each text in one place for F-54 | Feature assumptions |

### PN-6 file shape

```json
[{"type":"danger","title":"Loose gravel","note":"","from":1834},
 {"type":"difficult_section","title":"","note":"Busy road, no shoulder","from":2210,"to":2795}]
```

Top level an array; `to` only for sections (`to` > `from`). No coordinate, instant, ID, version or any other key. Go's `encoding/json`, deterministic.

## What cannot leak

- **Hidden or trimmed places:** a pin index is emitted only where the public data file has a position (PN-4), so `pins.{hash}.json` adds no place the map does not already show; no other public file has pin input (PN-6 to PN-8).
- **Radius:** the rule reads the transform's output, never the radii; `Count` counts public pins only.
- **Dimmed pins:** stored but never in any public input: not in the pins file, its name or hash, `Count`, the page, the preview or the card; a change to them alone causes no rebuild (PN-8), so not even a page-swap moment reveals them. Only the owner API and edit page show them.
- **Old places:** remove-first on every change, the sweep, and SH-10's existing recall notice for copies.

## Verification (QA high for PN-3 to PN-6)

Synthetic files only (ADR-004).

| What | Check |
| --- | --- |
| AC 35, 36 (PN-4, PN-5) | Over generated tracks and the corpus, radii 0, 50, 300, 2,000 per end, with and without a trim: a point or section sent to the API directly inside a hidden or trimmed part, on a dropout sample, or on a workout without a visible route gets `400` and the row is unchanged; a section with one end at the first visible fix is accepted. Raising a radius: every pin stays in the row, exactly the no-longer-public ones leave the pins file and `Count`, and their indices and texts appear in no file under `public/{public_id}/`; lowering it again republishes them. Editing the text of a dimmed pin (same anchor) is accepted and changes no public file; moving it to another hidden sample gets `400`. Trimming: exactly the not-kept pins leave the row, also when sent; undoing the trim does not bring them back |
| PN-6 | Every index in the pins file has a position in the referenced data file; the file holds only the keys of the shape; same pins give the same name; a pin change removes the old file |
| PN-3, regenerate | Stored instants survive `regenerate` byte-identical; a resolved instant of a moved sample still passes PN-4 |
| AC 40, 44 | P-7 fault injection with a pin change (remove-first). After delete and expiry: no row, no `pins` file; F-21's database byte scan also searches a pin title and note |
| AC 41 | Limits and text rules in Go and in the browser; a title and note of `<img src=x onerror=…>` and `</script>` render as text in list, card, marker name |
| AC 45 | No-pins page: no chunk or file request; entry ceiling; 50 pins on `ride-12h` pass ADR-016's scrub gate |
| Mutants | Each must fail a check: the check on `draft.bin` positions instead of the public output; one section end checked; a section clipped; `hiding_steps` used by the server; a removal skipped when only the trim changes; a pin deleted on a radius raise; a dimmed pin in the pins file or in `Count`; a new anchor in a hidden part accepted; a rebuild on a dimmed-only change; `pins` fully on P-7's allow-list; a coordinate in the pins file; owner text through an HTML API |
