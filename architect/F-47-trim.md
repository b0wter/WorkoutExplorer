## Decisions

| # | Decision | Why |
| --- | --- | --- |
| TR-1 | **One cut, in `workout`, on the normalised workout** (ADR-047 item 1): pure `workout.Trim(w, window)`, after `Normalise`, never on FIT records. `Normalise` keeps its sport timeline on `Workout` as an unexported, never-encoded field (as `inserted`, F-16 H-3), so the trim can re-run the sport and leg rules. Identity when the window is the whole workout | Trim points are sample positions of `draft.bin`, which is the normalised workout. Cutting records would re-run gap filling, resampling and R-1 on a different input and move every boundary |
| TR-2 | **Public transform = trim, then hiding** (OQ-173): one pure composition in `workout`, used by `publish`'s front half (`publicTransform`, `internal/publish/publish.go:157`) and by the owner view (TR-8). Nothing about either cut is stored, logged or cached. Every build computes it again from `original.fit` (ADR-028 item 2) | One definition for the public files and for everything the owner is shown about them |
| TR-3 | **Storage: two nullable settings columns, `trim_start_at`, `trim_end_at`**, Unix seconds (instants, as `created_at`), in one forward-only migration (ADR-019). `CHECK` start < end when both are set. `NULL` = that end is not trimmed. The server stores the instant of the resolved sample (TR-4). A side that resolves to the first or last sample is stored as `NULL`. Settings object: the same names, RFC 3339 UTC whole seconds or `null`; `null` is accepted for these two (the one exception to F-12's "a `null` gets `400`"). The TD's reserved `trim_start_s`, `trim_end_s` are replaced | Instants, not offsets or sample indices (ADR-047 item 2). Snapping makes equal trims equal rows, so a repeated trim writes the same names and moving both handles back yields the untrimmed row (AC 43) |
| TR-4 | **Window rule** (pure, in `workout`, used by `Trim` and the `PATCH` check): `a` = first sample at or after `trim_start_at`, `b` = last sample at or before `trim_end_at` (sample instant = `start_time` + offset). It rounds inward: never a sample from the trimmed part. Valid when `offset[b] − offset[a] ≥ 60`. Otherwise `PATCH` gets `400 invalid_settings`, "At least 1 minute of the workout must remain.". The check runs in `PATCH` on a fresh parse under the O-7 lock. A window that leaves fewer than two samples at build time (only after a parser change) is a build error: fail closed, and `regenerate` keeps the old files (RG-3) | AC 41. The server is the single judge. The browser applies the same formula to `draft.bin`'s offsets, which are the normalised offsets exactly, so the slider never sends a refused trim |
| TR-5 | **What `Trim` produces.** No metadata value may come from samples outside `[a, b]`; each is either taken from the window or dropped. **Time:** offsets rebased to `offset[a]` (the cursor at the first remaining sample shows 0:00:00), `start_time` += `offset[a]`; timer events clipped. **Streams:** sliced. Distance, cumulative moving time and gain are rebased by their (carried, F-17 R-2) value at `a`, so `M[0] = 0` (ADR-029). A stream with no valid value in the window is absent (AP-4); no positions gives the no-location hint (AP-3, not F-16's fully hidden). **Sessions:** clipped to the window; those with nothing left are dropped (OQ-174); a cut session's device totals are cleared. **Laps:** those with no remaining duration are dropped. A cut lap's totals are cleared and refilled by `completeLaps` as for a range (F-18 L-1), trigger kept (LS-1). Laps wholly inside keep the device's values. Numbering follows the list. **Sport and summary:** re-run R-9, R-10 and R-11 on the cut samples, with every session's totals left out of the summary. Every value is then the server-computed one; calories, timer time and lengths are absent; the pool length and `pool_length_recorded_m` stay (OQ-179, final 12 Nov 2026, replaces "pool values dropped"). Descent is recomputed or dropped, the engineer's choice | UP-6 "as if it had been recorded that way", AC 33 to 37, 39. Distance, moving time and gain of the trimmed summary equal the range panel over the same samples of the full workout, the rule a cut lap already uses |
| TR-6 | **Hiding after trim.** `HideEnds` runs on the trimmed workout, so both circles centre on the first and last *remaining* positions. The `inserted` marks are sliced with the samples (H-3 holds) | SH-4, OQ-173, AC 38 |
| TR-7 | **Public side: no new path.** Every artefact (data file and `.br`, page, preview and card values, suggested title by ST-4, the phase 3 export) is built from the transform's output only (P-4). `HidesMore` (P-7) does not list the trim columns, so **every trim change is remove-first**, widening included. They must never join the allow-list: with hiding on, widening moves the circles and can hide positions that were public, and it can change the town. The preview basemap follows by key match (MC-3); the frontend runs MC-8(b) after a save that changed the trim. Range links are not touched (OQ-176) | SH-10 and AC 44 with no new code. Fails toward less public content |
| TR-8 | **Owner view, per read** (ADR-047 item 3). With a trim stored, `GET` and `PATCH` compute, under the O-7 lock from one parse of `original.fit`: read-only **`trimmed`** = `{"sport", "summary"}` exactly as the public metadata would have them; **`hide_ends_ranges`** = `HiddenRanges` of the trimmed workout shifted by `a` into `draft.bin` indices; and **`suggested_title`** from the trimmed metadata and its first position after hiding (when `hide_ends` is on). Without a trim: `trimmed` is `null` and everything works as today (ADR-030 ranges, ST-6), with no parse. A failure never fails the read (as ST-6): then `trimmed` is `null`, the ranges are `[]` and the suggestion is `""`. A trim `PATCH` uses the same parse for TR-4's check and for the response | The owner sees exactly what the public build would make, from the same code. Nothing new is stored, and the town is never stored (F-45 storage check) |
| TR-9 | **Edit page (frontend), owner chunk only.** One two-handle slider in `components/edit`, over `draft.bin`'s samples: handles snap to samples, show elapsed time from the recording start, and apply TR-4's 60 s rule. The slider sends instants (`start_time` + offset), or `null` at an end. **Shading** of the trimmed parts follows the handles live, unsaved too (like E-9): on the map through E-9's marks path (own source, below the hidden marks), in the charts through MS-7's decoration seam. Hidden marks, the summary and the title placeholder follow the **saved** trim (E-6, ST-7). **Summary strip:** `lib/page` takes `trimmed` as an input that replaces `sport` and `summary` for the strip only; it formats, never computes (ADR-026). When a trim is stored but `trimmed` is `null`, the strip shows no values, never the untrimmed totals. Everything else stays the full recording from `draft.bin`: time axis, header, laps, sections (OQ-178). No second draft file, no `draft.bin` change | OQ-169, OQ-170, AC 31, 32. The browser holds no trim or summary rule, only the display mirror of TR-4. A display that is off by a sample is acceptable, as for F-16: the public build alone decides |
| TR-10 | **Cost.** `Trim` works in place on the build's own parsed workout (re-slice and rebase, no second copy of the streams). The owner-view parse runs under the O-7 lock, which already admits one owner-side build at a time and takes no extra original while waiting. Parses still go through the parser's slots, so ADR-017's M(N) is unchanged. A trim `PATCH` on a published workout parses twice, one after the other (view, then build), so the peak does not change. The engineer may share the parse, and widens P-15's `PATCH` write deadline to cover both. **Regenerate:** no new step. The build reads the trim from the row; RG-4 never writes settings columns; RG-5's re-read and RG-6 are unchanged. Stop rule: the peak RSS of a trimmed build on the all-caps file must not exceed the untrimmed build's. Above it: stop and report | 2 GB VPS (F-31 DP-8, ADR-017 rev. 8). Trimmed workouts are rare, so a parse per owner read of one is cheap at this scale |
| TR-11 | **Lifetime and logs.** Both columns go with the row (I-4, AC-4; `secure_delete`, ADR-019 rev. 3). Trim instants, windows and owner-view values are never logged (as ADR-030 ranges, I-5). `original.fit`, `draft.bin` and the owner's download never change (UP-6, AC 45) | Store as little as possible |

**Bundle.** Viewing-page static share target **0 bytes**, ceiling 100 (the seams exist: E-9 marks prop, MS-7 decoration). The slider and the trim glue are in the owner chunk; above 100 bytes: stop and report. Data file, page size and LCP are unchanged (AC 48).

## Verification (critical lane: QA at effort high)

Synthetic files only (ADR-004). The engineer extends `corpusgen` as needed.

| What | Check |
| --- | --- |
| AC 33, 35, 42 | A run plus a drive whose samples carry marker values (positions, heart rates, speeds, timestamps, distance and gain increments that occur nowhere in the run), trimmed at the end, then at the start. No file under `public/{public_id}/` holds a marker: `.bin`, the decompressed `.br`, `index.html`, PNG bytes. Repeat with hiding on, then with a pool and an indoor file |
| Range equality (AC 34, 37) | Over every synthetic file and generated windows: the trimmed summary's distance, moving and elapsed time, gain, averages and maxima equal Go's range values over `[a, b]` of the untrimmed workout. A cut lap equals its remaining range. Calories, pool and lengths are absent |
| TR-4 | 59 / 60 s; a window inside a long pause (no samples); inward rounding at both ends; `null` versus the first or last sample stores the same row |
| Owner equals public | Over the corpus with trims, hiding on and off: `trimmed.summary` bytes equal the public metadata's summary, `suggested_title` equals the public page's empty-title suggestion, and `hide_ends_ranges − a` equals the public cut |
| AC 38, 39, 40 | Circles from the remaining ends; a triathlon trimmed into the bike (sport, sections, T numbering, title); F-45's town A/B case with a trimmed start |
| AC 43, 44, 47 | Remove the trim: public bytes equal a never-trimmed build. Trim twice: same names. Every trim change on a published workout is remove-first, and old names are gone. `regenerate` keeps the trim columns byte-identical |
| Mutants | Each must fail a test: outward rounding; distance or cumulative streams not rebased; `start_time` not shifted; device session or cut-lap totals kept; hiding before trim; `Trim` missing from the owner view; trim columns on the `HidesMore` allow-list; a stream with no valid value in the window kept present |
