# F-59 Container image and install paths: architecture

- **Version:** 0.1
- **Status:** accepted (15 Nov 2026). Critical lane. Includes the user decisions of 15 Nov 2026 on Caddy: containers float on a pinned minor tag, bare metal uses Caddy's apt repository (OQ-261 reversed), no local Caddy override. Open points at the end
- **Feature:** [`features/F-59-container-image-and-install-paths.md`](../features/F-59-container-image-and-install-paths.md); "AC n" is the n-th acceptance criterion there
- **Requirements:** INF-9, INF-4, INF-1, INF-8 (F-52 builds on it), NFR Privacy, NFR Security, NFR Operations, UP-7, AC-4, UP-10; TD Hosting and operations, Build and CI, Security and privacy
- **Builds on:** [F-31](F-31-server-deploy-and-monitoring.md), [F-30](F-30-regenerate-command.md) RG-9 to RG-11, [F-29](F-29-about-page-and-attributions.md) AB-5, AB-6, ADR-021, ADR-022, ADR-031, ADR-034, ADR-035, ADR-039, ADR-043. **New:** [ADR-052](ADR-052-release-image-built-once-pushed-by-the-release-job.md), [ADR-053](ADR-053-web-assets-served-from-the-data-directory.md). **Revised:** ADR-034 rev. 5, ADR-035 item 4 superseded
- **Owner:** backend. Files: `deploy/Dockerfile`, `Dockerfile.dockerignore`, `compose.yaml`, `compose.build.yaml`, `compose.notify.yaml`, `Caddyfile`, `deploy.sh`, `example.env`, new `deploy/podman/` (Quadlet units, control script), new `deploy/systemd/` (bare-metal units, apt pin), `RUNBOOK.md` (shared parts), `DOCKER.md`, `BAREMETAL.md`, `PODMAN.md` (rewritten), `ci.yml`, `Makefile` (`docker-check`, `caddy`, `caddy-check`), the F-29 sources file. Removed: `caddy.env`, `fetch-caddy.sh`, `clean-assets.sh`. Go: a new package for the web assets and bundle lists (IP-8), called by `serve` and `regenerate`; no new setting, no schema or format change

## Shape

```
release vX.Y.Z (CI, one run)
  ghcr.io/<owner>/workout-explorer:vX.Y.Z  (app only: binary + web on the pinned distroless base; digest D)
  workout-explorer-vX.Y.Z-deploy.tar.gz    (deploy files; compose.yaml and the Podman app unit name the image by D)
  workout-explorer-vX.Y.Z-linux-amd64.tar.gz (binary + web, for bare metal)
  SHA256SUMS                               (both archives)

Compose, rootless Podman:  app = our image by digest     caddy = docker.io/library/caddy:2.11 (official, patch floats)
Bare metal (systemd):      app = binary from the tarball caddy = /usr/bin/caddy from Caddy's apt repository, held at 2.11.*
Every path:                serve copies web/assets into {data}/site/assets (additive); Caddy reads only public/ and site/
```

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| IP-1 | **Image contents.** Built from `deploy/Dockerfile` (the self-build Dockerfile becomes the release build). Final stage: the pinned distroless static Debian base (`nonroot`; its digest lives only in the Dockerfile now) plus the binary at `/srv/workout-explorer/bin/workout-explorer`, the web build at `/srv/workout-explorer/web` and the project's `LICENSE`. Nothing else: no Caddy, Caddyfile, settings, data, operator file, Impressum, key or token. Default user `10001:10001`, entrypoint the binary. OCI labels: source (repository URL), version (tag), revision (commit), licences (project SPDX id), title. linux/amd64 only, one plain image manifest: no index, no attestation manifests | User decision. The paths stay those of today's mounts, so every documented `exec … /srv/workout-explorer/bin/workout-explorer` command is unchanged. The base already carries CA roots for Pushover. A single manifest keeps "the digest" one value |
| IP-2 | **Licences (INF-1).** The base image's own Debian copyright files stay in the image (the build never deletes them). Third-party texts for the binary and the bundle ship inside the image already, in the generated About page (F-29 AB-5). The F-29 sources file gains one entry for the base image: name, Debian release, its packages with their licences, link to the distroless source. `make ci` fails when the image's package list differs from that entry, so a base bump cannot silently change what we redistribute. Caddy's entry stays (we still do not ship it) and shows the pinned minor (IP-6) | Publishing the image distributes the base's files; the check works like AB-6's escape hatch |
| IP-3 | **Build once, test, push the tested bytes** ([ADR-052](ADR-052-release-image-built-once-pushed-by-the-release-job.md)). On a `vX.Y.Z` run, `make ci` builds the image (version and commit as build arguments) into an OCI archive and runs every image check (IP-12) on exactly that archive. The `ci` job writes the archive's manifest digest into the release's `compose.yaml` and Podman app unit, packs the release assets, and hands assets and image archive to `release` (run artefact, 1 day). `release` pushes the archive unchanged (digest preserved, with the runner's preinstalled tooling, no third-party action) and fails if the registry reports another digest | AC 2. No rebuild between test and push |
| IP-4 | **Note 16 Nov 2026 ([F-52](F-52-auto-update.md) AU-5): step (3) creates a draft; step (4) moves to a job on the release's publication.** **Tags and who pushes.** `release`: `needs: ci`, only on tags matching `vX.Y.Z` (digits only), the only job with `packages: write` (beside `contents: write`), no checkout, no repository code, actions pinned by commit, `GITHUB_TOKEN` only, no personal token anywhere. Order: (1) `vX.Y.Z` already in the registry with another digest: fail red, nothing changes; same digest: continue (completes a half-done job); (2) push; (3) create the release (IP-5); (4) move `latest` to it only if the current `latest`'s version label is lower or absent (numeric per component). A whole re-run rebuilds, gets another digest and stops at (1): a version tag is never overwritten. Other tags: CI, no image, no release, `latest` untouched. One-time operator step (runbook, Releasing): make the package public, linked to the repository, write access for this repository's Actions only. A failure after (2) leaves an image no release names until the job is re-run; harmless | AC 1 to 3; as ADR-035 item 1 |
| IP-5 | **Release assets.** The bare-metal tarball (unchanged: binary, `web/`, `COMMIT`); a new **deploy archive** `workout-explorer-<tag>-deploy.tar.gz` (F-52 AU-3 moved forward), built from an allow-list of the files the three paths install: `compose.yaml`, `compose.notify.yaml`, `Caddyfile`, `deploy/podman/*`, `deploy/systemd/*`, `deploy.sh`, `example.env`, the operator and Impressum examples, `COMMIT`. Never `.env`, the Dockerfile, `compose.build.yaml`, `minisign.pub`. `SHA256SUMS` lists both archives. **Our digest's one home is the release's `compose.yaml`**: our image as a literal `ghcr.io/<owner>/workout-explorer:vX.Y.Z@sha256:…`, no variable, so `.env` cannot redirect it; the Podman app unit gets the same value, checked equal. The committed `compose.yaml` cannot start `app` without the release's value or `compose.build.yaml` | Image and deploy files (Caddyfile CSP hashes, RG-14) move together. Covered by `SHA256SUMS` now and by the signature with F-52 |
| IP-6 | **Caddy on the container paths** (user decision 15 Nov 2026). The official image `docker.io/library/caddy:<minor>` (today `2.11`), fully qualified (Podman needs it), **tag only**: patch versions float; a minor bump comes only with a release of ours. The minor's one home is `compose.yaml`'s Caddy tag; the Podman unit and the bare-metal apt pin carry the same minor, `make ci` fails if they differ. The Caddyfile comes from the deploy files, mounted as the `conf/` directory. No hoster override of the Caddy image or version is offered | Our signature covers the tag name, not Caddy's bytes; trust in patches rests on Docker's official-image pipeline (accepted) |
| IP-7 | **Hardening of the Caddy container** ([ADR-034](ADR-034-compose-bridge-networks-with-mounted-binaries.md) rev. 5 item 6). User `10002:10002` with group `10001`, read-only root, all capabilities dropped, `no-new-privileges`, a small `tmpfs` (owner 10002, `0700`) over the image's two state directories `/config` and `/data`, so nothing writes into the image and no anonymous volume is created. **No capability, empty bounding set** (user decision 16 Nov 2026, QA-59-r1-1): since 2.11.8 the official binary's file capability `cap_net_bind_service` has no effective bit, so it runs with an empty bounding set; a `cap_add` would leave it in CapPrm under Docker, against AC 8. Port 8088 needs none. Because the patch floats, every route that pulls Caddy first checks that the pulled image starts under this hardening (`caddy validate` with the same flags) and, if not, gives the tag back to the previous image, so nothing later starts it: `deploy.sh`, the runbook's update and between-releases steps, `workout-explorer-ctl install`/`pull`/`start`/`restart` (F-52's updater reuses the same guard). `app` keeps an empty set | AC 8's intent (the process holds no capability). Rejected: copying the binary out of the image (then we distribute Caddy), root, a derived image (ghcr carries no Caddy) |
| IP-8 | **Web assets through the data directory** ([ADR-053](ADR-053-web-assets-served-from-the-data-directory.md)), same on every path and for self-built images. Caddy serves `/assets/*` from `{data}/site/assets/` and no longer reads the web build. `serve` at start (before the page shells and before listening) and `regenerate` at start copy `web/assets/` **additively**: a present file with the same bytes stays, anything else is written by temporary name and rename; a copy never removes. One new package owns `site/assets/` and `{data}/bundles/` (`shell` keeps the HTML shells): each copy records the current bundle's names as a list keyed by its content (works for self-built and dev versions); on a data directory without `bundles/` the files already in `site/assets/` become one list first. **Clean-up moves into `regenerate`:** after a run that processed every workout, RG-10's rule unchanged; its result is reported distinctly, so `deploy.sh` keeps exit 4. No lock: a copy only adds the running bundle, a clean-up never removes the current list, and RG-9's scan can only over-keep. The files count toward the storage limit (a few MB per kept release) | In an image `web/` is replaced whole, and the official Caddy cannot see it. One writer per subtree; the deploy user no longer needs write access to anything Caddy serves |
| IP-9 | **Compose host layout.** `/srv/workout-explorer/` holds `compose.yaml`, `compose.notify.yaml`, `conf/Caddyfile`, `.env`, `operator/`; no `bin/`, `web/`, `bundles/`, `clean-assets.sh`. `WX_WEB` leaves `.env` and the Caddyfile. Mounts: `app` the data directory (read-write) and `operator/` (read-only); `caddy` `public/`, `site/` (assets inside) and `conf/`, read-only, plus IP-7's tmpfs. Networks, trust chain, memory cap, restart and logs: unchanged (ADR-034, F-31 DP-1 to DP-11) | Host directories only, never created by the runtime (DP-3) |
| IP-10 | **Operator's `deploy.sh` on the image path** (until F-52 replaces its entry). Keeps its tag, clean-tree and HEAD checks; downloads the deploy archive and `SHA256SUMS` (not the tarball), checks the sums and that `COMMIT` is HEAD, and installs the archive's files, not the checkout's. **Nothing on the server changes until** both images are pulled with the new `compose.yaml` and the new Caddyfile is validated by the pulled Caddy. Then: install, `up -d` (recreates `app` on the new image; recreates `caddy` only when a new patch arrived or its definition changed: brief page outage, accepted), Caddyfile-only change → graceful reload, health wait for the tag, `regenerate` (clean-up included), summary. Exit codes 0, 1, 3, 4 unchanged. Manual Compose hosters follow the same steps by hand (runbook) | AC "deploy.sh deploys the image of a tag". Validation on the server removes the linux/amd64 requirement for the operator's machine |
| IP-11 | **Note 16 Nov 2026 ([ADR-054](ADR-054-rootless-podman-deploy-files-owned-by-the-service-user.md), F-52): units, Caddyfile and control script belong to the service user, root never runs them; updates go through `update.sh`.** **Rootless Podman (Quadlet).** The units and the control script become files in `deploy/podman/`, shipped in the deploy archive; `PODMAN.md` explains, does not embed. Same images (ours by digest, Caddy by minor), IP-7 in Podman's form (engineer confirms CapPrm and CapEff 0 under rootless), mounts as IP-9 with today's subuid mapping, `WX_TRUSTED_PROXIES` still Caddy's own edge address. Root installs the units (root-owned unit directory, as today). Update: new units and Caddyfile from the archive, pull both images, restart, `regenerate` through the control script; no clean-up step | AC 15 (no tarball layout, no bind-mounted binaries) |
| IP-12 | **`make ci` fails** (not skips, without Docker) when: the image's file system holds anything outside IP-1, a label is missing, or the default user is root; the three Caddy minors (IP-6) differ; a builder version differs from `go.mod` / `.nvmrc` (as today); the base's package list differs from the IP-2 entry; forbidden files reach the build context (as today); a Compose file set does not validate (with a test digest in place of the release value); the deploy archive holds a file outside its allow-list or a script in it fails `sh -n`. `make caddy-check` runs against the binary of the current patch of the pinned minor, taken from the official image (the log records the patch) | AC 4, AC 5; keeps the three Caddy homes in step |
| IP-13 | **Note 18 Nov 2026 ([F-60](F-60-bare-metal-auto-update.md) BM-2, ADR-055): the program directory belongs to the deploy user; `.env` is `root:deploy` `0640`; `operator/` stays root's.** **Bare metal: processes and users.** Two system services, `workout-explorer` (app) and `workout-explorer-caddy`, unit files in the deploy archive, installed by root. Users `workout-explorer` (owns the data directory) and `workout-explorer-caddy` (in the app's group), as the 10001/10002 pair. Program files root-owned at the image's paths (`bin/`, `web/` from the tarball, `conf/Caddyfile`). `.env` root-owned `0600`, read by systemd for the app unit only; **Caddy's environment never contains it** (Pushover secrets): Caddy's few values are fixed in its unit, a drop-in overrides them. Caddy binds the host-local listen address itself (the Caddyfile gains a bind setting whose default keeps the containers as they are) and trusts `127.0.0.1` and `::1` as the proxy; Go trusts loopback (ADR-021, unchanged) | Same trust chain without containers. Every host process can reach both loopback ports and set a forwarded address: the accepted cost of DP-1b, unchanged |
| IP-14 | **Bare metal: Caddy** (user decision 15 Nov 2026, OQ-261 reversed). From Caddy's signed apt repository; an apt pin file in the deploy archive holds the package at the release's minor, so patches arrive with the host's package updates and minors only with our release. Our unit runs `/usr/bin/caddy` with our Caddyfile. The package's own `caddy.service` is not ours: disabled unless it is the hoster's proxy (otherwise it listens on :80 with its default config). Our unit restarts when the package replaces the binary (a systemd path unit; engineer verifies with a real package upgrade); brief page outage, accepted. If the package's binary carries a file capability, IP-7's empty-bounding-set rule applies | No `fetch-caddy.sh` on the host; patches without a release of ours |
| IP-15 | **Bare metal: sandbox**, the systemd form of ADR-034 items 1, 5, 6. See the table below. **Egress by systemd IP filtering** (`IPAddressDeny=any`, `IPAddressAllow=localhost`) on both units; with notifications on, a drop-in lifts the deny for the app unit alone (the `compose.notify.yaml` equivalent: any outbound route, as on Compose) | Per unit, no global firewall state, independent of the hoster's firewall. Needs cgroup v2 (Debian default). Would choose nftables owner rules if a supported distribution lacked cgroup IP filtering |
| IP-16 | **Note 18 Nov 2026: updates go through `update.sh` ([F-60](F-60-bare-metal-auto-update.md)); `regenerate` in an update runs as a fixed unit (BM-4).** **Bare metal: subcommands and updates.** `regenerate`, `delete` and `parse` run as the app user with the app's `.env`, sandbox and slice (as `exec` into `app`'s cgroup, F-30 RG-13); the runbook gives one `systemd-run` line each, or a shipped wrapper (engineer's choice). Reports: `sqlite3` read-only as the app user. Update by hand until F-60: verify both archives, binary by temporary name and rename, `web/` replaced whole (old assets live on in the data directory, IP-8), units and apt pin when changed, restart `app`, health, `regenerate`; Caddyfile change → reload | AC 12 |
| IP-17 | **Migration** from the tarball layout (operator's VPS, the former RUNBOOK 6a; now `DOCKER.md` section 12) and today's Podman setup. The data directory stays in place with its owner (10001, or the Podman-mapped UID), so every workout, link, expiry and report survives by construction: the move changes program files only. Before the first start of the image, copy the old `web/assets/` into `{data}/site/assets/` as the app's UID; the first copy turns them into one list (IP-8), and the clean-up drops them once no served page names them. Then install the deploy archive's files, drop `WX_WEB` (keep `COMPOSE_FILE` without the build override), replace the stack, health, `regenerate`. Remove the old `bin/`, `web/`, `bundles/` and `clean-assets.sh` only after `regenerate` exits 0. Schema migrations run at first start as on any deploy (ADR-019: back only by a newer release) | AC 14. Kept workouts keep their old assets |
| IP-18 | **Self-build.** `compose.build.yaml` shrinks to a local `build` and image name for `app`; Caddy as in `compose.yaml`. Clone at a tag, build, `up -d`, `regenerate` (the clean-up now runs there too). Version `unknown` unless given as build argument. A short runbook note, not a path; F-52 does not cover it (OQ-215) | Scope |
| IP-19 | **`caddy.env` and `fetch-caddy.sh` are removed.** Nothing needs an exact Caddy patch any more: the containers float within the minor, bare metal uses apt, the image ships no Caddy. `make caddy` takes the binary out of the official image of the pinned minor (Makefile reads the minor from `compose.yaml`). F-22 H-7's pin now means the minor: a new minor must pass `make caddy-check` (the 2.10.2 `.br` regression stays the example). A patch regression between our releases is not caught (accepted with the floating patch) | One home per fact; no checksum file for a version nobody runs |

**Invariants per path (AC 8 to 11)**

| Invariant | Compose | Rootless Podman | Bare metal |
| --- | --- | --- | --- |
| App has no egress unless notifications are on | internal `backend`; `compose.notify.yaml` | internal network; egress network unit | IP-15 IP filtering; drop-in |
| Caddy only host-local; app port never outside | `WX_LISTEN` on loopback; `app` unpublished | `PublishPort` on loopback | IP-13 bind; IP filtering allows localhost only |
| Trust chain | ADR-034 item 2 | Caddy's own edge address (PODMAN.md) | proxy `127.0.0.1`/`::1`; Go loopback |
| Non-root, no capability held, read-only, no new privileges | IP-7 | IP-7, Podman form | IP-15 |
| Caddy reads only `public/`, `site/` | mounts IP-9 | mounts IP-9 | IP-15 file-system view |
| Memory cap; restart; stopped stays stopped | `mem_limit`; `unless-stopped` | memory args; `Restart=always`, stop = disable | slice; `Restart=always`, stop = `disable --now` |
| No visitor addresses in logs | `local` driver | journald | journald |

**Bare-metal sandbox (IP-15)**

| | App unit | Caddy unit |
| --- | --- | --- |
| Capabilities | empty bounding set, `NoNewPrivileges` | as app (IP-7: the binary's file capability has no effective bit) |
| File system | system read-only, home and `/tmp` private; writable: the data directory only | system read-only; under the data directory sees only `public/` and `site/` (empty temporary file system over the data and deploy directories, read-only binds of `public/`, `site/`, `conf/`); state in a runtime directory, gone at stop |
| Network | IP filtering: localhost only, lifted by the notify drop-in | localhost only, never lifted |
| Memory | `workout-explorer.slice` capped at the Compose value, no swap; subcommands join it | not capped |

## Verification notes (QA at effort high)

Beyond the AC, on each path where it applies: CapPrm and CapEff 0 for both processes (Docker and rootless Podman); no anonymous volume after `up -d`; the image's full file listing; the pushed digest equals the digest in the release's `compose.yaml`; a re-run with a rebuilt image is refused and leaves tag and `latest` alone; an older tag pushed after a newer one leaves `latest` (scratch fork or registry); bare metal: an outbound connection as the app unit fails with notifications off and works with them on, Caddy's unit cannot read `workouts.db` or `.env`, a package upgrade of Caddy restarts our unit; N → N+1 on all three paths with a network log of an old page before `regenerate`; the migration rehearsal (AC 14). Mutants that must fail a test: a copy that removes, a clean-up that removes the current list, a clean-up after an incomplete run.

## Open points (for the user)

Decided by the user on 15 Nov 2026 as suggested (decision log of `features/README.md`).

1. **OQ-264 `latest` with Compose.** A `compose.yaml` switched to `:latest` runs a new app with old deploy files (Caddyfile CSP hashes, service changes) and can break pages. Suggestion: the runbook never uses `latest` for Compose or Podman; it names `latest` only for a quick `docker pull` look.
2. **OQ-265 Caddy's one bounding capability (IP-7).** The official binary cannot run with an empty bounding set; the container keeps `NET_BIND_SERVICE` there, while the process itself holds no capability. Suggestion: accept as meeting AC 8 ("without capabilities" = none held). Superseded 16 Nov 2026: empty bounding set plus a guard on every Caddy pull (IP-7).
3. **OQ-266 Hoster's own apt Caddy (IP-14).** If the hoster's TLS proxy is the same apt Caddy package, our pin holds it at our minor too. Suggestion: accept; the runbook says so.
