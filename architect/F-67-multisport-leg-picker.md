# F-67 Multisport leg picker: architecture

- **Version:** 0.1
- **Status:** accepted (24 Nov 2026). Normal lane. OQ-315 to OQ-325 decided as suggested (user, 24 Nov 2026; feature file); no open questions
- **Feature:** [`features/F-67-multisport-leg-picker.md`](../features/F-67-multisport-leg-picker.md)
- **Requirements:** AP-12; AP-3, AP-4, AP-5, AP-6, AP-7, AP-15, AP-17, AP-18, AP-19, AP-21, DS-1, DS-2, DS-4, DS-6; NFR Performance, NFR Reliability
- **Builds on:** [F-42](F-42-multisport-sections.md) MS-1, MS-2, MS-7, MS-9; [F-64](F-64-laps-and-splits-per-multisport-leg.md) LL-3, LL-4; [F-17](F-17-range-selection-and-axis-toggle.md) R-7, R-8; [F-33](F-33-fullscreen-cursor-readout.md); [F-13](F-13-activity-page-layout.md) D-10, D-20; ADR-009 (item 5 noted in place), ADR-011, ADR-016, ADR-026
- **Owner:** frontend. **No backend change** (LP-2), no data file, format or setting change

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| LP-1 | **Entries.** The sport legs of `legs(sections(meta), N)` (MS-2: sections with samples), transitions left out (OQ-315), preceded by "Whole workout". A sport that occurs more than once is numbered in the picker only, in order ("Run 1", "Run 2"; name + space + number, no new text) (OQ-324). No sport leg with samples: no picker. The leg's range is its `sectionRanges` pair `[a, b]` (b = the next section's start or N − 1) | One leg rule (MS-2) for picker, range check and lines |
| LP-2 | **Control and place: a native `<select>` in the existing axis toolbar row**, after the axis toggle, built by the sections chunk. The row is already reserved from first paint by `has-distance` (40 px, F-17 R-8), so the late picker shifts nothing and needs no server change. It shrinks (`min-width: 0`, the select truncates its text) so phone portrait at 360 px never scrolls sideways with the toggle beside it. A multisport workout **without any distance stream** has no toolbar row and gets **no picker** (deviation, see below). Keyboard, focus and touch come with the native control; styled with the toggle's tokens (`--line`, `--bg`, `--fg`), CSS in `sections.css` | Any number of legs (swimrun, duathlon) fits one row in four languages; segmented buttons do not at 360 px beside the toggle. Same pattern as F-64's per-leg drop-down *(F-76 TC-7: the row is reserved for every workout with charts, so the sections chunk checks the distance stream itself and inserts the picker before the size toggle.)* |
| LP-3 | **View state.** One value: `null` (whole workout) or the picked leg `{a, b, sport}`, held as reactive state on the page's `Look` next to `decorate`, written only by the sections chunk, read by `ChartStack` through a getter prop. Memory only: no `lib/prefs`, fragment or history entry (OQ-320). Units, language and axis changes keep it (they do not touch `Look.view`) | Same seam as F-42's decorators; the edit page gets it through `startPage` with no owner code (LP-10) |
| LP-4 | **Chart zoom (all charts, both axes).** `ChartStack` adds the view to its inner `{#key}` so a switch rebuilds the uPlot instances, as an axis or units switch does today. In a leg view every chart gets the same x range `[at[a], at[b]]` of the drawn axis (ADR-009 item 5 still holds: one range for all). Only the samples `a..b` reach `chartValues` and `decimate` (subarrays; gap indices rebased); samples outside must not be passed, since `decimate` folds them into the edge columns and would stretch the y axis. So the y axes and the pace bound (95th percentile) fit the leg, and the leg gets every pixel column (detail ≥ the whole view). Same chart set and order as the whole view (a leg without a stream shows an empty plot), so heights stay reserved. `view = null` takes today's path unchanged ("restores exactly", AC 2). Axis labels stay elapsed time and distance from the workout start (OQ-323) | One rebuild path that exists and is measured; no per-chart state; no layout change |
| LP-5 | **Degenerate legs.** On the distance axis, a leg whose distance does not advance (`at[b] ≤ at[a]`: pool swim without distance, missing stream) is drawn on the time axis, the toggle showing the drawn axis while the viewer's stored choice stays (R-8's existing fallback, per view). A zero span on time (a last leg of one sample) widens to `[x, x + 1]` as `xRange` does for N = 1. Legs without samples never reach the picker (LP-1) | MS-7 reliability cases without new UI |
| LP-6 | **Speed chart in a leg view:** the speed spec is `chartSpecs(leg.sport, units).speed` (label, unit, faster-up axis, pace ticks); every other spec follows the leg's sport too (`presentCharts`/`readoutFields` take it; only the cadence unit label differs, no value changes), and a fresh readout is seeded with the view's sport. The whole view keeps one km/h or mph speed chart (OQ-321) | The constraint's "swap a spec"; per-leg cadence units are not in scope |
| LP-7 | **Interaction in a leg view.** Cursor store, gesture reducer and range store unchanged (ADR-008, ADR-010). A chart's pointer index is clamped to `[a, b]`, so hover, touch-drag and long-press ranges stay inside the leg. The plot overlay clips its children **in a leg view only** (one class), so the cursor line from a map hover outside the leg, range shading and decorations (leg lines and names, pins, trim marks) are cut at the plot edge; the whole view keeps today's overhang (pin dots at the edge). The flush path gains nothing | 60 fps path untouched (ADR-016 gate) |
| LP-8 | **Range and view** (OQ-316, OQ-319). Picking a leg never touches the selection store; an existing range stays. The chunk subscribes to the selection: a new range (`a ≥ 0`) not inside the shown leg (`a ≥ leg.a` and `b ≤ leg.b`) sets the view to `null` and the select to "Whole workout", without moving the map (AP-19). Clearing a range keeps the leg. A `#range=` link is applied before the chunk exists, so the page opens on "Whole workout" anyway | One rule, one listener, in lazy code |
| LP-9 | **Map** (OQ-317). New map handle call (lazy map chunk): fit to the bounds of the samples in `[a, b]` that have a position, with the initial fit's padding and `maxZoom`, no animation; `null` fits `route.bounds`. That target becomes D-20's resize refit target until the viewer moves the camera. No positioned sample in the leg: no move, target unchanged. Called on a pick; LP-8's automatic return only resets the refit target to the whole route (`fit(-1, -1, true)`, no camera move, also when queued before the map is ready). Positions are the decoded data file's, i.e. the public, privacy-applied ones on the viewing page (SH-4, UP-6), so a hidden end gives the fit nothing; the edit page fits the owner's draft as its route already shows it. The sections chunk gets the map handle as the pins chunk does; today's seam keeps **one** waiting callback (`onPinMap`), so it must serve both chunks | AP-19 stays true for ranges; nothing new is published |
| LP-10 | **Readout and range panel per leg (entry).** Readout (both instances, so F-33's fullscreen strip matches): on a workout with sections the speed field takes label, unit and format from the sport of the leg holding the cursor sample (the last section whose start ≤ i), in every view and before the chunk arrives; "–" in a transition, at a stop (as today) or without a value. Label and unit cells are written only when that sport changes, never per flush. Range panel (OQ-322): a range inside one section (the LP-8 test) uses that section's sport for the speed label, unit and value; otherwise the workout's (`multisport` → km/h or mph). Existing texts only (`chartPace`, `chartSpeed`, `rangePace`, `rangeSpeed`). **The entry must not import `lib/sections`' index:** that moves the whole shared chunk (398 gzip, with `sportName`) into the entry. MS-2's ordering (by start, file order on ties, first at 0) moves into a small module of `lib/sections` that `sections()` builds on and the entry imports alone, so the rule stays in one place | Scope "applies in every view, also with the picker not yet loaded"; smallest entry share |
| LP-11 | **Edit page** (OQ-325). Same `startPage`, `ChartStack`, `Look` and sections chunk, so it gets the picker with no code in `src/edit/` | Owner chunk stays put (Cost) |
| LP-12 | **Texts** (DS-6, ADR-011 decision 6 R-2): "Whole workout" and the select's accessible name in the sections chunk's own text group, in all four languages; the chunk rebuilds the option texts on a language change (as its leg names, MS-7) and keeps the chosen leg | No entry text |

## Cost

| What | Decision |
| --- | --- |
| Entry (ADR-011) | Hook (LP-3, LP-4, LP-5, LP-7: view state and prop, key, subarray and range, clamp, clip class), readout and panel per leg (LP-10), map and selection passed to the chunk. **Target 300, ceiling 400 bytes gzip**; reserve after the ceiling 1,035 of 62,000 (entry 60,565). The engineer measures before and after and records the figure in ADR-011 item 4. Above 400: stop and report (the reserve would near the review trigger) |
| Owner chunk | **0**: nothing new imported from `src/edit/`. `start.svelte` measured before and after; a change beyond chunk-hash churn (±20) means a module moved (e.g. `lib/sections` reshuffled by LP-10): stop and report. Must stay under 20,000 (19,763 today) |
| Lazy | Sections chunk: picker, view writes, LP-8 listener, numbering, texts, CSS. Map chunk: the fit call. Not counted |
| Server, data file, no-JS page | Unchanged |
| Performance | Leg switch ≤ 100 ms on a mid-range phone (the operator measures, ADR-016 recorder or User Timing around the rebuild). If over: keep the uPlot instances and set scale and data in place instead of the key rebuild (entry cost counts). Scrubbing in a leg view meets ADR-016 on the longest multisport corpus file |

## Deviations for the main session

1. **No picker on a multisport workout without any distance stream** (LP-2). Real triathlons, duathlons and swimruns carry distance; the case would need a reserved row from the server (a `has-legs` class in Go `internal/page` and `lib/page`, a page sample, CSS, and the toolbar condition in `ChartStack`). Overrule if AC 1 must hold there too.
2. **AC 1's "Whole workout · Swim · Bike · Run"** is the drop-down's option list, not buttons side by side (LP-2).
