## Decisions

| # | Decision | Why |
| --- | --- | --- |
| DP-1 | **Topology** ([ADR-034](ADR-034-compose-bridge-networks-with-mounted-binaries.md)). The operator's existing reverse proxy, on the same host, does TLS and forwards plain HTTP to Caddy. One Compose project, two services: `app` (`workout-explorer serve -addr :8080`) and `caddy` (plain HTTP on container port 8088; no ACME, no 80/443, `auto_https off`). Two bridge networks: **`edge`** (Caddy only; IPv4 only; a fixed subnet, so its gateway address is known) publishes the one port **`${WX_LISTEN}` → 8088**, default `127.0.0.1:8088`; **`backend`** (`internal: true`; Caddy at a fixed address and `app`). `app` publishes no port and has no outbound route. No `depends_on`: Caddy serves pages while `app` is down | Decision log 1 Nov 2026, later. A loopback bind keeps Caddy's port off the internet without relying on the host firewall, which Docker's published-port rules bypass |
| DP-1a | **Go trusts only Caddy** (ADR-021 rev. 6 item 6, unchanged in substance). `WORKOUT_EXPLORER_TRUSTED_PROXY`: one IP address, invalid → exit 2, unset → loopback only. The Compose file is the one home of Caddy's `backend` address and sets both Caddy's `ipv4_address` and `app`'s setting from it; not in the operator's env file | No other peer can choose its address |
| DP-1b | **Caddy trusts only the operator's proxy.** Server option `trusted_proxies static ${WX_TRUSTED_PROXIES}` with `trusted_proxies_strict` (rightmost untrusted entry of `X-Forwarded-For` is the client). `WX_TRUSTED_PROXIES`: one or more addresses or CIDR prefixes as Caddy reads them; default the `edge` gateway address, which is the source Caddy sees for a proxy on the host connecting to `127.0.0.1` (Docker rewrites loopback sources to it, with or without its userland proxy). A proxy in a container binds `WX_LISTEN` to an address it reaches and sets the narrowest range holding its source (runbook). Unset locally: Caddy trusts nobody. Caddy then **replaces** `X-Forwarded-For` towards Go with its resolved client (`header_up X-Forwarded-For {client_ip}`), so Go's last entry is the client, not the operator's proxy. Invalid value: Caddy refuses to start | Caddy's default would append the operator's proxy behind the client, and every visitor would share that key. **Accepted cost:** every process on the host (and every container that reaches `WX_LISTEN`) shares the proxy's source address and can set a client address; the host is the operator's |
| DP-1c | **Two upload limits** (ADR-021 rev. 6 items 7, 8). `WORKOUT_EXPLORER_UPLOADS_PER_HOUR_IPV4` (per address) and `WORKOUT_EXPLORER_UPLOADS_PER_HOUR_IPV6` (per /64); default 60 each, range 1–240, TD number format, invalid → exit 2, read by `serve`, logged in `server started`. One key table (100,000 keys, fail closed) holds both families; L ≤ 100,000 × (4·max + 160) bytes: 40 MB at 60, **112 MB at 240** | 240 per hour (4 a minute) covers a household or a CGNAT address of friends; the maximum keeps L small next to M(4) on 2 GB |
| DP-1d | **Docker daemon settings: no runbook duty.** Clients never reach a published port directly; their address travels in `X-Forwarded-For` from the operator's proxy, so `"userland-proxy"` and `ip6tables` change nothing for us. IPv6 on `edge` is not needed (the operator's proxy terminates IPv6) | Supersedes the 1 Nov 2026 "Docker daemon settings" entry. Standalone mode (later) would bring both back |
| DP-2 | **The operator's deploy builds no image and does not use the Dockerfile.** Both services run one pinned base image (distroless static, Debian, `nonroot`; pinned by digest). The Go binary and `web/` (GitHub Release, DP-18) and the Caddy binary (`deploy/fetch-caddy.sh`, checksums from `deploy/caddy.env`) are bind-mounted read-only. No image is published: no registry, CI uploads no image | Deploy is "copy and restart", and production runs the bytes `make ci` tested (ADR-035). The image path (DP-16) would cost the operator three things: `web/` inside the image drops the old `web/assets/` that published pages still name (DP-10 keeps them); Caddy, which serves `web/`, would be recreated on every deploy (AC 2 allows that only for Caddy changes); and the build runs on the 2 GB VPS next to a live `serve`, or images get shipped. DP-17 keeps the second path from rotting |
| DP-3 | **Host layout.** `/srv/workout-explorer/` holds `compose.yaml`, `.env`, `bin/`, `web/`, `conf/Caddyfile`; `/srv/workouts` is the data directory. Caddy's own state (instance ID, autosaved config, admin socket) is a small `tmpfs`: no certificates exist, nothing needs to survive. **Same path inside the container as on the host.** **Mount directories, never single files.** Compose never creates a host path (`create_host_path: false`); the runbook creates them with owner and mode | A file mount keeps the old inode after a rename. A Docker-created path is root-owned and breaks `publish.Open`'s `MkdirAll` |
| DP-4 | **Data directory.** A bind mount of `/srv/workouts` on local disk, one file system, nothing mounted below it. Every process that writes `public/` (`serve`; `regenerate`, `delete` via `docker compose exec app`) uses that directory, so ADR-031's `flock` works across containers. Caddy mounts only `public/` (F-22 H-10) | ADR-022, ADR-031; AC 11 checks a plain directory |
| DP-5 | **Users and hardening.** `app` runs as a fixed non-root UID:GID owning `/srv/workouts`; `caddy` as another non-root UID with `app`'s GID as supplementary group, so it reads `public/` (`0750`/`0640`, F-15) and nothing else. Both: read-only root, all capabilities dropped, `no-new-privileges`. Port 8088 needs no privilege | A Caddy bug can read only published files |
| DP-6 | **Settings: one env file**, `/srv/workout-explorer/.env` (owned by the `deploy` user, `0600`; QA-31-r1-6: as built, not root), Compose's project `.env` and `app`'s `env_file`. Keys: the `WORKOUT_EXPLORER_*` settings of TD Configuration except `TRUSTED_PROXY` (DP-1a), plus `WX_DATA`, `WX_WEB`, `WX_LISTEN`, `WX_TRUSTED_PROXIES`. **No site address for Caddy:** it answers on its port for any host; the site name lives only in `WORKOUT_EXPLORER_BASE_URL` (the operator's `https://` origin), so "set together and must match" holds with one key. `deploy/example.env` lists every key with its default; the server's file is not committed | One home for the site name. `regenerate` (F-30) gets the same environment through `exec` |
| DP-7 | **Restart and stop.** Both services `restart: unless-stopped`; `docker compose stop` stays stopped (AC 3). Docker starts at boot; no unit of ours. `stop_grace_period` above `serve`'s 10 s shutdown grace (F-01); a kill is covered by startup recovery (ADR-022). The binary is PID 1 | Same effect on crashes as `Restart=always` |
| DP-8 | **Memory cap** on `app`: `mem_limit` = `memswap_limit`. Value: the cgroup's **`memory.peak`** during 4 uploads at the parse limits plus one publish with its preview render, plus **L at the limits' maximum (112 MB, DP-1c)**, plus 20 %, rounded up to 100 MB. So raising a limit never needs a new cap. At least about 600 MB of the 2 GB must stay free for the OS, Docker and Caddy; if not, ask the user (more RAM, or N below 4; ADR-017's gate of 2 does not lower M(4)). A deploy's `regenerate` is not included (ADR-017 rev. 8, F-30 RG-13). `GOMEMLIMIT` not set (ADR-017 item 5) unless the AC 10 run peaks within 10 % of the cap. Caddy is not capped | The peak is what kills |
| DP-9 | **Caddyfile additions** (it stays the one config, F-22): DP-1 listener, DP-1b trust and `header_up`. **Graceful reload** through the admin API, on `localhost` inside the `caddy` container only in the Compose environment; `admin off` stays the default locally and in `make caddy-check`. **No access log.** Caddy's own log lines must not carry client addresses, query strings or `Authorization`: the engineer checks what 2.11.7 writes for a `404` and a `502` with `app` stopped, and filters the default logger if needed. Never `log_credentials`. **No `/api/*` timeout below Go's longest write deadline** (the owner download, F-12 O-12; the upload's 120 s + 6·T ≤ 480 s). No request-body limit | A Caddyfile change costs no outage. No IP addresses on disk |
| DP-10 | **Deploy** ([ADR-035](ADR-035-deploy-run-by-the-operator-no-server-credentials-in-ci.md)): one command on the operator's machine, `deploy/deploy.sh vX.Y.Z user@host` (or `... local` on the server itself: same steps, commands run locally instead of via ssh/scp, 2 Nov 2026); the tag is required (no "latest"). (1) Refuse unless the tag has the `vX.Y.Z` form, the tree is clean and HEAD is the tag's commit (`compose.yaml`, `Caddyfile` and `caddy.env` come from the checkout, so they match the binary). Download the release's two assets (`gh release download`), check `sha256sum -c SHA256SUMS`, unpack, and refuse unless `COMMIT` is HEAD (catches a tag moved after its release). (2) Copy over SSH; `web/assets/` additive only; every other file to a temporary name, then renamed; template and binary before the restart, the HTML entries Caddy serves after it. (3) Restart **only `app`**, then wait for `/api/health` through Caddy to answer `200` with `"version"` exactly the tag (whole string, not a prefix); on timeout exit non-zero with `app`'s last log lines. **No automatic rollback** (ADR-019 one-way door). (4) Caddyfile changed: validate, then reload. Caddy binary, service definition or Caddy's settings changed: recreate `caddy`; the brief page outage is accepted (decision log 1 Nov 2026). (5) Then `regenerate` and the old-bundle clean-up, as [F-30](F-30-regenerate-command.md) RG-10 and RG-11 decide | Pages stay reachable: Caddy keeps running and reads the disk per request |
| DP-11 | **Logs.** Docker's `local` log driver on both services, size-rotated, inside the F-10 headroom (`WORKOUT_EXPLORER_STORAGE_LIMIT_MB` below free space minus logs, Docker and one over-cap upload). Go adds no access log. Logs never leave the VPS | Bounded, local, no addresses (I-7) |
| DP-12 | **Health endpoint; no monitoring in F-31** (decision log 1 Nov 2026). `/api/health` stays side-effect-free (F-01). `serve` opens its listener only after the store is open, recovery has run and the startup expiry pass is done, so a `200` means a healthy start. A later monitor of the operator's checks `/api/health` and `/` (never a workout page); the runbook names both targets | A database probe per check adds a code path for little gain |
| DP-13 | **Hosting and GDPR.** VPS in an EU data centre, ≥ 2 GB RAM, Debian stable, local disk. **Provider backups and snapshots off**; no backup job or off-server copy (AC 11). Our setup opens no port to the outside: 22/tcp (host firewall) and the operator's proxy ports are the operator's; `WX_LISTEN` is never a public address. SSH by key only. Unattended security upgrades on. On the VPS only: `/srv/workouts`, Docker's logs | NFR Privacy |
| DP-14 | **Secrets.** None in the repository or in GitHub. Server access is the operator's SSH key. On the server: the env file (`0600`, no secret today); TLS keys are the operator's proxy's, outside our setup. Release assets hold build output only. The only write permission in CI is `contents: write` on the release job (DP-18); no personal access token | A leaked GitHub token cannot reach the server |
| DP-15 | **Runbook** `deploy/RUNBOOK.md`, linked from `README.md`: fresh-VPS rebuild in under an hour (VPS, DP-13 settings, Docker and the Compose plugin with default daemon settings, users and directories DP-3 to DP-5, `.env` from the example, first deploy). **Operator's proxy:** forward the site to `WX_LISTEN`; append the client's address to `X-Forwarded-For` (rightmost) and set `WX_TRUSTED_PROXIES` to the proxy's source as Caddy sees it; pass responses unchanged (no added or changed security or cache headers, no response caching); no request-body limit below 20 MB + 16 KiB; `/api/*` timeouts as DP-9; no access log for this site (advice; the operator's proxy is outside our privacy guarantees). It records the measured `memory.peak` and the cap (AC 8), and the VPS `parse` time of the all-caps synthetic file with the chosen T (AC 9). **Releasing:** push an annotated or lightweight `vX.Y.Z` tag, wait for the release, deploy it; a failed release run is fixed with the next version (DP-18). A **self-hosting** section covers DP-16: same users, directories and `.env`, plus the `COMPOSE_FILE` line, build and upgrade commands, and on a 2 GB host building with `app` stopped (or on another machine, then `docker save | ssh … docker load`). Links go to friends only after F-29 | — |
| DP-16 | **Self-built image** (decision log 1 Nov 2026, Dockerfile; [ADR-034](ADR-034-compose-bridge-networks-with-mounted-binaries.md) rev. 3 item 4). **`deploy/Dockerfile`**, build context the repository root, with an **allow-list** `deploy/Dockerfile.dockerignore`: `Makefile`, `src/server` without `testdata/`, `src/web` without `node_modules/` and build output, `deploy/caddy.env`, `deploy/fetch-caddy.sh`, `deploy/Caddyfile`. Stages run the **Makefile targets** (`build-web`, `build-server` with `VERSION` as a build argument, and `deploy/fetch-caddy.sh` for Caddy); no copy of their commands. Builder images pinned by version and digest, versions equal to `go.mod` and `src/web/.nvmrc`. **One image for both services:** the final stage is the base image of `compose.yaml`, same digest, holding `bin/workout-explorer`, `bin/caddy`, `web/` and `conf/Caddyfile` under `/srv/workout-explorer/`, the paths the operator's mounts give, so entrypoints and commands stay as in `compose.yaml`. **`deploy/compose.build.yaml`**, an override selected by `COMPOSE_FILE=compose.yaml:compose.build.yaml` in `.env` (a commented line in `example.env`): adds `build` and a local image name to both services and resets their mounts to the data mounts (DP-4) only. Networks, users, hardening, memory cap, logs and settings stay those of `compose.yaml`; `WX_WEB` keeps its default. **Upgrade:** `git pull`, `docker compose build`, `docker compose up -d`; both services are recreated (brief page outage). `web/` is replaced whole, so pages published before an upgrade that changed assets lose their styles and scripts until F-30's `regenerate` rebuilds them (accepted, OQ-96). Platform: linux/amd64 only, the only Caddy pin (OQ-95); arm64 is one more checksum pair when a self-hoster asks | One Compose file and one build recipe for both paths. Allow-list: real FIT files never enter the build context. Caddy's pin stays in `caddy.env` only |
| DP-17 | **`make ci` builds the Dockerfile.** A target in `ci` (after `build`): validates `compose.yaml` with and without the override (`docker compose config`), builds the image with no cache from a registry, checks the image holds both binaries and that Caddy reports `CADDY_VERSION`, and fails if the final stage's digest differs from `compose.yaml`'s or a builder version differs from `go.mod` / `.nvmrc`. Fails, not skips, without Docker (as `caddy-check`, OQ-90). CI publishes nothing from it | A second cold build costs CI minutes, inside the 15 min job timeout; the engineer raises the timeout or adds a local BuildKit cache if it does not fit |
| DP-18 | **Releases** ([ADR-035](ADR-035-deploy-run-by-the-operator-no-server-credentials-in-ci.md) rev. 2; decision log 2 Nov 2026). **One workflow, `ci.yml`, two jobs.** Workflow permission stays `contents: read`. **`ci`** runs only on `v*` tag pushes and manual `workflow_dispatch` (user decision 2 Nov 2026; no branch-push runs); on a tag run it builds with `VERSION` set to the tag name (not `git describe`, which depends on fetch depth and on annotated tags), packs the asset and its checksum, and hands them to the next job as a run artefact (shortest retention, 1 day). **Manual runs on a branch upload nothing.** **`release`**: `needs: ci`, runs only on a tag matching `vX.Y.Z` (digits only; other tags get CI, no release), `permissions: contents: write` on this job only. It checks out nothing and runs no repository code: it downloads the hand-off and calls `gh release create <tag> --verify-tag` with both assets, published (not draft). **Assets:** `workout-explorer-<tag>-linux-amd64.tar.gz` (`workout-explorer`, `web/`, `COMMIT` with the full commit hash) and `SHA256SUMS` (one line, that tarball). **Version:** the tag, exactly (`v1.4.0`), in the binary and in `/api/health`; branch builds keep `git describe --always --dirty`; self-hosters keep the Dockerfile's `VERSION` argument. **Re-pushed tag:** a release is never replaced (no `--clobber`, no delete in CI). If the release exists, `release` fails red and the old assets stay; a tag moved to another commit is refused by the deploy's `COMMIT` check (DP-10). The fix is the next version; the operator may delete a broken release by hand and re-run the job | Tested bytes are released bytes: the release job reuses the `ci` job's build. The write token never meets `npm`, Go modules or the Makefile. Immutable releases make "which bytes are `v1.4.0`" a fact. Note 2 Nov 2026: repository and releases are public; no login needed to download. |

**Headers (ADR-032 re-checked).** No change. HSTS (F-22 H-2) is ignored by browsers over plain HTTP, but it reaches them over the operator's HTTPS, so it takes effect as long as the proxy passes it through unchanged and does not add a second one (DP-15). No other H-2 header assumes TLS at Caddy. HTTP/3 (443/udp, `Alt-Svc`) is gone with Caddy's TLS.

## Verification (critical lane: QA at effort high, on the real VPS behind the operator's proxy)

| What | Check |

| AC 3, DP-7 | `docker compose stop app` stays stopped; `kill -9` of `serve` and a reboot: both services back without the operator |
| AC 4, DP-1, DP-5, DP-9, DP-13 | `ss` on the host: our only listener is `WX_LISTEN`; nothing on 80/443 of ours, no ACME attempt in Caddy's log; from outside, `WX_LISTEN`'s port and `8080` are unreachable. `app` cannot open an outbound connection. The F-12 AC 6 guessed-path list through the live site gives `404`. Headers through the proxy equal H-2, HSTS exactly once. Neither container's log holds the tester's addresses |
| AC 5, DP-1a to DP-1c | With both limits set to 1: an external IPv4 client's second upload gets `429` while an external IPv6 client still uploads, and a second address in that IPv6 client's /64 gets `429`. | AC 6, DP-16, DP-17 | On a clean checkout on any Linux amd64 host with Docker (not the VPS): runbook self-hosting steps, `docker compose build`, `up -d`; a synthetic upload, publish and page view through Caddy; headers equal H-2; `docker inspect` shows only the data mounts. | AC 8, 10, DP-8 | `memory.peak` run; a fifth upload gets "try again in a minute"; no OOM kill in `docker inspect` |
| AC 7, 9, 11 | Timed rehearsal; runbook entries; provider panel and host inspected for backups |
