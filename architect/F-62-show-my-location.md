# F-62 Show my location on the map: architecture

- **Version:** 0.1
- **Status:** accepted (21 Nov 2026). Critical lane, QA at effort high. No open points
- **Feature:** [`features/F-62-show-my-location.md`](../features/F-62-show-my-location.md); decisions of 20 Nov 2026, OQ-285 to OQ-290
- **Requirements:** AP-25, AP-3, AP-15, AP-19, SH-5, SH-12, DS-6, DS-7, INF-1, NFR Privacy, NFR Performance
- **Builds on:** [ADR-013](ADR-013-maplibre-behind-a-lazy-adapter.md) (one value importer of MapLibre, DOM markers), [ADR-015](ADR-015-map-interaction-hover-touch-nearest-sample.md), [ADR-038](ADR-038-fullscreen-map-as-css-overlay-with-a-history-entry.md), [ADR-032](ADR-032-response-headers-in-caddy.md), [ADR-011](ADR-011-activity-page-bundle-allocation.md), [F-61](F-61-satellite-map-layer.md) SL-6, SL-10, [F-13](F-13-activity-page-layout.md) D-20 (refit until moved), [F-22](F-22-caching-and-security-headers.md) H-2, H-5, [F-54](F-54-translated-interface.md) LG-3, LG-8, [F-29](F-29-about-page-and-attributions.md) AB-2. No new ADR; no format, schema, endpoint or CSP change
- **Owner:** frontend; backend only for the `Permissions-Policy` line in `deploy/Caddyfile` and its pinned Caddy check

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| LC-1 | **Two parts.** The map chunk (`map-view.ts`) creates the buttons, and only on the viewing page `/w/{id}`: the viewing glue passes one flag through the map props; edit and published owner pages pass none (OQ-287). Everything else (watch, state, dot, circle, messages) is a **new lazy chunk** `components/map/location.ts`, loaded by map-view's `import()` on the first location tap, with its pure state rules in `components/map/location-state.ts` (`import type` only, Node tests, as `map-style.ts`). The chunk imports `maplibre-gl` as types only: map-view hands over the map, the `Marker` class, the two buttons, the message slot and a callback that ends D-20's refit; it gets back only a stop function, called by its teardown | AC 55 read literally: no location code before the tap. The permission prompt follows the tap anyway, so the extra round trip is hidden. ADR-013 item "only value importer" holds. **Would choose differently if** the location chunk measures under about 0.5 KB gzip: fold it into the map chunk as F-61 SL-1 did |
| LC-2 | **Controls.** One control group, last in the top-right stack (after Satellite, ordered by `map-view.css` as SL-6): the location toggle (`aria-pressed`) and the follow button, present only while location is on (`hidden` otherwise; its pressed look is the engineer's call). Inside the map container, so also in the fullscreen map (ADR-038) and never without a map (AP-3). Labels from the map text group, relabelled on a language change like the Satellite toggle | AC 41, 54; OQ-285, OQ-288 |
| LC-3 | **States.** `off` → tap → `starting` (watch running, no dot, no follow button) → first fix → `on` with `following` true. In `on`, a fix redraws; it centres only while `following`. Follow tap: centre on the last fix, `following` true. Location tap in `starting` or `on`: watch cleared, markers removed, the last fix dropped, camera untouched, `off`. The camera is moved **only** by the first fix after a tap, a follow tap and a fix while following; the pure rules make that a table check | AC 43, 45 to 47 |
| LC-4 | **Viewer move = a MapLibre `movestart` or `zoomstart` that carries `originalEvent`**; it sets `following` false. The same rule as F-13 D-20. Checked in maplibre-gl 6.14.0: touch, mouse, wheel and keyboard handlers and the zoom buttons (`NavigationControl` passes `{ originalEvent }`) carry it; a resize (ResizeObserver entries as event data) and our own `jumpTo`/`easeTo` do not. A gesture during an animated centring still fires its own `movestart` (the handler manager tracks its gestures separately from camera animations) and stops the animation. Our moves never pass event data that imitates a viewer. Not viewer moves, so follow stays on: a route scrub (MapLibre never sees it, ADR-015), a one-finger drag blocked by cooperative gestures, a resize. `jumpTo` or a short `easeTo` for follow updates and the zoom on turning on are the engineer's call; no `flyTo` | AC 44 |
| LC-5 | **Refit and resize.** The first centring calls map-view's callback, which ends D-20's "refit until moved", so rotation, the pin layout or entering and leaving fullscreen never refit the route over the position. MapLibre's resize keeps the centre, so a followed position stays centred with no extra rule | AC 56; feature assumption on fullscreen |
| LC-6 | **Drawing: two DOM markers** (dot and accuracy circle, circle below the dot), as the cursor marker (ADR-013) and as MapLibre's own geolocate control does. The circle's CSS size comes from the reported accuracy and the metres per pixel at the position's latitude and current zoom, updated on every fix and on `zoom` while location is on. Both have `pointer-events: none`: route hover and scrub only hit when the canvas is the target (`map-view.ts` `hitAt`), and pin taps must pass. Colours are theme tokens in CSS, with a Satellite override if needed (SL-10); no colour literals. Not a GeoJSON layer: every `setStyle` (scheme, Satellite) would drop or need to re-apply it, and each fix would cost a worker round trip. **Not MapLibre's `GeolocateControl`:** its one-button cycle (a tap in background state re-centres instead of turning off) contradicts OQ-285's two buttons, it disables itself after a denial and ignores page visibility; bending it costs more than LC-3 | AC 43, 56; DOM markers survive style swaps and cost nothing per scrub frame |
| LC-7 | **Geolocation use.** Only `watchPosition`, only after the tap, `enableHighAccuracy: true` (walking a route needs GPS); `timeout` and `maximumAge` are the engineer's call. At the tap: `isSecureContext` and `navigator.geolocation` checked first. No `getCurrentPosition`, no `navigator.permissions` query. At most one watch at any time, also for repeated taps while the chunk loads | AC 42, 49 |
| LC-8 | **Errors.** Before the first fix, any error (denied, unavailable, timeout, insecure, no API, chunk import failed): one message, `off`, map unchanged. After the first fix: a denial turns location off with the message; unavailable or timeout keeps it on with the last dot and the watch, message once per turning on. The message is one element in the map box (visible in fullscreen), `role="status"`, clears itself; our text only, never the browser's `error.message`, nothing logged | AC 49 |
| LC-9 | **Lifecycle.** `visibilitychange` to hidden: watch cleared, state, `following` and dot kept; visible again: a new watch without a tap (feature assumption). `pagehide`: fully `off`, so a back-forward-cache restore starts off like a reload. Map teardown: fully `off`. Fullscreen needs nothing: same map, same controls (LC-4, LC-5) | AC 48; ADR-038 |
| LC-10 | **The position has no exit.** It lives only inside the location chunk: no export, no event, no store, no getter on `RouteMapHandle`, never passed to the cursor, selection, range link, pins or `basemap.ts`. The two location modules use no network, storage, URL, history, messaging or console API and do not import `lib/prefs`. `basemap.ts` (SH-12) and the owner glue never import them; SH-5 is drawn on the server from the data file. The only accepted exposure is the tile requests for the centred area (feature constraints, About) | AC 50, 51; NFR Privacy |
| LC-11 | **Header.** `Permissions-Policy: geolocation=(self)` joins the deferred `(security)` snippet in `deploy/Caddyfile`, so every response carries it: pages, assets, data files, `/api/*`, `/about`, and `handle_errors` (which imports the snippet). Exactly this value, no other feature (clipboard stays unrestricted, F-22 H-5). The H-12 Caddy check pins the exact value on each response kind. CSP unchanged: geolocation is not governed by CSP, and no host or script hash is added. Local development needs no header (the default allowlist is `self`; `localhost` is a secure context) | AC 52; OQ-289 |
| LC-12 | **Texts.** Button names, follow name and messages in the map text group (`map-texts.ts`), so in the map chunk and its language files (LG-3, ADR-011 decision 6 R-2), within 5 KB gzip each. The About sentence is template text (AB-2: the engineer drafts, the user owns the wording) with `data-t` keys in de, es and fr (LG-8). No text on the viewing page itself (OQ-290) | AC 53, 54 |

## Cost

| What | Limit |
| --- | --- |
| Activity entry (static) | **Ceiling 50 bytes gzip** (the viewing-page flag through the map props); reserve 1,719 → 1,669, above the review trigger, so no ADR-011 decision. Above 50: stop and report. The measured row is added to ADR-011 item 4 at QA close |
| Map chunk | About +0.4 KB gzip (control group, CSS, `import()` call site, texts); reported |
| Location chunk | About 1.5 to 2.5 KB gzip, not counted; reported (LC-1 trigger) |
| LCP | Unchanged: no request and no Geolocation call before the tap |
| Scrubbing | 60 fps on the 12-hour ride with location on: markers are outside the scrub path, a fix costs one map render |

## Verification (besides the acceptance criteria)

| What | Check |
| --- | --- |
| No exit, structurally | A source check over the two location modules fails on any of: `fetch`, `XMLHttpRequest`, `sendBeacon`, `WebSocket`, `EventSource`, `localStorage`, `sessionStorage`, `indexedDB`, `cookie`, `history`, writes to `location`, `postMessage`, `console`, an import of `lib/prefs`. Review: nothing position-bearing crosses the LC-1 seam back to map-view |
| No exit, at run time | jsdom with a fake geolocation and spies (AC 42, 48, 50); and QA in a real browser with an emulated, moving position, also in fullscreen and after hide and show: network log shows only the tile hosts and the location chunk's `/assets/` request without a query; no cookie set; storage empty; URL unchanged; console empty |
| Mutants | Each must fail a check: the position written to storage or `lib/prefs`; a console call in an error path; centring on a fix while not following; a resize ending follow mode; the watch kept while hidden; the buttons on the edit page; a second feature in `Permissions-Policy`; `basemap.ts` importing a location module |
