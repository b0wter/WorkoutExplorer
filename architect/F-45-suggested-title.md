# F-45 Suggested title: architecture

- **Version:** 0.1
- **Status:** accepted (11 Nov 2026). Critical lane. OQ-162, OQ-163 open (below), neither blocks the code
- **Feature:** [`features/F-45-suggested-title.md`](../features/F-45-suggested-title.md); rules in UP-5, decision log OQ-154 to OQ-161
- **Requirements:** UP-5, UP-4, SH-4, SH-5, SH-9, SH-10, UP-6 (phase 2), UP-7, AC-4, AP-12, INF-1, DS-3; NFR Privacy, NFR Performance; invariants I-3, I-5
- **Builds on:** new [ADR-045](ADR-045-place-data-vendored-and-embedded.md); [F-16](F-16-start-and-end-hiding.md) H-4, H-7, FE-1; [ADR-030](ADR-030-to-be-hidden-ranges-computed-at-upload.md); [ADR-028](ADR-028-public-files-rebuilt-whole-page-as-commit-point.md); [ADR-026](ADR-026-activity-page-template-adopted-not-hydrated.md); [F-19](F-19-edit-page-and-settings.md) E-5 to E-7; [F-42](F-42-multisport-sections.md) MS-1, MS-2; [F-29](F-29-about-page-and-attributions.md) AB-5. No migration, no setting, no data file format change
- **Owner:** both. Backend first (ST-1 to ST-6, ST-9), then frontend (ST-7)

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| ST-1 | **Place data: a vendored GeoNames snapshot, embedded with `go:embed`** (ADR-045). One UTF-8 TSV in `src/server/internal/places/`: `name`, `latitude`, `longitude`, copied verbatim from `cities15000.txt` columns 2, 5, 6 in upstream order, plus a short source note beside it (download date, URL, licence, the exact projection command). Ceiling 1.5 MB. Refreshed by hand, rarely; `make ci` never downloads it. `make ci` checks the table: it parses, more than 20,000 rows, valid UTF-8 names without Cc or Cf characters, coordinates in range, and the longest possible suggestion stays within UP-4's 100 code points | Upstream has no versioned URL, so a build-time fetch cannot be pinned. A snapshot gives offline, reproducible builds and reviewable refreshes. The check runs where the third-party text enters, at refresh, not at runtime |
| ST-2 | **Lookup: new pure package `internal/places`**, standard library plus `workout` (its R-6 haversine, exported, so the radius has one home). An immutable index, built once per process on first use (`serve`, `regenerate`). Nearest town to one point by haversine; within **25,000 m inclusive**, else none; ties go to the earlier table row. Linear scan, no allocation per lookup. *Shortcut:* no grid or k-d tree; add one only if a lookup measures above 2 ms on the server. If the table fails to load (a defect `make ci` catches), the index reports "unavailable", logged once without data | Decision log OQ-159, AC 36 (25.0 km gets the town, 25.001 does not). Determinism keeps ADR-028's "same inputs, same names". About 30,000 haversines take about 1 ms, so a spatial index is not worth its code yet |
| ST-3 | **Wording is assembled in `internal/page`** (pure; no place data). Input: the data file metadata plus a town or none. Time of day from `start_time` and the workout's offset, UTC when unknown, no word without a start time (UP-5 boundaries). Sport word: for a workout with sections (F-42 MS-1), "triathlon" when its non-transition sessions, in MS-2 order, are exactly `swimming`, `cycling`, `running`; otherwise "multisport". For any other workout, the page's sport name in lower case. Then " near {town}". First letter upper case ("Ride near Köln"). Always non-empty | One home for every English word and sport name (DS-3), next to `DefaultTitle` |
| ST-4 | **Which point, public side: the first positioned sample of the public data file as written.** `publish` takes it from the decoded public file `f` that the page is built from (`internal/publish/publish.go:394`), after the public transform (hiding now, trim and privacy zones when built). It never reads `w` before the transform, `draft.bin` or `original.fit` for this. No position columns (indoor, pool swim, fully hidden) → no town | SH-4, F-16 H-7: geometry follows the cut. The town is derived only from a position that is already public, so it reveals nothing the route does not |
| ST-5 | **Delivery, public side: one view-model input, no stored or encoded value.** `page.Settings` gains the suggestion (string, `""` = none), filled by `publish` (empty when places are unavailable). `page.Build` uses it instead of `DefaultTitle` when the title is empty, so header, `<title>`, the Open Graph card and the preview image (F-23, drawn from the view model) all show it. Not in the data file (ADR-005 item 7 holds), not in the row. Every build computes it again (ADR-028 item 2), so hiding changes reach it by the existing rules: off → on is remove-first, on → off and a cleared title rebuild in place, regeneration likewise | UP-5 "worked out again whenever the page is built", AC 35 within SH-10 with no new code path. Store as little as possible (UP-7, AC-4) |
| ST-6 | **Delivery, owner side: read-only `suggested_title` in the settings object** (`GET`, `PATCH`; F-12). `""` = none. A `PATCH` that sends it gets `400`, like every read-only field. Computed per request from `draft.bin`: its metadata, and its first positioned sample outside ADR-030's `hide_ends_ranges` when the **stored** `hide_ends` is on (any positioned sample when off; `[[0, N−1]]` → none). Reads the header, the metadata and the two position columns only up to that sample: memory does not grow with the sample count, no parse, no parse slot, no lock. A read or decode failure gives `""` and never fails the request (F-19 E-5). Owner-only | The edit page needs the placeholder before publish, and the browser has no place data. ADR-030 rejected a parse or a full decode per owner read; the stored ranges equal the public cut sample for sample, and both files quantise positions the same way, so the result equals ST-4's. If they ever differ, the public build decides what is public; this is a display (F-16 hand-off to F-19) |
| ST-7 | **Edit page (frontend):** `lib/page` takes the suggestion as an input setting, as it takes `routeHidden` (F-16 FE-1); `""` → `defaultTitle`. Header, `document.title` and the title field's placeholder use that one value; the field stays empty and the panel never sends it. It follows the saved settings and updates from the save response (F-19 E-6), not from an unsaved hiding toggle. One new page sample with the suggestion set (ADR-026 contract). Owner chunk only; the viewing page reads the server markup and gets no code: static share **0 bytes** (ADR-011 unchanged; the engineer confirms the entry line) | UP-4, UP-5, AC 31, AC 39 |
| ST-8 | **Privacy rules for the town.** The town and the suggestion are location-derived: under I-5 they are never logged (places, publish, the owner read, regenerate). Town names are third-party text: printed as text only (template escaping, TS text nodes, ADR-026); the preview draws them as it draws a typed title. No coordinate or town leaves the server; `places` has no network code | AC 34, AC 38; NFR Privacy |
| ST-9 | **Cost.** Index heap at most 4 MB, constant, per process; the engineer reports the measured figure (it adds to the baseline under F-31's container cap). One lookup per public build and per owner settings read. Upload, data file, page size and LCP unchanged. The binary grows by about the table's size | NFR Performance, AC 41 |
| ST-10 | **Attribution, same change:** one entry in `src/server/tools/attributions/sources.json`: GeoNames, CC BY 4.0, the GeoNames link, a line saying town names are reduced to name and position (CC BY's "indicate changes"); no origins, since nothing contacts GeoNames | INF-1, F-29 AB-5, AC 40 |

**Not changed:** data file format and goldens, database schema, settings, Caddy and CSP, the viewing page's scripts, the Pushover message (never a title), `page.RowTitle` on the operator's delete confirmation page (OQ-163).

## Verification (critical lane)

| What | Check |
| --- | --- |
| AC 34 | A test table with towns A and B; hidden start next to A, first public point nearer B → B. With hiding on, A's name appears in no public file (page, data file, `.br`, preview) and not in `suggested_title` |
| Agreement | Every synthetic corpus file and F-16's generated tracks, hiding on and off: `suggested_title` equals the public page's title with an empty title |
| AC 35 | Published workout, hiding off → on: page, `og:title` and preview change in the remove-first build; no file under `public/` keeps the old town |
| AC 32, 33, 36, 37 | Pure tests in `page` and `places`: boundaries, offset vs UTC, no start time, 24.9 / 25.0 / 25.1 km, indoor, fully hidden, triathlon vs other multisport |
| Storage | Schema unchanged; byte scan of `workouts.db` (with `-wal`) finds no town name |
| Mutants | Each must fail a test: the town from `draft.bin` sample 0 or from `w` before the transform; owner ranges ignored with hiding on; `<` for `≤` at 25 km; server zone or UTC instead of the workout's offset; the suggestion written into the title field or the row; `DefaultTitle` used while places are available |
