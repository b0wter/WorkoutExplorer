## Decisions

| # | Decision | Why |
| --- | --- | --- |
| PC-1 | **The preview is a P-4 artefact rendered from the decoded public data file**, the same `datafile.File` the page is built from, plus the card strings of PC-3. The renderer never receives `workout.Workout`, the record or `original.fit`. Route, bounding box and the "has GPS" choice come from that file's positions only (F-16 H-7): hidden ends are absent, and the box does not reach into them. A file without position columns (indoor, fully hidden) draws no route and no hint text | I-3 by construction: the image can only show what the public data file already publishes. One formatter, one projection input, no second hiding path |
| PC-2 | **New pure package `internal/preview`**: `datafile.File` + card strings → PNG bytes. No I/O, no clock, no map-order dependence, so the bytes are deterministic. `publish` is its only caller. Name `preview.{hash}.png`, `{hash}` as P-5 (first 16 hex of SHA-256 of the PNG bytes), so F-22 H-6 caches it `private, immutable`. Library, fonts and limits: ADR-033 | Same artefact rules as the data file (ADR-028 items 2, 3). Determinism keeps a lifetime or description save from writing a new image |
| PC-3 | **Card content (SH-5).** Name: the page title (`Page.Title`, so an empty title gives the sport-and-date default). A sport icon (simple drawn: run, ride, swim, walk/hike, generic) in front of the name. Values, from `internal/page`'s formatted summary strings, metric (README assumption 7): distance only when present and above zero; moving time, or elapsed time when the public file has no positions; elevation gain only when altitude was recorded and gain > 0; pace min/km for run/walk/hike, speed km/h for rides, pace per 100 m for swims (only with distance); **average** heart rate only when present (never the "Max" fallback of `pair`). No other value, no units switch, no site name | The user's choice (decision log 15 Oct, OQ-28; 31 Oct, OQ-91). The page already formats these strings; the card selects, never computes (ADR-026 item 3) |
| PC-4 | **Name in the image**: cut to N code points plus "…", and cut further until it fits its box. N = 40 (OQ-91). Characters the fonts cannot draw are dropped in the image only; nothing left → default title (OQ-92). `og:title` carries the full title, uncut | Feature scope. Messengers cut `og:title` themselves |
| PC-5 | **Layout constraints** (look is the engineer's, reviewed by the user, OQ-91): 1200 × 630, plain light background, fixed colours (no dark variant), route in the page's light route colour. Name and values stay inside the central 1200 × 600 band (X crops to 2:1). Square thumbnail crops (small previews) may cut the values; the text tags carry them. Degenerate routes (one point, all points within a few metres) render without error at a minimum span. Under 300 KB for every synthetic corpus file, `ride-12h` included | TD Indexing (WhatsApp skips larger images). Card renders in all five messengers (SH-5) |
| PC-6 | **View model group `Card`** `{Title, Description, Image}`, built in Go only (`internal/page` gains the base URL and preview name as settings). `Description`: the PC-3 values as "Label value unit" joined by " · ", e.g. "Distance 42.3 km · Moving time 1:23:45 · Elevation gain 310 m · Avg speed 30.1 km/h · Avg heart rate 142 bpm". `Image`: `{base URL}/w/{public_id}/preview.{hash}.png`. **Not in `lib/page`:** the samples carry a fixed placeholder `Card`, and the Go sample comparison skips that group; Go tests cover it alone (one-line note in ADR-026) | No TypeScript renderer shows the card, so there is no cross-language drift to guard (ADR-026 item 2's reason), and no bundle bytes |
| PC-7 | **Template tags (FE-1, `src/web/index.html`)**, right after the `viewport` meta, before the preload and the module script: `og:title`, `og:description`, `og:image`, `og:image:width` 1200, `og:image:height` 630, `twitter:card` `summary_large_image`. Values printed from `Card` only. The `og:image` content ends in `/preview.{hash}.png` followed by `"`, so ADR-028 item 5's sweep keeps the file; a build-then-sweep check confirms it | WhatsApp reads only the start of the document. Without the plain-path link the sweep deletes the image within a minute |
| PC-8 | **Base URL setting `WORKOUT_EXPLORER_BASE_URL`**: scheme `http` or `https`, host, optional port; no path, trailing slash, user info, query or fragment; must parse with `net/url` and re-serialise to the same string. **Required, no default:** unset or invalid → exit 2 before the data directory is touched. Read in `settings.go` by every subcommand that runs the public build (`serve`, later `regenerate`). `make dev-server` and the F-22 check pass a local value; production is `https` (F-31) | ADR-020 item 8 deferred it to here. A default would publish wrong absolute links silently (the P-10 reasoning) |
| PC-9 | **Owner-page card (SH-11, FE-1, `src/web/edit.html`)**, which Caddy serves for both `/edit/*` and `/published/*`: `og:title` "Edit link: do not share", `og:description` "Anyone with this link can change or delete this workout.", `twitter:card` `summary`. Byte-constant, so identical for every workout, draft or published. **No image**: a static file cannot hold an absolute URL without the deploy's base URL, and a text card carries the warning. No `og:url`. The `<title>` stays | SH-11. The token is in the fragment, so no fetcher ever sees it; the file has no workout input at all |
| PC-10 | **Draft and expired: nothing to build.** No folder exists for a draft; an expired or deleted workout has none either, and Caddy answers the generic page (F-15 P-12: no OG tags, `404`). A remove-first build deletes the old preview before any new one is written, and the new name is unknown until `index.html` links it | SH-5, README assumption 3. SH-10 holds with the folder: delete, expiry and hiding on remove the image as they remove the data file (F-22 H-11) |
| PC-11 | **Indexing.** No `robots.txt`: Caddy's catch-all answers `/robots.txt` with `404`, which RFC 9309 treats as "allow everything", so `/w/` is never disallowed and Twitterbot may fetch pages and images. The robots meta already sits in `index.html`, `edit.html` and `generic.html`; `X-Robots-Tag` is F-22's (H-8, OQ-89). F-23 adds nothing here | No file to keep in sync. A file whose only content is "allow all" adds bytes and a route for no effect |
| PC-12 | **No CSP change.** Meta tags are not governed by CSP, and no page shows the preview; crawlers fetch it directly. No external fetch at render time: fonts are embedded (ADR-033), no tiles behind the route (out of scope) | ADR-032 unchanged; I-6 |

**Consequences.** A title save now writes the page **and** a new preview (the name is in the image); a description or lifetime save still writes only `index.html`. Each build holds one 1200 × 630 RGBA image (about 3 MB) and one PNG encode (tens of ms) outside the public lock.

## Verification (critical lane: QA at effort high)

Synthetic files only (ADR-004).

| AC | Check |
| --- | --- |
| 1, 2, 3 | Render every synthetic corpus file: 1200 × 630, under 300 KB, deterministic (twice equal). Indoor without HR: no distance or HR value, elapsed time shown. Fully hidden: values only, elapsed time |
| 3 (hiding) | With hiding on, every point the renderer receives is a public position of the hiding-on data file; the hidden-ends route's box is smaller than with hiding off. Visual comparison by the operator for one file |
| 4 | `index.html` has every PC-7 tag, an absolute image URL from the setting, the full title HTML-escaped. Build then sweep: the preview survives; an unlinked preview is removed |
| 5 | `/robots.txt` through Caddy answers `404` (F-22 H-12 check gains one request) |
| 6 | Draft and expired links through Caddy: generic page, no `og:` and no `preview` in the body |
| 7 | `edit.html` and `/published/*` through Caddy return the same bytes for two workouts and a draft; tags as PC-9; no 22-character base62 string, no workout value |
| 8, 9 | Manual, by the operator: WhatsApp, Signal, Slack, Telegram, X, on a deployed instance |
| Mutants | Each must fail a check: preview from the parsed workout before the transform; box from the full route; `Max heart rate` used as average; distance `0` shown; image not linked by path; `BASE_URL` with a trailing slash accepted; a workout field in `edit.html` |
