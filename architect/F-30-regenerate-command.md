# F-30 Regenerate command: architecture

- **Version:** 0.2 (RG-13: QA-30-r1-6; history in [history/F-30-regenerate-command.md](history/F-30-regenerate-command.md))
- **Status:** accepted (4 Nov 2026). Critical lane: it deletes workouts and rewrites public files
- **Date:** 4 Nov 2026
- **Feature:** [`features/F-30-regenerate-command.md`](../features/F-30-regenerate-command.md); "AC n" below is the n-th acceptance criterion there
- **Requirements:** SH-10, UP-7, AC-4, NFR Reliability, NFR Operations, NFR Privacy; TD Workout data file (Versioning), Hosting and operations (Deploys); invariants I-3, I-4, I-5
- **Builds on:** [F-09](F-09-upload-api-and-storage.md) F-30 hand-off (outcome rule, raised `MaxBytes`, parse time limit), [F-15](F-15-publish-pipeline-and-static-page.md) P-6, P-7, P-14, [F-19](F-19-edit-page-and-settings.md) E-5, [F-21](F-21-lifetime-and-expiry.md) X-1 and its F-30 hand-off, [F-27](F-27-reports-api-and-operator-delete.md) R-8, R-10, [F-31](F-31-server-deploy-and-monitoring.md) DP-8, DP-10 and its F-30 hand-off; ADR-005 item 9, ADR-017, ADR-018, ADR-019 item 9, ADR-022, ADR-023, ADR-028, ADR-030, ADR-031 (settles QA-15-r2-1 for this process too), ADR-032 item 3, ADR-034, ADR-035
- **Owner:** backend (Go and `deploy/`). No front-end change. No migration. No new setting
- **Out of scope:** the export file (F-24, phase 3; its DL-9 needs nothing more from here)

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| RG-1 | **Command.** `workout-explorer regenerate -data <dir> -web <dir>`, both required as for `serve` (`-web` gives the page template). It reads only `WORKOUT_EXPLORER_PARSE_TIMEOUT` and `WORKOUT_EXPLORER_BASE_URL`, with `serve`'s checks (invalid: exit 2 before touching the data directory). It opens an **existing** `workouts.db` only and **refuses a schema version other than the binary's** (no migration; `serve` migrates at start; F-27 R-8). It never runs `Recover`. One parser for the process, with `MaxBytes` raised by ADR-023 item 7's growth (F-09 hand-off), used for both `Accept` and the public build. In production: `docker compose exec -T app /srv/workout-explorer/bin/workout-explorer regenerate -data /srv/workouts -web /srv/workout-explorer/web`, so it gets the same env file, mounts and cgroup as `serve` | Same limits and template as the `serve` it runs beside (ADR-017 rev. 7). A stored original must never be refused for a size our own strip produced |
| RG-2 | **Which workouts.** Every row that is live by F-21 X-1 when the run starts, drafts included, **one at a time**. Before each, the row is read again: gone or due → skipped (expiry deletes stay `serve`'s) | Feature scope "skips workouts that expire during the run"; one rule for "live" |
| RG-3 | **Outcome comes from `Accept`'s error only**, by the F-09 hand-off table (v1.9): rejected by the file → **delete** through `lifecycle.Service.Delete` (row with reports, `public/{public_id}` under the ADR-031 lock, `private/{id}`), the F-12 O-10 line with `by=regenerate`; `canceled`, `limit`/`time` or any non-`ingest` error → **kept**, nothing written. Any error after `Accept` succeeded (writes, encode, preview, page) is server-side → kept. The device model comes from `ingest`'s own rejection line (ADR-018), with `id` added through `logger.With`; never the `public_id`, coordinates or a path | One delete routine (I-4). The public build still never deletes (P-14) |
| RG-4 | **Commit order of a rebuilt workout.** Compute everything in memory first (`Accept`, `draft.bin`, the derived row values including ADR-030's ranges from the same function the upload uses). Then: **(a)** private files through `privatedir`: `original.fit` only if `Accepted.Original` differs, then `draft.bin`; temp file and rename, **only into an existing `private/{id}`, never creating it** (F-21 hand-off 4); **(b)** the row's **derived columns only** (`sport`, `start_time`, `time_zone_offset_s`, `summary_json`, `data_end_s`, hidden ranges), in one statement that changes nothing when the row is gone or no longer live; settings columns are never written; **(c)** the public build when unlisted (RG-5). Each file and the row is atomically old or new. A failure at any step counts the workout as kept; the next run redoes all of it | A full disk fails at (a), so the workout is unchanged (AC 6). Public last keeps the old page and its old bundle whole until the new page commits. If (b) or (c) fails, the private side is already new: the edit page reads it with the current bundle, which is better than before; the next run converges |
| RG-5 | **Public build against `serve`'s concurrent saves** (F-21 hand-off 2). The build goes through `publish`, so it takes the ADR-031 lock with no extra code. **Inside the lock, before its write phase,** `publish` reads the row again. If it differs in any field from the record the build used, or is gone or not live, nothing is written: the newer row was written by the restarted `serve` (new binary, new template), whose hook builds or has already built from it. P-6's post-build re-read stays. **Constraint:** no process waits for the public lock while it holds an SQLite write transaction (true today: rows commit before hooks and removals) | A stale, less hidden page can never overwrite a newer one (SH-10, privacy). Skipping instead of rebuilding avoids a second build that `serve` already does |
| RG-6 | **`publish.HidesMore` allow-list** (F-15 P-7, edited there) gains the fields derived from the original that the public build never reads: `Sport`, `StartTime`, `TimeZoneOffsetS`, `SummaryJSON`, `DataEndS`, `HiddenRanges`. Regenerate builds with before = the row as read and after = the row after (b), so a run is always an in-place rebuild. A later feature whose public build starts reading one of these fields must take it off the list | Otherwise every regenerated workout, and every owner save that races a run, is remove-first: the generic page for up to a second, on every page, on every deploy |
| RG-7 | **Stopping.** SIGINT or SIGTERM cancels the context: the parse in progress ends `canceled` (kept), commit steps the current workout has begun run to the end (`context.WithoutCancel`, as ADR-022's row insert), no further workout starts, the report is printed, exit 1. A kill leaves each file and the row old or new (RG-4), and files from a stopped public write are removed by `serve`'s sweep (ADR-028 item 5) | AC 7 |
| RG-8 | **Report, logs, exit.** The run ends with a report: counts `rebuilt`, `deleted`, `kept`, `skipped`, and the RG-9 asset names. Log lines stay slog JSON; the engineer keeps them separable from the report so `deploy.sh` reads the report with POSIX tools only. Under `exec`, log lines reach the deploy's output, not Docker's log; accepted. Exit 0 when the whole list was processed, whatever was deleted or kept; 1 when it could not start or did not finish; 2 on usage or settings. After a run that deleted anything, one WAL checkpoint (ADR-019 item 9); busy is fine, `serve`'s every-pass checkpoint covers it (F-27 R-10) | "Failures never stop the deploy" (feature scope); the counts are the operator's signal |
| RG-9 | **Assets still in use.** After the run, regenerate lists every `/assets/{name}` that any `public/*/index.html` references (byte match as ADR-028 item 5). No lock: every page written since the restart names only the current bundle, so the scan can only over-keep. Drafts have no page; the edit page always uses the current bundle | Kept workouts are found from what is served, not from the run's bookkeeping, so an owner save or a delete in between cannot make it wrong. `app` cannot write `web/` (read-only mount, F-31), and the `deploy` user cannot read `public/`, so the scan is regenerate's and the removal is the deploy's |
| RG-10 | **Bundles and their removal** (OQ-55, ADR-005 item 9). A **bundle** is the set of file names in one release's `web/assets/`, taken from the release tarball. `deploy.sh` stores it as `/srv/workout-explorer/bundles/{tag}` before copying (outside `web/`; no container mounts it). Files already in `web/assets/` when the first list is written form one list of their own (the releases before F-30). **Clean-up, only after a regenerate exit 0:** keep the current release's list and every list that contains a name from RG-9 that is not on the current list (content hashes; QA-30-r1-1); remove every other file in `web/assets/`, then the lists with no file left. After a non-zero exit nothing is removed | A page names only its entry script and stylesheet; the chunks it loads lazily (map, worker, owner, report form) are named only inside JavaScript. Keeping whole releases is exact without parsing JS. Shared names across releases are kept by the union |
| RG-11 | **Deploy order** (replaces F-31 DP-10 item 5, edited there): …restart `app`, health wait, HTML entries, then **regenerate, then clean-up**, then one summary: rebuilt, deleted, kept, bundles removed. `deploy.sh` exits 0 when the new version is healthy and regenerate exited 0, whatever was deleted or kept. If regenerate did not finish, the version is still live, nothing is removed, and the script exits with a code other than the health failure's. **Retry,** for a failed run or kept workouts: run `deploy.sh` again with the same tag (idempotent; it costs one `app` restart). Self-hosters run the same `exec` after `docker compose up -d`, with no clean-up (F-31 hand-off; OQ-96) | Between the restart and the end of the run (seconds), published pages serve their old files with the old bundle, which is still on disk (DP-10 copies assets additively) |
| RG-12 | **Kept workouts in `serve`** (feature open points). **Owner save:** unchanged. ADR-028 already rebuilds the whole public side at the current version, and the private side stays old until a run. No rebuild-on-edit is added: no reader mixes the two sides, because the page reads only public files and the edit page reads only `draft.bin` and the row, which stay old together. **Kept workout on the edit page after a format bump:** F-19 E-5 applies as built: the load-error text, with the panel, publish and delete still working, until a run rebuilds it or it expires | No new code. The feature's suggestion (rebuild on edit) would add a second private-write path to `serve` for a rare state |
| RG-13 | **Memory, time, storage.** One workout at a time inside `app`'s cgroup (exec): it adds one `Accept` (A, ADR-017), one preview render and at most one compression to `serve`'s peak, about 365 MB max RSS on the published all-caps file (QA-30-r1-6). **Not added to the cap** (ADR-017 rev. 8): DP-8's cap stays sized for `serve` alone, and the worst case (a deploy during 4 uploads at the caps, about 1.34 GB) ends in an OOM kill inside the cgroup, recovered as below. No VPS memory measurement is needed for regenerate, before or after the first deploy; after each deploy the operator checks `docker inspect` for `OOMKilled` (ADR-017 rev. 8 says what then). Regenerate keeps no storage total, so `serve`'s total drifts until its next start (accepted, as F-27 R-10; a run's net change is about zero). **Trigger:** if AC 10's 100-workout run takes more than 30 s on the VPS, run two at a time (the parser's two slots); that adds a second A to the overlap, so it comes with ADR-017 rev. 8's cross-process slots | 2 GB VPS. An OOM kill can hit `serve` (PID 1) and end the run; that is an interrupted run (RG-7), and the retry is RG-11 |
| RG-14 | **CSP hash of the inline theme script** (ADR-032 item 3). A release that changes the script keeps the old hash in `deploy/Caddyfile` too, because Caddy reloads before regenerate runs. The old hash is dropped only in a later release, and only if the previous deploy reported `kept=0` and regenerate exited 0 | Otherwise old pages lose their theme script while they are still served |

**What picks up a new release, and when** (settles the CONTINUE reminder; nothing else holds the old template):

| Output | Made from | Picks up the new release |
| --- | --- | --- |
| `public/{id}/index.html`, data file and `.br`, preview | template, binary, `BASE_URL` | regenerate, or an owner save in the restarted `serve` |
| `draft.bin`, `original.fit` (wider strip), derived row columns, ADR-030 ranges | binary | regenerate only |
| About page | `web/about.html`, operator file | `serve` restart (F-29 AB-4), not regenerate |
| Edit, upload and generic pages | static files in `web/` | the deploy's copy (DP-10) |

The old bundle stays referenced only by kept workouts' pages, and by pages a viewer had open across the clean-up: their lazy chunks are gone, so the map or the owner panel fails to load until a reload (accepted, a deploy-time edge).

## Verification (critical lane: QA at effort high)

Synthetic files only (ADR-004); format and template changes through test seams.

| What | Check |
| --- | --- |
| AC 1, 3 | With a bumped format version and a changed template: after one run, every live page names the new bundle and the new data file, no old file remains except for kept workouts, and `draft.bin` decodes at the new version. A second run writes no new content-hashed file and every page still works |
| AC 2, RG-9, RG-10 | `deploy.sh local` against a scratch layout: a kept page's whole release list survives clean-up and its page loads every chunk; after a later run rebuilds it, that list goes. A non-zero regenerate exit removes nothing. The first list of the pre-F-30 files is written once |
| AC 4, RG-3 | An unparseable original: row, reports, `private/{id}` and `public/{public_id}` gone (F-21 X-9 check, byte scan included); the generic page condition holds; the rejection line names the device model, and no line holds the `public_id`, a coordinate or a path; the others are rebuilt; exit 0 |
| AC 5 | A parser seam that stops earlier: kept, shorter on the page, `data_end_s` and ranges updated |
| AC 6, RG-4 | Fault injection at (a), (b), (c) and a `limit`/`time`: counted kept, never deleted; at (a) row and files unchanged; the next run rebuilds |
| AC 7, RG-7 | SIGTERM mid-run and a kill inside a commit step: unprocessed workouts unchanged, no page links a missing file, the next run converges |
| AC 9 | Settings columns byte-identical before and after; the export check waits for F-24 |
| RG-5, RG-6 | The F-21 hand-off probe: an owner hides-more save in `serve` lands between regenerate's build and its write phase; afterwards the page is the more hidden one. A plain run is in place (no moment without `index.html`) |
| Privacy | After a run, no file under `public/` has the bytes of `original.fit` (F-15 AC 10); with hiding on, no public file holds hidden data (F-16 AC 1) |
| AC 8, 10, RG-13 | On the VPS through `deploy.sh`: counts printed; 100 synthetic workouts timed, recorded in the runbook (at the first F-30 deploy, not before it); no `OOMKilled` |
| Mutants | Each must fail a test: no in-lock re-read; derived fields off the allow-list; `privatedir` creating a missing folder; delete on `canceled` or `limit`/`time`; a delete decided from the build's error; migration from regenerate; clean-up after a non-zero exit; a referenced list removed |
