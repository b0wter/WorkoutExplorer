## Decisions

| # | Decision | Why |
| --- | --- | --- |
| D-1 | **One formatting home, unit-aware.** `lib/format` owns the unit system type (metric, imperial), every conversion factor and every unit label. Each unit-dependent formatter takes the unit system as a parameter. Imperial: mi, ft, mph, min/mi, °F; swimming per 100 yd; rowing per 500 m in both systems (question 9). Distance is km or mi for every sport, swims included; yards for swim distance come with pool lengths (AP-13, AP-16, phase 2; OQ-67). Same precision rules as metric. No other module holds a factor or a unit string. Go mirrors only the metric part (F-13 D-6) | DS-1. One place to check, and the samples keep metric equal across languages |
| D-2 | **Presence never depends on units.** Which summary items and laps columns exist is decided before formatting (a conversion keeps sign and finiteness, so "pace hidden for speed ≤ 0" holds in both). A switch therefore changes text only, never the set of boxes | Makes D-5 a pure text rewrite |
| D-3 | **One units store** in a new `lib/units`: framework-free (get, set, subscribe; synchronous delivery, listener errors caught per listener as in ADR-008), plus the default rule (D-4). One instance per page, created by the page glue at start-up and passed to every consumer: components as a prop, enhancers as an argument. Memory only: no cookie, storage, URL or history state. *(29 Oct 2026, DS-1: the page glue seeds the store from a drop-down choice remembered in `localStorage` through `lib/prefs`, over D-4's default; the store itself stays memory only.)* No other module reads `navigator` for units or keeps a unit of its own. `lib/units` imports only `lib/format` (the type) | TD Implementation notes ("components talk through stores"). F-17, F-18, F-25 reuse it (table below) |
| D-4 | **Default from the browser language.** The first entry of `navigator.languages` (else `navigator.language`), read once at start-up. Region subtag `US` gives imperial; any other region, no region (bare `en`) or an unparseable tag gives metric (assumed mapping, question 8). Parsed by hand, no `Intl` (D-6 of F-13: engines differ) | Assumed mapping, literally. A reload returns to the default (AC 3) |
| D-5 | **Units on the server markup: rewritten in place from the data file** (ADR-027). The markup is always metric (question 7); the page is one static file for every viewer, so the server cannot choose. When the default is imperial, and on every later store change, an enhancer runs `lib/page`'s summary and laps builders with the chosen units over the **decoded data file's metadata** (`sport`, `summary`, `laps`) and writes the strings into the existing nodes through hooks: summary cells by their `Key`, laps header cells by column `Key`, body cells by position. The template gains hooks only (attributes carrying the existing `Key` strings, and a wrapper where a value is a bare text node); the view model and the samples do not change. Text only: no element is added, removed or replaced. A markup that does not match the builder's keys and counts is a defect: the enhancer leaves it untouched and logs to the console. The edit page gets the same enhancer over its components' markup, which carry the same hooks (F-13 hand-off, "one code path") | The data file is the source the server built the markup from (F-13 hand-off to F-15), the bundle already loads it, and the builder is the one the samples hold equal to Go. No second contract |
| D-6 | **Before the bundle, and on failure.** JavaScript off: metric throughout, no drop-down, theme still correct (D-9). JavaScript on: an imperial viewer sees metric until the data file is decoded, then one swap (accepted, question 7). If the data file fails to load, the page stays metric and gets no drop-down; nothing else on the page shows units then | The data file is preloaded in the head and arrives in parallel with the bundle, so the extra wait is small |
| D-7 | **No layout shift from a swap.** A swap never changes a box height: summary value lines and laps cells never wrap. Summary cells are grid cells sized independently of their text (F-13 hand-off). Laps column widths may change by the text difference; at load the laps are below the first viewport in both layouts, and a switch by the viewer is user input. The swap writes text into nodes already painted, so it creates no new LCP element | F-13 AC 7 (CLS 0). Checked by the Lighthouse re-run F-13 already plans (Lighthouse emulates `en-US`) |
| D-8 | **Drop-down: a bundle-only control in a reserved header slot.** Never in the template as a control (ADR-026 item 4). The template has an empty slot at the right end of the header, in one control group with Copy link: beside it where the header is wide (always in two columns, whose right column is at least 608 px), under it on narrow phones. CSS reserves the slot's size in both arrangements, so the control's arrival moves nothing; without JavaScript it is an empty box. The glue inserts a native `<select>` (two options) once the data is decoded, set from the store; a change sets the store. The engineer proposes the wording (OQ-63 rule). The edit page's header component has the same slot | The header is the one place both layouts share at the top, and units affect the whole page. A native select themes and works by keyboard for no bytes. Would choose differently if the user wants it reachable while reading laps: then a second, synced control by the laps (F-18) |
| D-9 | **Theme by CSS custom properties.** Every colour of the page, the charts and our map layers is a custom property in one theme block of the entry stylesheet: light values on `:root`, dark ones under `@media (prefers-color-scheme: dark)`. `color-scheme: light dark` in CSS and `<meta name="color-scheme" content="light dark">` in the head, so native controls, scrollbars and the first paint follow the system. Component styles use the same properties; no colour literal stays in components or TypeScript, apart from fallbacks for bench pages. No theme toggle (DS-4 follows the system). *Changed (user, 3 Nov 2026, DS-4): a System / Light / Dark drop-down in the header slot beside units on the activity and edit pages, remembered in `lib/prefs` (`wx.theme`, System stores nothing); a hashed inline head script sets `<html data-theme>` before the first paint, the theme block honours it, and `Look.scheme` takes it before the system listener (D-10).* The upload page gets the same theme block, CSS only, in its own entry (ADR-024); the About page gets it in F-29 (OQ-68) | Right theme on the first paint, without JavaScript, with no inline CSS (ADR-026 item 5). One home per colour |
| D-10 | **Canvas and map read the properties; one scheme listener.** uPlot and MapLibre cannot use CSS variables, so chart and map code read the computed values from their host element whenever they build a style. The glue holds one `matchMedia('(prefers-color-scheme: dark)')` listener and passes the scheme to ChartStack and RouteMap as a reactive prop (as `load` in `map-props`). No reload, no refetch, no new decode (AC 2, AC 5) | Colours stay in CSS; script only knows *when* to redraw |
| D-11 | **Charts under a units or scheme change.** Chart specs become a function of the unit system and the workout's sport. For the pace sports (workout sport, as F-13 D-4: `multisport` and unknown sports show speed) the speed chart is a **pace chart**: axis inverted (faster up), m:ss labels, a stop (speed < 0.3 m/s, `STOP_SPEED`) has no pace: a gap in the line (NaN before decimation) and '–' in the readout (OQ-66). The axis comes from the workout: moving samples slower than the 95th percentile of the moving ones clip to that bound (`chartValues`), uPlot's auto padding applies, no fixed per-sport slowest pace. The cursor readout shows the real, unclipped pace. Values are converted before uPlot sees them, so ticks fall on round numbers in the display unit (F-05 D-13). On a change, ChartStack keeps its root, the readout and the chart area with its reserved height, and recreates only the uPlot instances and the readout's field functions. The cursor store, and F-17's selection, live outside the charts and survive | AC 2 and AC 4 for charts. Recreating six uPlot instances on a click is cheap and off the scrubbing path; the reserved area means nothing moves |
| D-12 | **Dark map: OpenFreeMap `dark`.** `https://tiles.openfreemap.org/styles/dark`, verified 24 Oct 2026: only `tiles.openfreemap.org`; the same `openmaptiles` source (`/planet`), `ne2_shaded` raster, sprite and glyphs as liberty, and the one fontstack (`Noto Sans Regular`) our lap labels use; 47 layers, lighter than liberty. ADR-014's CSP, referrer and attribution are unchanged (ADR-014 rev. 3 note). The map's first style follows the scheme at load. On a change, the lazy `map-view` fetches the other style (`credentials: 'omit'`), applies it through the existing merge (our `wx-` layers kept) and re-reads our layer colours from the custom properties. Never a remount or a refit (F-13 D-20). If the style fails to load, the current style stays ("where available", question 28). RouteMap's read-once `styleUrl` prop gives way to the reactive scheme prop | AC 5 for the map. Lazy code only |

**Module boundary:** the technical design's front-end dependency rules (Code structure), with `lib/units` and the static `lib/page` builders in `src/page`.
