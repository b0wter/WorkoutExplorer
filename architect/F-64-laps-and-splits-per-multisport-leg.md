## Decisions

| # | Decision | Why |
| --- | --- | --- |
| LL-1 | **Which workouts.** MS-1 unchanged decides: two or more distinct session sports. Everything else, a ride, ride workout included, keeps today's view model, markup, enhancers and chunk behaviour | One rule in both languages; AC "single sport unchanged" |
| LL-2 | **Server markup per leg** (Go `internal/page`, `lib/page`, template, `components/page`). Under the unchanged `.laps-head` (h2 "Laps", `#laps-slot`), one container for the laps view holding **one block per section** (MS-2: every section in order, transitions included). A block carries the session's sport code as `data-sport`, an `h3` with the leg name and, when the leg has laps, its own `.laps-scroll` table with its own header, rows numbered from 1. Laps go to blocks by MS-3 (unchanged rule; a leg's laps are a contiguous slice of `meta.laps`, so the flat DOM order of all lap rows is still `meta.laps` order, L-2). **Columns per table:** each block's table is `lapsGroup(leg sport, leg laps)`, so speed or pace (OQ-300), cadence unit, which columns show, Stroke and Trigger (AP-8) all follow the leg by construction; no special case for transitions. A leg without laps: block with heading only. No laps at all (`None`): unchanged, no blocks. **Separator rows go entirely:** the `LapsSection` type, `lapSections`, `.laps-section` markup, selectors and CSS (page, sections, efforts) are removed, not left dormant. The view-model shape is the engineer's; Go and `lib/page` produce it identically, pinned by the samples (ADR-026) | Works without JavaScript and on the edit page (AC 1). `data-sport` lets the entry rebuild a table without the section rule or sport names (LL-3). One builder per table keeps one formatting home (F-13 D-6) |
| LL-3 | **Static enhancers (entry).** *Units and language* (ADR-027, LG-4): per block in DOM order, `lapsGroup(data-sport, next r laps of meta.laps)` with r = the block's row count; any count or column mismatch leaves the markup as served (today's rule). *Taps* (L-2, L-3, MS-6): within a view container, leg headings and rows form one list in DOM order; a row or heading maps to its pair by its position in that list, not by `rowIndex` (which restarts per table). Lap rows take L-2's ranges; laps-view headings stay unselectable until the sections chunk fills them through the unchanged `legs` seam. A click on a control inside a heading never selects. L-7 applies to headings as to rows. Leg names follow the language through `page/header.ts` (selector follows the headings) | Keeps `lib/sections` and `sportName` out of the entry; one tap path (LS-8) |
| LL-4 | **Leg boundaries in the browser.** The splits chunk derives legs itself from `lib/sections` (MS-2): leg *k* = `[start_k, start_k+1]` (the shared boundary sample) or *N* − 1 for the last, exactly the range its heading selects (MS-6). It does not wait for the sections chunk. **Windowed split rule:** F-18 L-4 over a sample window `[a, b]`: boundary 0 = `a`, `d0` = the first valid `d̄` in the window, the partial split ends at `b`, a tail without advance is in no split. The window `[0, N−1]` is today's rule exactly. Lives in lazy code; if `splitBounds` still sits in a module the entry bundles, move it to `lib/splits` rather than grow the entry. Trim needs nothing: the trimmed file's sessions already follow the cut (TR-5), and a trim that leaves one sport gives single-sport tables (MS-1) | No split crosses a leg (AC 2); a leg's split distances sum to the distance the range panel shows for its heading (AC 4) |
| LL-5 | **Splits view per leg** (built by `src/splits/`, same block structure and classes as LL-2, so `page.css` styles both). Sport leg: heading row (`h3` name and its drop-down), table, chart. A sport leg whose distance does not advance over its window: `h3` and "No splits", no drop-down, no chart. Transition (OQ-297): one heading "T1 · 1:12", the elapsed time of the window it selects (so text and range panel agree), no table. A section without samples (MS-2) keeps its heading, unselectable. `#laps-slot` keeps only the view switch; the workout-wide drop-down is not shown for multisport. Pairs for headings and rows go through the LS-8 seam in DOM order | AC 2, 4, 7; one CSS home |
| LL-6 | **Drop-down per sport leg** (OQ-296; changes LS-5, LS-7). List and default from the leg: its session sport, its own advance (`d̄[b] − d̄[a]`) for hiding longer presets, and the pool rule only when that session is lap swimming (PS-1) and the summary holds the shared pool length (PS-3); otherwise the sport's list (swimming → open water). A single-sport workout passes today's inputs, so its choice is unchanged. State: in chunk memory per leg, never `lib/prefs`, storage or the fragment (AP-19); every load starts on the defaults. A change rebuilds only that leg's table and chart; the selection store is untouched; a marked row is unmarked only when it was in the rebuilt table (the seam change is the engineer's, its entry cost counts). Units or language change: every built leg table is rebuilt with its own preset | AC 5, 6, 10 |
| LL-7 | **Comparison chart per table** (OQ-299; changes SC-4, SC-9). One F-51 chart under each sport leg's table, in the laps and the splits view, last in its block (outside its `.laps-scroll`); SC-3 to SC-11 apply per table with the leg's sport (pace or speed, axis, median, 2 to 200 bars, own overlay choice). None for transitions. SC-4's "no chart for multisport" is replaced by this. Single sport: one chart, as today. The enhancer's one mark notification (SC-7) is fanned out inside the chunk to the chart whose block holds the row; no second listener in the entry. Built only with its table (SC-10) | AC 13; no entry cost |
| LL-8 | **Unchanged:** which view opens (AP-8), the Lengths view (one table across the workout, PL-8), the chunk's import condition (LS-4, PL-8), no splits without JavaScript, the edit page's full recording (OQ-178). Already-published pages keep the bundle they reference (assets are additive, ADR-053); no compatibility code | Feature scope |

## Open for F-65 (not designed here)

- Leg tables take `meta.laps` as their only input, whatever produced the laps; F-65's merged laps land in the right leg by MS-3 with no change.
- Lap numbers are per-table display text, never an identifier; an edit-only control (F-65's ×) must address its lap by data (instant or index), not by the number shown.
- Columns are chosen per table, so an extra edit-page column or the trigger word "Added" fits the existing per-table rule.
