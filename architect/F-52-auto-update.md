# F-52 Optional automatic updates for hosters: architecture

- **Version:** 0.2 (16 Nov 2026; revised on top of the built F-59, old rows in [history](history/F-52-auto-update.md))
- **Status:** accepted. Critical lane. OQ-210 to OQ-217 and P-1 to P-6 decided by the user (decision log of `features/README.md`, 14 to 16 Nov 2026); open product points at the end
- **Feature:** [`features/F-52-auto-update.md`](../features/F-52-auto-update.md); "AC n" is the n-th acceptance criterion there
- **Requirements:** INF-8, INF-4, INF-1, INF-9, NFR Privacy, NFR Security, UP-7, AC-4; TD Hosting and operations (Deploys), Configuration, Security and privacy
- **Builds on:** [F-59](F-59-container-image-and-install-paths.md) IP-4, IP-5, IP-7, IP-10, IP-11; [F-31](F-31-server-deploy-and-monitoring.md) DP-10, DP-18; [F-30](F-30-regenerate-command.md); [F-29](F-29-about-page-and-attributions.md) PT-9a; ADR-019, ADR-034, ADR-039, [ADR-052](ADR-052-release-image-built-once-pushed-by-the-release-job.md). **Own:** [ADR-050](ADR-050-deploys-run-on-the-server-from-a-signed-release.md), [ADR-051](ADR-051-updater-as-host-script-verified-by-minisign.md), [ADR-054](ADR-054-rootless-podman-deploy-files-owned-by-the-service-user.md) (new)
- **Owner:** backend. Files: `deploy/update.sh` (new), `deploy/deploy.sh` (server-only, both container paths), `deploy/podman/workout-explorer-ctl` (runs as the service user), `deploy/sign-release.sh` (new, operator machine), updater units for both paths in `deploy/` (new), `deploy/minisign.pub`, `example.env`, `RUNBOOK.md`, `DOCKER.md`, `PODMAN.md`, `ci.yml`, `Makefile` (deploy archive allow-list, parse check), Go: one setting and the About block (PT-9a)

## Shape

```
Compose host                                        Rootless Podman host
system timer (root installs once, User=deploy user) user timer of the service user (linger), hoster installs once
        │ nightly          operator/hoster by hand: update.sh vX.Y.Z, as that same user      │ nightly
        └───────────────▶ {deploy dir}/update.sh ◀─────────────────────────────────────────┘
          gate → pick tag → verify manifest → fetch deploy archive, check hash → unpack
          → run that archive's deploy.sh → state, alert, log line
deploy.sh:  Compose = F-59 IP-10 steps        Podman = the archive's workout-explorer-ctl (install, restart),
            both: Caddy guard (IP-7) before anything changes; health; regenerate; exit 0, 1, 3, 4
```

One path for every deploy on both container paths (ADR-050). The installed, already verified `update.sh` does all checking; the downloaded release supplies `deploy.sh` and the files it installs, and runs only after verification. Our image arrives by the digest the signed `compose.yaml` (or Podman app unit) names; `update.sh` holds no digest logic of its own.

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| AU-1 | **Updater = POSIX shell script `update.sh`** at `{deploy dir}/update.sh` (default `/srv/workout-explorer`), installed and replaced by `deploy.sh` like every deploy file; verification by the host's distribution package `minisign` against the pinned key (ADR-051). Not part of the Go binary, which runs only inside containers | No own crypto code; trust root is the hoster's package archive, not GitHub |
| AU-2 | **Two entry modes, one code path.** `update.sh` with no argument = scheduled run (AU-6 picks the tag; acts only when the switch is on). `update.sh vX.Y.Z` = **manual deploy** of that tag, whatever the switch, the stopped state or the running version (same or older allowed). Both download, verify, lock and run the same `deploy.sh`. Manual runs are made as the path's deploy user (AU-13): the operator over SSH, a Podman hoster as the service user. `deploy.sh` has no remote mode, needs no checkout, `git` or `gh`, and is not an entry point (ADR-050) | Manual and automatic deploys cannot drift apart; lock and stopped state need one home on the server |
| AU-3 | **Release assets** as F-59 IP-5 (bare-metal tarball, deploy archive, `SHA256SUMS`), plus `SHA256SUMS.minisig`. The deploy archive's allow-list gains `update.sh` and the updater units of both paths. Container paths fetch only the deploy archive; the tarball is listed and signed but left to F-60. **Caddy:** the signature covers the minor tag name in `compose.yaml` and the Podman Caddy unit, not Caddy's bytes (user decision 15 Nov 2026); patches float, so every deploy pulls the newest patch through IP-7's guard | OQ-211, OQ-215 on the image layout. One manifest covers our digest, deploy files and Caddy's tag |
| AU-4 | **Manifest = plain `sha256sum` output**, one line per archive, nothing else. **The tag is in the signed text through the file names:** every name starts `workout-explorer-<tag>-`, and both archives are listed. `sha256sum -c` stays usable by hand | OQ-211 without a new format; a replayed manifest names its own, older tag |
| AU-5 | **Signing and publishing (OQ-212, P-2).** CI's `release` job pushes the image (IP-4 steps 1, 2) and creates the release as a **draft** (IP-4 step 3 changed); it no longer touches `latest`. On the operator's machine `sign-release.sh` downloads the draft's assets, checks the hashes, that `COMMIT` in the deploy archive is the local tag's commit and that the names carry the tag, signs `SHA256SUMS` with `minisign -S` (secret key password-protected, outside the repository directory), uploads the signature, publishes the release and marks it latest. **The image's `latest` tag moves on publication:** a separate job runs on the release's `published` event for `vX.Y.Z` tags, holds `packages: write` only, checks out nothing, runs no repository code, shares `release`'s concurrency group, and applies IP-4 step 4's rule unchanged (only to a higher version; the version tag's digest copied as is). Releases are published in version order; no back-port releases (P-4) | A draft is invisible to anonymous downloads and to "latest release", so no scheduled run meets a release waiting for its signature. `latest` then names only images of published releases; a withdrawn draft leaves its version tag in the registry but never `latest`. Signing locally with a registry token was rejected: no personal token anywhere (IP-4) |
| AU-6 | **Which tag (scheduled run).** Running version = `version` from `/api/health` at the path's host-local address: Compose `WX_LISTEN`; Podman the address the Caddy container publishes. Unreachable or not `vX.Y.Z` (self-built `unknown`, a stopped stack): `none`, no request. Candidate = the tag named by the release host's "latest release" redirect (drafts and pre-releases are never latest; no API call, no JSON). Not `vX.Y.Z`, or not greater than running: `none`. Comparison numeric per component, major, minor, patch; components with more digits than the shell compares safely are refused as malformed. Installed only if the signed manifest names the same tag (AU-4) | OQ-214: the latest, whatever changed. GitHub only points; the signed text decides. Never starts a stack the hoster stopped |
| AU-7 | **Verification order: nothing unpacked or run before it ends.** (1) Manifest and signature into a fresh directory only the updater's user can write. (2) `minisign -V` with the pinned key given as a value (`-P`). (3) Names checked (AU-4). (4) Only then the deploy archive is fetched and its SHA-256 compared with the verified manifest. (5) Every member a regular file or directory with a relative name without `..`. (6) Unpacked into an empty directory without owners from the archive; that copy's `deploy.sh` runs. Nothing is fetched again or read from outside that directory after step 2, except the images, which `deploy.sh` pulls by the names in the verified files. Every download is HTTPS only (redirects too), size-capped, time-limited, without credentials | AC 38 to 40. Closes TOCTOU, mix-and-match and archive tricks |
| AU-8 | **Outcomes.** Refused (signature missing on a published release, invalid, by another key; names; hash; member check): alert and stopped state, nothing unpacked. Failed (`deploy.sh` exits non-zero: 1, 3, 4 or anything else; a Caddy patch refused by the guard is exit 1): alert and stopped state. Applied: exit 0. **Not a failure, no state change, no alert:** switch off, stopped, lock busy, health unreachable, not newer, network error, timeout, any HTTP error other than a missing `.minisig` next to a present manifest. **Manual runs (P-3):** exit 0 clears the stopped state; a failure sets it and, when the switch is on, prints one terminal line that automatic updates are now stopped and sends the alert (AU-11) | AC 38, 41, 42, 47; P-3 as decided 15 Nov 2026 |
| AU-9 | **Stopped state** = file `{deploy dir}/update.stopped`; present = stopped. One `key=value` line: UTC time, tag, `refused` or `failed`, exit status, reason class (AU-14). Written by temp file and rename. While present, a scheduled run makes no request and sends nothing; only its log line says `stopped`. Cleared by AU-8 (deleting it by hand has the same effect; the runbook names the manual deploy) | One alert per failure (INF-8); readable with `cat` |
| AU-10 | **Lock:** one exclusive `flock` (util-linux) on `{deploy dir}/deploy.lock`, taken by `update.sh` before its first request and held until the state is written. Not waiting: a scheduled run logs `busy` and stops; a manual run says another deploy is running and exits non-zero. The kernel drops it when the process dies | AC 45. Every deploy enters through `update.sh` (AU-2), so one lock covers all |
| AU-11 | **Alert from the host, not from `app`.** `update.sh` reads the two Pushover settings from `.env`; both set: one `POST` to the Pushover message API, HTTPS, 10 s, no retry; secrets passed to `curl` on stdin, never on a command line or in a log. Fixed text: title `Workout Explorer`, the tag and `refused (<reason>)` or `failed (exit <n>)`, and that automatic updates are stopped until a manual deploy; no link, no HTML. Not set: the log line is the alert. `app` gets no route out for this | AC 41, 44. The updater's user already reads `.env` on both paths |
| AU-12 | **Switch and About page (OQ-216).** `WORKOUT_EXPLORER_AUTO_UPDATE` in `.env`: unset or empty = off, `on` = on, anything else = `serve` exits 2 and `update.sh` refuses to run (config error). Read by `serve` (PT-9a) and by `update.sh` for scheduled runs; on Podman the app unit's `EnvironmentFile` passes it as every `WORKOUT_EXPLORER_*` key. **Pinned key:** `WX_UPDATE_PUBLIC_KEY` in `.env`, the base64 line of the minisign public key; required by every run; missing or malformed = config error before any request. `.env` is read as data key by key, never sourced; no deploy step writes it | One switch for behaviour and disclosure. The key lives where no release writes (OQ-217: re-pin by hand) |
| AU-13 | **Schedule and rights, per path.** Daily at the hoster's hour (set in a drop-in) plus a random delay within that hour, no catch-up after downtime. The timer units are installed once by the hoster and never changed by a release (a release that needs a unit change says so in its notes). No cron variant (P-5). **Compose:** a oneshot system service with `User=` the deploy user (deploy-directory owner, docker group), `NoNewPrivileges`, file-system writes confined to the deploy directory (plus a private `/tmp`), installed by root into `/etc/systemd/system`; root runs no code of ours. **Rootless Podman:** a oneshot user service and timer of the service user (which has linger), installed by the hoster as that user; no root step at all. No `NoNewPrivileges` and no file-system confinement there: rootless Podman needs the setuid `newuidmap`, and the service user is unprivileged and owns everything it can write. The deploy files belong to the service user (ADR-054). Data directory written only by the containers on both paths. Engineer confirms `docker compose` under the Compose confinement and lists any extra writable path | OQ-213; AC 43. Least privilege per path: Compose's deploy user is root-equivalent (accepted), Podman's is not and stays so |
| AU-14 | **Log line:** one per run, last, on stdout (the unit's journal; the terminal for manual runs): `update: running=<v or -> latest=<v or -> action=<none\|applied\|refused\|failed> reason=<class> exit=<n>`. Fixed reason classes (switch off, stopped, busy, health, current, network, config, signature, manifest, checksum, archive, deploy); never a tool's error text, a secret, a URL with a query, workout or visitor data. On a run that applies, `deploy.sh`'s own lines come before it | AC "Logging"; I-5, I-7 |
| AU-15 | **Self-update.** `deploy.sh` installs the new `update.sh` (and on Podman the new `workout-explorer-ctl`) by temp name and rename, so the running shell keeps its old copy; the new updater acts from the next run. The checking code of a run is always the installed one. `make ci` checks that every script in the deploy archive parses (`sh -n`), `update.sh` included | The updater is covered by the signature (AC 40) and never verifies itself |
| AU-16 | **`deploy.sh` on both paths** (F-59 IP-10 kept, entry changed). Runs from the unpacked verified archive, installs into the deploy directory. Nothing on the host changes until both images are pulled and the pulled Caddy passes IP-7's guard against the new Caddyfile; a refused patch gives the tag back to the previous image (exit 1). **Compose:** IP-10's steps. **Podman:** IP-11's steps through the archive's `workout-explorer-ctl` (install units, Caddyfile and itself with the guard, daemon-reload, restart both: brief page outage, accepted). Then on both: health wait for the tag, `regenerate` (clean-up included). Exit codes 0, 1, 3, 4 unchanged. **Path:** Compose when the deploy directory holds `compose.yaml`; Podman when the service user's Quadlet directory holds our app unit; both or neither: config error before any change. `update.sh` itself never pulls an image | F-59 items 2, 3, 8: one guard, one home per path, no digest check in the updater |
| AU-17 | **Host prerequisites.** Both paths: `curl`, `tar`, coreutils (`sha256sum`), util-linux (`flock`), `minisign`; pulls from ghcr.io and Docker Hub without login. Compose: Docker and Compose as DOCKER.md. Podman: as PODMAN.md, linger on. No `git`, `gh` or `sha512sum` on the server. **Out of scope:** self-built clones (OQ-215); bare metal (F-60: its units and apt pin already sit in the signed archive; Caddy's patches come through apt, never through our updater) | Least privilege holds on both container paths |

## Attack paths considered

| Path | Result |
| --- | --- |
| GitHub account, repository or CI compromised; assets swapped | No valid signature without the offline key: refused, alert, stopped. Checksums alone never count (AC 39) |
| Registry tag `vX.Y.Z` or `latest` repointed | Not used: the signed `compose.yaml` and Podman unit name our image by digest |
| A Caddy patch on Docker Hub that is malicious | Not caught: the signature covers the tag name only (accepted, user decision 15 Nov 2026). A patch that needs a capability or rejects our Caddyfile is caught by IP-7's guard |
| Old valid manifest and signature replayed under a new release | Names carry the old tag: refused (AC 38) |
| Old signed release made "latest" (rollback, downgrade) | Not greater than running: `none`. Only a manual run installs an older tag |
| New manifest with an old archive (mix and match) | Hash differs from the verified manifest: refused |
| Swap between verify and unpack (TOCTOU) | Files in a directory only the updater's user writes; nothing re-fetched; the hashed bytes are the unpacked bytes |
| Archive with absolute paths, `..`, symlinks, hard links, devices | Member check before unpack, empty target, no owners: refused (defence in depth) |
| `deploy/minisign.pub` replaced on GitHub | Key pinned at install after comparing GitHub with the DNS TXT record; never read from a release |
| Signature deleted or updates withheld (freeze) | Not preventable; a deleted signature alerts and stops. Accepted |
| CI builds malicious bytes from the tagged commit | Not caught by signing (the operator signs CI's output); `COMMIT` catches only a wrong commit. Residual |
| Offline key stolen | Forged releases install until hosters re-pin (OQ-217). Residual |
| Updater as a privilege path | Compose: the deploy user (docker group, root-equivalent, accepted); no root, no sudo; cannot change its units. Podman: the unprivileged service user; root never runs a file that user can write (ADR-054). On both, the pinned key can be changed only by something already running as that user |
| Secrets via process list or logs; `.env` injection | Stdin only; fixed log classes; `.env` never sourced |

## Verification notes (critical lane, QA at effort high)

Beyond the AC, on Compose **and** rootless Podman: a tamper matrix on a scratch release host or local file server (each AU-7 step failing once, each AU-8 non-failure case once); the Compose units installed as on a real host, writes outside the deploy directory failing; on Podman no process of the update path runs as root (`ps` during a run) and no root-owned file is written; a Caddy image that fails the guard leaves the running stack and the local tag as before; `ps` with Pushover set shows no secret; a manual and a scheduled run started together; the `latest` job moves the tag only on publication and only upwards; the private key and signing absent from CI logs and history.
