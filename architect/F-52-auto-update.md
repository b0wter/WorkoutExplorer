# F-52 Optional automatic updates for hosters: architecture

- **Version:** 0.1
- **Status:** accepted (15 Nov 2026). Critical lane. OQ-210 to OQ-217 decided by the user on 14 Nov 2026 and built in here; open product points at the end
- **Feature:** [`features/F-52-auto-update.md`](../features/F-52-auto-update.md); "AC n" is the n-th acceptance criterion there
- **Requirements:** INF-8, INF-4, INF-1, NFR Privacy, NFR Security, UP-7, AC-4; TD Hosting and operations (Deploys), Configuration, Security and privacy
- **Builds on:** [F-31](F-31-server-deploy-and-monitoring.md) DP-3, DP-6, DP-10, DP-18; [F-30](F-30-regenerate-command.md) RG-10, RG-11; [F-29](F-29-about-page-and-attributions.md) AB-3; ADR-019, ADR-034, ADR-035, ADR-039. **New:** [ADR-050](ADR-050-deploys-run-on-the-server-from-a-signed-release.md), [ADR-051](ADR-051-updater-as-host-script-verified-by-minisign.md)
- **Owner:** backend. Files: `deploy/update.sh` (new), `deploy/deploy.sh` (server-only), `deploy/sign-release.sh` (new, operator machine), two systemd units in `deploy/`, `deploy/minisign.pub`, `example.env`, `RUNBOOK.md` (6a, 13, new updater section), `ci.yml`, `make ci` (scripts parse), Go: one setting and the About block (`about.html` template line, frontend-owned file, backend may edit it in this feature)

## Shape

```
systemd timer (root-owned unit, User=deploy)        operator, by hand:  ssh deploy@vps .../update.sh vX.Y.Z
        │ nightly                                                                 │
        └──────────────▶ {deploy dir}/update.sh  ◀────────────────────────────────┘
                          gate → pick tag → verify → unpack → run the release's deploy.sh → state, alert, log line
```

One path for every deploy on the release layout (ADR-050). The installed, already verified `update.sh` does all checking; the downloaded release only supplies `deploy.sh` and the files it installs, and runs only after verification.

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| AU-1 | **Updater = POSIX shell script `update.sh`** at `{deploy dir}/update.sh` (default `/srv/workout-explorer`), installed and replaced by `deploy.sh` like `clean-assets.sh`; verification by the host's distribution package `minisign` (Debian bookworm 0.11, trixie 0.12) against the pinned key (ADR-051). Not part of the Go binary, which runs only inside containers | Matches `deploy.sh`; no own crypto code; trust root is the hoster's package archive, not GitHub |
| AU-2 | **Two entry modes, one code path.** `update.sh` with no argument = scheduled run (AU-6 picks the tag; acts only when the switch is on). `update.sh vX.Y.Z` = **manual deploy** of that tag, whatever the switch, the stopped state or the running version (same or older allowed, ADR-035 item 5). Both download, verify, lock and run the same `deploy.sh`. The operator deploys over SSH with the manual mode; `deploy.sh` has no remote mode, needs no checkout, `git` or `gh`, and is not an entry point (ADR-050) | Manual and automatic deploys cannot drift apart; the lock and the stopped state need one home on the server |
| AU-3 | **Release assets.** `workout-explorer-<tag>-linux-amd64.tar.gz` (unchanged), `workout-explorer-<tag>-deploy.tar.gz` (new), `SHA256SUMS`, `SHA256SUMS.minisig`. The deploy archive is built from an **explicit allow-list**: the files the release layout installs or runs (`deploy.sh`, `update.sh`, `clean-assets.sh`, `fetch-caddy.sh`, `caddy.env`, `compose.yaml`, `compose.notify.yaml`, `Caddyfile`, the two systemd units) and the templates the runbook copies once (`example.env`, the operator and Impressum examples). Never the whole `deploy/` folder (a local `deploy/.env` may hold secrets; `make ci` creates one), never `minisign.pub`, never the self-build files | OQ-211, OQ-215. Caddy stays covered: its pinned checksums live in the signed `caddy.env` |
| AU-4 | **Manifest = plain `sha256sum` output**, one line per archive, nothing else. **The tag is in the signed text through the file names:** every name starts `workout-explorer-<tag>-`, and both required archives are listed. No extra line, so `sha256sum -c` stays usable by hand | OQ-211 without a new format; a replayed manifest names its own, older tag |
| AU-5 | **Signing (operator, OQ-212).** CI's `release` job creates the release as a **draft** (F-31 DP-18 changed). On the operator's machine `sign-release.sh` downloads the draft's assets, checks the hashes, checks that the binary archive's `COMMIT` is the local tag's commit (the check `deploy.sh` made from the checkout) and that the names carry the tag, signs `SHA256SUMS` with `minisign -S` (default prehashed Ed25519, secret key password-protected, stored outside the repository directory), uploads the signature, publishes the release and marks it latest. Releases are published in version order; there are no back-port releases | A draft is invisible to anonymous downloads and to "latest", so no nightly run ever meets a release still waiting for its signature, and "no signature" on a published release means an error or an attack |
| AU-6 | **Which tag (scheduled run).** Running version = `version` from `/api/health` through `WX_LISTEN`, as `deploy.sh` reads it. Health unreachable or not `vX.Y.Z` (self-built `unknown`, a stopped `app`): `none`, no request. Candidate = the tag named by the release host's "latest release" redirect (drafts and pre-releases are never latest; no API call, no JSON). Not `vX.Y.Z`, or not greater than running: `none`. Comparison: numerically per component, major, then minor, then patch; components with more digits than the shell can compare safely are refused as malformed. The candidate is installed only if the signed manifest names the same tag (AU-4) | OQ-214: the latest, whatever changed. GitHub only points; the signed text decides. Never starts an `app` the hoster stopped |
| AU-7 | **Verification order: nothing unpacked or run before it ends.** (1) Manifest and signature into a fresh directory only the updater's user can write. (2) `minisign -V` with the pinned key given as a value (`-P`), never a key file from anywhere else. (3) Names checked (AU-4). (4) Only then the archives are fetched and their SHA-256 compared with the verified manifest. (5) Every archive member must be a regular file or directory with a relative name without `..`. (6) Unpacked into an empty directory without owners from the archive; that copy's `deploy.sh` runs. Nothing is fetched again or read from outside that directory after step 2. Every download is HTTPS only (redirects too), has a size cap and a time limit, and sends no credential | AC 38 to 40. Closes TOCTOU, mix-and-match and archive tricks (Attack paths) |
| AU-8 | **Outcomes.** Refused (signature missing on a published release, invalid, by another key; names; hash; member check): alert and stopped state, nothing unpacked. Failed (`deploy.sh` exits non-zero: 1, 3, 4 or anything else): alert and stopped state. Applied: exit 0. **Not a failure, no state change, no alert:** switch off, stopped, lock busy, health unreachable, not newer, network error, timeout, any HTTP error other than a missing `.minisig` next to a present manifest. A manual run never alerts (the hoster is watching); a failed manual run sets the stopped state, a manual run that ends with exit 0 clears it | AC 38, 41, 42, 47. A failed manual deploy leaves the box in the same doubt as a failed automatic one |
| AU-9 | **Stopped state** = file `{deploy dir}/update.stopped`; present = stopped. One `key=value` line: UTC time, tag, `refused` or `failed`, exit status, reason class (AU-14). Written by temp file and rename. While present, a scheduled run makes no request and sends nothing; only its log line says `stopped`. Cleared by AU-8 (deleting it by hand has the same effect; the runbook names the manual deploy) | One alert per failure (INF-8); readable with `cat` |
| AU-10 | **Lock:** one exclusive `flock` (util-linux) on `{deploy dir}/deploy.lock`, taken by `update.sh` before its first request and held until the state is written. Not waiting: a scheduled run logs `busy` and stops; a manual run says another deploy is running and exits non-zero. The kernel drops it when the process dies: no stale lock | AC 45. Every deploy enters through `update.sh` (AU-2), so one lock covers all |
| AU-11 | **Alert from the host, not from `app`.** `update.sh` reads the two Pushover settings from `.env`; both set: one `POST` to the Pushover message API, HTTPS, 10 s, no retry; secrets passed to `curl` on stdin, never on a command line or in a log. Fixed text: title `Workout Explorer`, message naming the tag and `refused (<reason>)` or `failed (exit <n>)` and that automatic updates are stopped until a manual deploy; no link, no HTML. Not set: the log line is the alert. `app` gets no route out for this; `compose.notify.yaml` is neither needed nor touched | AC 41, 44. The deploy user already reads `.env` for `deploy.sh`; no new secret, no new process holds one |
| AU-12 | **Switch and About page (OQ-216).** One setting, `WORKOUT_EXPLORER_AUTO_UPDATE` in `.env`: unset or empty = off, `on` = on, anything else = `serve` exits 2 and `update.sh` refuses to run (config error). Read by `serve`, which renders the OQ-216 sentence as a conditional block like Pushover's (F-29 AB-3, PT-9a), and by `update.sh` for scheduled runs. **Pinned key:** `WX_UPDATE_PUBLIC_KEY` in `.env`, the base64 line of the minisign public key; required by every run, scheduled or manual; missing or malformed = config error before any request. `.env` is read as data key by key, never sourced; no deploy step writes it | One switch for behaviour and disclosure. The key lives where no release writes (OQ-210, OQ-217: re-pin by hand) |
| AU-13 | **Schedule and rights.** Two units shipped in the deploy archive and installed by the hoster as root into `/etc/systemd/system` (no user units, no linger): a oneshot service with `User=` the deploy user (deploy-directory owner, docker group), `NoNewPrivileges`, file-system writes confined to the deploy directory (plus a private `/tmp`), and a timer, daily at the hoster's hour (set in a drop-in) plus a random delay within that hour, no catch-up after downtime. A release never changes the units (the updater cannot write them); a release that needs a unit change says so in its runbook text. The data directory is written only by the containers through Docker, as on a manual deploy. Engineer confirms `docker compose` works under the confinement and lists any extra writable path. No cron variant | OQ-213; AC 43. Root installs once, never runs code of ours |
| AU-14 | **Log line:** one per run, last, on stdout (the unit's journal; the terminal for manual runs): `update: running=<v or -> latest=<v or -> action=<none\|applied\|refused\|failed> reason=<class> exit=<n>`. Reason classes are a fixed set (switch off, stopped, busy, health, current, network, config, signature, manifest, checksum, archive, deploy); never a tool's error text, a secret, a URL with a query, workout or visitor data. On a run that applies, `deploy.sh`'s own lines (as on a manual deploy) come before it | AC "Logging" scope; I-5, I-7 |
| AU-15 | **Self-update.** `deploy.sh` installs the new `update.sh` by temp name and rename like every file, so the running shell keeps its old copy; the new updater acts from the next run. The checking code of a run is always the installed one. `make ci` checks that every script in the deploy archive parses (`sh -n`), so a release cannot ship an updater that silently stops the nightly path | The updater is covered by the signature (AC 40) and never verifies itself |
| AU-16 | **Host prerequisites** (release layout): Docker with Compose, `curl`, `tar`, coreutils (`sha256sum`, `sha512sum`), util-linux (`flock`), `minisign`. No `git` or `gh` on the server. Out of scope: self-built clones (OQ-215) and rootless Podman (Quadlet) hosts, whose program files are root-owned and which `deploy.sh` does not drive | Least privilege holds only where `deploy.sh` already works |

## Attack paths considered

| Path | Result |
| --- | --- |
| GitHub account, repository or CI compromised; assets swapped | No valid signature without the offline key: refused, alert, stopped. Checksums alone never count (AC 39) |
| Old valid manifest and signature replayed under a new release | Names carry the old tag, not the release's: refused (AC 38) |
| Old signed release made "latest" (rollback, downgrade) | Not greater than running: `none`. Only a manual run installs an older tag |
| New manifest with an old archive (mix and match) | Hash differs from the verified manifest: refused |
| Swap between verify and unpack (TOCTOU) | Files live in a directory only the updater's user writes; nothing re-fetched; the hashed bytes are the unpacked bytes |
| Archive with absolute paths, `..`, symlinks, hard links, devices | Member check before unpack, empty target, no owners: refused (defence in depth; a signed archive is trusted) |
| `deploy/minisign.pub` replaced on GitHub | Key pinned at install after comparing GitHub with the DNS TXT record on the operator's domain; never read from a release |
| Signature deleted or updates withheld (freeze) | Not preventable; a deleted signature alerts and stops, so the hoster notices. Accepted |
| CI builds malicious bytes from the tagged commit | Not caught by signing: the operator signs CI's output (OQ-212); `COMMIT` catches only a wrong commit. Residual; reproducible builds would close it |
| Offline key stolen | Forged releases install until hosters re-pin (OQ-217). Residual, the operator's duty |
| Updater as a privilege path | Runs as the deploy user (docker group, root-equivalent, accepted); no root, no sudo; cannot change its units. The pinned key in `.env` can be changed only by something already running as that user |
| Secrets via process list or logs; `.env` injection | Stdin only; fixed log classes; `.env` never sourced |

## Verification notes (critical lane, QA at effort high)

Beyond the AC: a tamper matrix on a scratch release host or a local file server (each AU-7 step failing once, each AU-8 non-failure case once); the units installed as on a real host, checking that writes outside the deploy directory fail; `ps` during a run with Pushover set shows no secret; a manual and a scheduled run started together; the private key and `SHA256SUMS.minisig` creation absent from CI logs and the repository history.

## Open questions

| # | Point | Suggestion |

| P-2 | Releases stay drafts until the operator has signed them (AU-5) | Accept |
| P-3 | A failed **manual** deploy also sets the stopped state (AU-8); INF-8 names only automatic failures | Accept |
| P-4 | No back-port releases: a lower version published after a higher one is never offered (AU-5, AU-6) | Accept |
| P-5 | systemd timer only, no cron variant (OQ-213 said "or cron") | Accept: cron has no write confinement |
| P-6 | Rootless Podman (Quadlet) hosts are not covered (AU-16) | Accept; their updates need root today |
